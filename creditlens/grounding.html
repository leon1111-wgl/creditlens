XBRL 对照

从项目从未用过的上市公司 10-K 中渲染财务报表页，只把页面图像交给 OCR 取数，再与发行人自己在 Inline XBRL 中给每个数字打的标签逐项对照：数值、括号符号、单位量级和年份列。绿框为一致，琥珀虚线框为未作答，红框为冲突；点选任一框查看 XBRL 概念与上下文。

答案键 = 发行人自己的 XBRL 标签干净渲染页，不是扫描件OCR 只看图像，HTML 文字不参与取数正在载入保存的运行结果…

对照的做法：抽取字段附上定位框与置信度，低置信度交给人工，如 AWS Bedrock Data Automation 的视觉定位（2024-12 预览）。本页规模小、不用密钥，取数是 CPU 上的 OCR 加确定性规则，不是大模型。

    方法、评分规则与边界

    发行人怎样选

    规则在任何保留集运行之前提交（configs/xbrl-grounding.json，heldout-2026-11-b）：总体取自 SEC 2026q1 Financial Statement Data Set，即 2025 年 12 月 31 日财年末、大型加速申报人（1-LAF）提交的 10-K 原件；排除项目已用的微软、苹果、AMD、NVIDIA，以及 FinQA 开发集里能对应到 CIK 的股票代码；按加盐 SHA-256 排序，依次取前 6 家能找到利润表、资产负债表和现金流量表的发行人。页面上不手工挑选公司或页码。

    页面与答案键

    • SEC 拒绝 GitHub Actions 运行器的请求，因此不向 SEC 发请求：10-K 的 iXBRL HTML 取自互联网档案馆已有的 SEC 原地址抓取，按抓取摘要核对字节，并核对文件自报的 CIK 与文件类型。
    • 在 GitHub Actions 上用 Chromium 渲染（禁止其他网络请求），按文件自身的分页样式切页；每家最多 4 页报表页。
    • 每个 ix:nonFraction 记录位置框、印刷文字、概念、上下文（期间与维度）、单位、decimals、scale 与 sign。ix:hidden 里的事实只有在正文以 -sec-ix-hidden 显示时才进入对照；文本块内、嵌套、重复出现的标签分别标注。
    • 符号以印刷括号为准，XBRL 的 sign 属性并列显示：有的概念印成扣减项“(500)”，标签值却是正数，这类不同只说明列报方式，不算读错。

    取数与评分

    • OCR 只接收整页 PNG：RapidOCR 3.10、PP-OCRv6 small、CPU，与项目文档实验同一套固定配置。单位表头与年份列也只从 OCR 文字和位置读出。
    • 识别完成后才按标签框取片段：覆盖框 35% 以上或中心落在框内；置信度不低于 0.90；片段越出框 8 pt 以上、一格多段、旁边有分离的符号碎片、文字不是完整金额时都不作答。行名或其上方最近的纯文字标题提到股数、每股或面值时不套用单位表头的量级；本页首轮用的是 score-1：这条标题规则也会波及“普通股，面值 … 股”说明下方的权益金额行。v0.35.0 的 score-2 把标题的覆盖范围限定为紧接的一行和缩进在它下面的行，在另外 6 家按新规则选出的发行人上，与 score-1 用同一批 OCR 配对测量：一致 1,406 对 1,388，冲突 16 对 20，未作答 465 对 479（运行 42773541603，见仓库 docs/45-xbrl-grounding.md）。本页的数字仍是首轮 score-1 的结果。
    • 一致 = 数位、括号符号、量级、年份列全部相符；冲突 = 读出了完整读数但至少一项不符；其余为未作答。

    边界

    • 干净渲染页比扫描件容易；Chromium 的字体替换也会让页面与发行人 PDF 不同。
    • 评分规则沿用项目已有规则，首轮之前没有按这些公司调过；首轮之后的任何修改都不再是盲测，会另行标注。
    • 没有人工复核；XBRL 标签本身也可能有误，这里把它当作发行人自己的答案。
