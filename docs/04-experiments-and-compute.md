# 评测 后训练与 A100 预算

## 当前可复现结果

2026 年 10 月 25 日在本地 Python 3.12.14 上运行官方 FinQA dev 883 题。固定数据 SHA-256：a847fb7e0d61a3125a1e2909852df6b89f1ee64d2c5ff1bf689e332214deee51。

| 指标 | 结果 | 分母与含义 |
|---|---:|---|
| Macro evidence Recall@5 | 82.43% | 每题取回 gold 证据比例，再对 883 题平均 |
| 全部 gold 证据取回率 @5 | 70.78% | 625 / 883 题，所有标注支持块都在前 5 条中 |
| 不存在的 gold 定位 | 0 | 全部标注 ID 均能在原始材料块中定位 |

它是**给定报告页内**的 BM25 检索实验，不是跨企业文档库检索、完整信用分析、LLM 回答准确率或生产业务收益。标准答案和预置检索结果没有进入索引。逐题结果见 artifacts/retrieval-baseline.json。

## 完整实验矩阵

| 组别 | 系统 | 需要回答的问题 |
|---|---|---|
| B0 | BM25 + 原始材料，无生成 | 有多少证据能被低成本检索找到 |
| B1 | BM25 RAG + 固定基座 | 最简单完整回答链的表现 |
| B2 | 混合召回 + reranker + 同一基座 | 改善来自检索，还是额外上下文 |
| B3 | B2 + 确定性工具 | 数值工具贡献有多大 |
| B4 | B3 + 证据／时间／单位验证 | 可信完成率和覆盖率如何变化 |
| B5 | B4 + SFT 适配器 | 结构化输出与工具行为是否改善 |
| B6 | B5 + DPO | 错误自信、乱引证和过度拒答如何变化 |
| B7 | B5 + 小模型 RL | 相同数据与推理预算下是否优于 B6 |

主要比较固定同一个基座、文档版本、上下文长度、工具数上限和搜索预算。额外用一个当前强模型作为能力参考，不把模型变化和系统变化混为一个改进。

## 指标定义

可信完成率 = 答案正确且全部关键结论具有充分证据的任务数 / 所有可回答任务数。拒答在这个指标中不算完成。同时报告证据不足任务上的恰当拒答率，防止通过全部拒答获得漂亮的精度。

检索用 Recall@k、MRR 或 nDCG；存在多条必要证据时额外报告全部证据取回率。答案用正确率、数值执行正确率、单位和期间一致率；容差由任务类型预先定义，零附近不盲用 MAPE。实体与因子抽取报告 span/字段 F1、缺失和未知状态的误判。

引用分别衡量：引用是否存在、是否支持该条结论、是否覆盖全部关键结论。存在 URL 不代表引用充分。LLM judge 只能辅助，数值与时间由程序核验，关键结论由人工抽样校准。评审模型与生成模型尽量不同，隐藏系统身份、随机排序，保留分歧。

报告覆盖率与错误率曲线、每任务 token、工具调用数、p50/p95 时延、峰值显存及总成本。按公司／文档聚类 bootstrap 给置信区间；同一题重复执行时报告成功的稳定性。不同语种、行业、扫描质量和问题类型分开统计。

## 拟定验收门槛

以下是产品目标，未达成前不能写进简历当成成绩。用首轮人工标注校准难度后可以调整，但必须在最终 test 运行前冻结。

| 能力 | 初始门槛 |
|---|---|
| 结构化输出 | 合法 schema 比例 ≥99%，并单独计算内容正确率 |
| 有限域财务事实抽取 | 关键字段 F1 ≥0.90；单位／期间错误单列 |
| 正确且证据充分 | 比 B1 至少提高 10 个百分点，报告置信区间 |
| 引用支持精度 | ≥95%，同时报告回答覆盖率 |
| 时间或权限违规 | 专门对抗集上观察到 0 次；不能外推为永不发生 |
| 数值工具 | 确定性规则测试全部通过，端到端输入抽取另评 |
| 人工任务总耗时 | 小样本配对任务减少 ≥30%，包含核查与返工时间 |
| 性能 | 在标注硬件、上下文与并发条件下报告；未压测不承诺 SLA |

真实 PD 扩展还需要违约定义、观察窗口、表现窗口、删失处理、拒绝样本偏差和 out-of-time 划分，再使用 AUC、KS、PR-AUC、Brier、ECE、PSI。没有真实标签时只做风险线索抽取，不宣称降低坏账率。

## 训练数据与顺序

先准备高质量、可审计的 2,000–5,000 条 SFT 样本试验，再根据学习曲线决定是否扩大。它们是计划规模，尚未生成。每条样本包含任务、授权证据、短步骤工具动作、结构化结果和拒答依据。只使用明确允许训练的来源和教师模型输出，不能默认任何 API 输出均允许蒸馏。

训练重点是稳定工具参数、正确引用、单位与期间约束、资料不足处理，避免背诵企业最新财务数值。保留 20%–30% 的困难负例或缺证据样本作为初始采样假设，最终按真实分布校验，不能只靠增加负例诱导拒答。

DPO 从 1,000–3,000 对经审核的同题同证据偏好对起步。chosen 必须真正优于 rejected，不把更长、语气更自信或引用更多视为更好。先看 SFT 是否已解决问题，没有额外增益就不部署 DPO。

RL 最后考虑。把检索、取单元格、计算和提交作为有限动作，限制 6–8 次工具调用和输出长度。环境使用冻结语料，答案与证据由确定性检查器和人工标注评分。Search-R1 的检索文本 masking、Search-R1++ 对拒答崩塌的分析提供参考；不能把论文中的最优设置直接当成金融场景最优。[Search-R1](https://arxiv.org/abs/2503.09516)、[Search-R1++](https://arxiv.org/abs/2602.19526)

候选奖励：错误权限或未来证据直接判失败；其余按答案正确、证据支持、口径正确、合理完成给分，再加小幅工具成本惩罚。权重先在人工排序数据上校准，报告奖励各分量与被利用的例子。拒答不能与错误回答完全同罚或永远获奖。比较 outcome-only、加证据约束、加动作成本三个奖励版本；若奖励提高但盲测质量下降，停止训练。

## 单张 A100 40GB 的使用方案

起点选 [Qwen3-4B-Instruct-2507](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507) 作为已核实可获取的中文友好基线。它不是“当前最强”声明。完整模型选择应在相同任务上比较当前可用的小模型与一个强模型，综合正确率、工具行为、许可证和成本再定。

| 工作 | 单卡方案 | 判断 |
|---|---|---|
| 语料处理与 BM25 | CPU，本地完成 | 当前无需租 GPU |
| embedding／reranker | 轻量模型批处理，分时运行 | 可与生成模型错峰 |
| 4B SFT | QLoRA 或 LoRA，2k→4k token，microbatch 1，梯度检查点 | 高优先级试跑候选 |
| 7–8B SFT | 4-bit QLoRA，短上下文，LoRA rank 16/32 对照 | 常见可行方向，仍以实测峰值为准 |
| 14B SFT | 量化、小 batch、短上下文 | 暂不作为起点，显存与速度余量较小 |
| 4B DPO | PEFT，控制 chosen/rejected 长度，必要时预计算 reference log-prob | 按 trainer 版本验证兼容性 |
| 1.5–4B RL | 少量 rollout、短输出，生成与训练分时或卸载 | 探索性项目，不保证单卡吞吐可接受 |
| 7B 全参数 Adam 训练 | 权重、梯度、优化器与激活会远超仅权重大小 | 不安排 |
| 大规模 MoE／长上下文 Agent RL | 需要更多显存、吞吐和分布式验证 | 不属于这张卡的交付承诺 |

只算权重：4B BF16 约 8 GB，8B BF16 约 16 GB，4-bit 原始权重约 2 GB 和 4 GB；实际还有量化元数据、激活、适配器、优化器、KV cache 和框架开销。约 16 bytes/参数的常见混合精度全参 Adam 粗估下，7B 在激活前已约 112 GB。不要把“能装下推理权重”等同于“能训练”。

QLoRA 依据：[论文](https://arxiv.org/abs/2305.14314)。长度、padding、packing、checkpointing 与训练器兼容性依据：[TRL 显存指南](https://huggingface.co/docs/trl/reducing_memory_usage)。推理和 RL rollout 可能同时需要模型副本，不能默认训练、重排和高并发推理共用 40GB 都能运行。

## 租卡启动条件与预算

现在不租。满足以下条件后再开机：下载与环境脚本可复现、评测集冻结、至少 200 条样本完成人工核查、CPU 数据处理测试通过、明确要比较的 baseline 与训练组。

建议服务器规格是单张完整 A100 40GB、Linux、约 64–128 GB RAM、足够的 CPU 和 200 GB 以上可用磁盘；这些是计划配置，不是特定供应商报价。先确认不是未说明的 MIG 切片，并记录驱动和 CUDA 兼容版本。

分批授权计算预算：先 2 GPU 小时做安装与 100–200 step 显存／吞吐校准；确认没有 OOM 和数据错误后，第一批 SFT 的资源上限设为 8–24 GPU 小时。DPO 和 RL 分别作为后续独立批次决定，不能开着服务器边研究边等待。

训练时长估计公式：训练 token 总量 ÷ 实测有效 token/s ÷ 3600，再增加评测、保存和启动开销。例如 5,000 条 × 平均 2,000 token × 2 epoch = 2,000 万 token；若试跑实测 200 token/s，纯训练约 27.8 小时。此处 200 token/s 是算式示例，不是 A100 性能承诺。超出当前批次预算时缩小样本或 epoch，再决定是否续租。

费用 = GPU 小时 × 实际供应商单价 + 存储 + 流量 + 可能的教师 API 费用。本轮没有租用服务器、创建付费实例或调用收费模型。
