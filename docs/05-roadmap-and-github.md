# 实施路线与 GitHub 展示

## 从首版走到有竞争力的项目

完整目标按 250–400 小时有效研发与标注投入估算，取决于数据授权、人工复核和实验速度。全职推进可按约 8–12 周组织；这不是根据用户学习基础给出的承诺。优先交付可检查的任务，不等所有技术都学完再开始。

| 阶段 | 交付物 | 进入下一阶段的条件 |
|---|---|---|
| 当前 v0.2 | 官方事实包、完整模拟复核流程、角色/租户约束、48 项测试、因子导出与模型接口 | 继续做真实模型和多模态证据验证 |
| 第 1–2 周 | 30 家企业材料清单、第一行业口径、解析对照、200 题自建评测、强模型与小模型基线 | 原始证据定位可用，无 gold 泄漏 |
| 第 3–4 周 | 混合检索、重排、结构化风险因子、有限工具工作流、中文完整底稿 | 同模型等预算实验优于普通 RAG，失败能定位 |
| 第 5–6 周 | 单卡 SFT、DPO 实验、适配器、模型卡、消融和样本外结果 | 盲测有增益且未损害拒答与通用任务 |
| 第 7–8 周 | 人工复核、任务恢复、身份与权限、监控、备份、性能测试 | 测试能证实隔离与恢复，真人完成任务 |
| 第 9–12 周 可选 | 小模型 RL、复杂关系任务、论文式技术报告、公开 benchmark 贡献 | 研究假设与数据足够，资源投入有明确收益 |

每阶段都保留一个可演示版本。若 SFT 不优于强提示基线，分析数据与错误类型，不为展示训练经历强行上线。若 RL 无增益，发布负结果和原因同样有研究价值。

## 下一批具体任务

1. 选非金融企业的第一个行业与 10 份公开报告，比较 Docling 与 MinerU，标注 50 个表格／附注定位。
2. 从已取得的原始材料建立 Document 和 Fact 契约，补齐真实公告时间与版本关系。
3. 引入一个中文 embedding 与 reranker，对相同 query 做 BM25、dense、hybrid 三组比较。
4. 接入模型接口，限制其只能提出结构化检索、抽取和数值动作；验证器执行工具并检查证据。
5. 建 50 条高质量人工任务再扩到 200 条；模型输出不能充当唯一标准答案。
6. 跑固定模型、固定工具预算的普通 RAG 与带工具流程；准备误差分析后才开启微调。
7. 完成一次“新公告进入→旧结论失效→形成待复核差异”的完整信用研究演示。

## 五个适合展示的场景

- **现金流与债务覆盖**：核对经营现金流、受限现金、短债及到期口径，逐项显示数值证据和公式。
- **利润与现金背离**：拆解应收、存货与非现金项目，不把背离直接判成造假。
- **担保和关联风险**：输出证据支持的关系与待核验链路，不臆造最终控制关系。
- **历史时点回放**：同一公司在两个截止日期得到不同证据集合；未来公告被拦截。
- **冲突和不足材料**：年报与后续更正矛盾时呈现版本，缺关键分母时拒绝计算并列出缺口。

当前已完成现金流和简化债务覆盖、时点与冲突阻断、逐项复核；担保关系、公告更新与完整附注分析仍未实现。

## 风险登记与停止条件

| 风险 | 早期信号 | 处理 |
|---|---|---|
| 公开材料不能支持真实信贷结论 | 没有违约标签或关键授信材料 | 范围保持为分析底稿与风险线索 |
| 解析器表格错位 | 金额与年份不一致、单位丢失 | 阻断下游结论，显示原页，人工修正 |
| 幻觉和不充分引用 | 数字无法重算、引文不支持结论 | 验证失败或转人工，进入回归集 |
| 基准污染 | 高分但新报告表现差 | 新报告盲测、反事实数值替换、公司隔离 |
| 奖励被利用 | reward 上升、覆盖或人评下降 | 停止 RL，审查奖励和训练样本 |
| 算力投入失控 | 显存溢出、低吞吐、无改善 | 先缩模型、长度和任务，按批次停机 |
| 工程范围失控 | 服务数量增加但任务仍不完整 | 回到单一信用研究任务，延后平台化 |
| 没有真实工作流需求 | 试用者仍更愿意手工做完整任务 | 追踪核查成本，调整需求而非只调模型 |

## 面试叙述原则

可以讲“基于公开 FinQA 开发集建立无标签泄漏的证据检索基线，使用源单元格引用完成确定性计算，设计并实现数据可追溯与时点过滤”。只能在完成后补充微调收益、真实用户节省时间、吞吐或上线情况。

不能说“已落地银行”“降低坏账率”“复现顶会论文”“单卡训练金融大模型达到行业最优”，除非对应实验、授权和业务证据确实存在。
