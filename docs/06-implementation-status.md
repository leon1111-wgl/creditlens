## 验证结果

v0.4 新增苹果 22 项事实、分区定位与四个原始单元格构成的覆盖率公式，两个 52 周年度产生 11 行可比数据。三张定位原页已检查。桌面浏览器完成独立模拟复核（5 事件／v5），497px 窄屏检查入口与台账，手动截止日切换后保留；HTTP 验证旧 v2 案件写入 409 且事件不变。详见 [第 4 轮报告](iterations/2026-10-25-04.md)、[实际底稿](../artifacts/apple-review-memo.md) 和 [HTTP 验收](../artifacts/multi-issuer-http.json)。开发参考未经第二位标注者复核，不是泛化准确率。

v0.3 真实 PDF 提取完成，20 项数值及财务口径与 HTML 包一致，三张原页的定位框已渲染检查；不是通用 PDF 准确率。浏览器验证了 PDF 来源选择、建案、证据台账和坐标展开（窄屏内容宽 482px、桌面视口 1280px）。HTTP 验证 0.3.0、20 个定位、事件链和导出底稿。详见 [第 3 轮报告](iterations/2026-10-25-03.md) 与 [新界面截图](images/pdf-evidence-workbench.png)。

86 项 unittest 通过，覆盖核心、API、严格 schema、时点、金融口径、权限、租户、幂等、并发、独立复核、篡改检查、受限模型传输及因子导出。

v0.2.1 新增的 15 个财务控制场景（1 个官方参考 + 14 个合成变体），修复前 9 个通过，修复后全部通过；已包含在 unittest 中。这是程序回归检查，不是金融模型准确率。详见 [第 2 轮报告](iterations/2026-10-25-02.md)。本机 HTTP 已验证版本 0.2.1、新规则建案，以及旧案可读、可导出、写入拒绝且事件不变。

官方披露演示脚本生成 5 个事件，状态 reviewed、版本 5，事件链与快照一致。身份为 simulated-analyst / simulated-reviewer，不是银行真实用户验收。FinQA 页内检索 Recall@5 为 82.43%，全部标注证据召回 625/883；不是回答准确率。

## 当前限制

- 仅微软、苹果两份固定数字 PDF 的六页具备原页 bbox；通用 PDF、图表/扫描件理解、跨页续表及更正关系尚未实现。两个来源格式一致不代表真实性鉴定。
- 当前模型接口只做模拟传输测试；没有真实 LLM 质量、训练增益、金融预测、负载测试或用户效率结果。
- 官方数据仍需核查是否适用于目标任务。事实包导入不自动证明材料真实性；现有债务/现金口径不完整。
- API-key 模式不等于 SSO 与企业身份治理；默认 demo 只能本地使用。
- SQLite 哈希链不能抵御拥有数据库写权者重算全链；尚无独立审计存储、删除传播及备份恢复验收。
- 1 MB 请求检查先读体，生产还需入口流式限制。未完成渗透、安全及合规审查。
- Docker 配置已提供，但本机无 Docker，未实跑。Python 包应从仓库根目录运行，独立 wheel 分发未验证。
- Starlette TestClient 对 httpx 给出弃用提示，当前测试通过，后续需评估迁移。
- GitHub 仓库已创建；连接器写入返回 integration 403，最终发布与远端 CI 结果另见验收摘要。

## 启动与接续

从仓库根目录按 README 启动，默认端口 8765。主工作台不需 FinQA 下载；实验室需先运行 scripts/download_data.py 并重启。状态保存在 data/，原始材料在 data/raw/，均不进入公开提交。模型、身份和部署配置见 [操作说明](07-operation-and-model.md)。每轮先查 [制作报告](iterations/README.md)，继续用户指定的文档智能、风险因子和模型治理主线。
