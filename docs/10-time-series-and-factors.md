# 从财报核查走向时序预测与金融因子研究

调研与更新日期：2026-10-25（北京时间）。本文是后续研究计划。当前 v0.4 已有财务指标计算与带来源的因子导出；尚无多公司季度面板、真实时序模型评测、自动因子挖掘或预测收益结果。

时空图、多模态与组合方法的研究依据见 [平台设计](11-financial-research-platform.md)。一个微软财年的季度数据整理脚本已在 v0.5 接入只读研究页面，作为下面任务的数据准备；尚未达到多公司面板或训练条件。收益因子与组合研究作为有数据门槛的后续任务，和经营现金流任务分开评估。

## 给谁用，解决什么问题

继续服务企业信用分析员与复核员。看完一份财报后，他们还需要判断：现金流变差是季节变化还是持续恶化，短期债务是否增长过快，公告里的新信息是否改变原来的判断，以及哪些企业值得优先核查。

计划把原始财报、历史财务变化、风险线索与预测放在同一案件中。使用者可以沿着一条线查看“原文写了什么 → 指标如何计算 → 与历史有什么不同 → 模型给出什么估计 → 哪些地方需要人工确认”。是否能减少核查时间、降低漏检仍需真人任务验证。

## 把“时序”和“因子”说清楚

**时序研究**就是把连续多个季度的数据连起来看，研究季节性、趋势与异常变化，再尝试估计后续现金流及可能范围。企业财报频率低、披露有延迟、会更正，不能把股票日线模型直接套到季度财务数据上。

**因子研究**就是把值得关注的线索写成有定义、能复算的指标。例如现金流与利润是否匹配、流动资金能覆盖多少短债、资金支出是否持续挤压现金流。还可研究公告中的担保、诉讼或融资变化，但这些文本线索需要原文证据和独立标签。

| 因子类型 | 本项目怎样使用 | 当前状态 |
|---|---|---|
| 可观察财务指标 | 现金流质量、流动性、债务覆盖与资本开支负担，保留公式和原始数字 | 已有示例导出；未证明预测能力 |
| 待验证风险线索 | 指标变化、波动、公告事件及其组合，研究能否解释后续现金流变化或帮助排序核查任务 | 研究计划 |
| 收益 alpha／资产定价因子 | 预测投资回报或解释共同风险的另一类任务；可借鉴因子搜索与验证方法 | 当前财务指标尚未验证 alpha；不包含交易执行系统 |

## 第一个实验：财报发布后的季度现金流估计

使用者是信用分析员，目的是安排后续核查与了解现金流变化，不自动审批贷款。任务先限定非金融企业；银行、保险的财务结构需另行设计。

| 要素 | 拟定规则 |
|---|---|
| 观察时点 | 季度 q 的官方报告公开后，以能够证明的公开时间 t 冻结输入；只有日期时采用保守可得日约定并单列记录 |
| 目标与窗口 | 估计该企业财季 q+1 的单季经营现金流，输出点估计和区间 |
| 预测还是当季估计 | t 在 q+1 开始前为预测；落在 q+1 内为当季估计（nowcasting），分开评分；目标季度已结束的样本从主实验排除 |
| 输入 | 截至 t 可得的历史财务序列、可复算因子、带出处和公开时间的公告事件；宏观数据如引入需真实历史版本 |
| 标签 | q+1 现金流首次正式披露的值及公布时间；更正后的值另作敏感性分析，不静默覆盖原标签 |
| 使用成本 | 除计算时间与显存，记录每案待人工核查数量、误报和漏报；没有真人或合格事件标签时不报告业务改善 |

拟用 [SEC EDGAR 官方 API](https://www.sec.gov/search-filings/edgar-application-programming-interfaces) 的提交记录、XBRL 与原始 filing 建面板。SEC 的聚合接口会持续更新，不能直接把今天下载的 companyfacts 当成当年的信息集。每个值必须关联 accession、期间、单位与当时已公开的版本。

季度累计现金流须在相同财年、实体范围和版本口径下差分；第四季度由年报与前三季度累计值推导时保留两份依据。缺失不补零，币种不混合，52／53 周财年和并购造成的不可比单列。完整披露登记沿用 [数据约定](09-data-register.md)。这批面板尚未导入。

## 怎样验证，才值得增加复杂模型

1. **先冻结数据和简单基线。** 先跑去年同季值、只用历史的季节中位数、线性模型和树模型。样本不足或标签质量不合格时停在数据与因子报告。
2. **分开比较模型与信息增量。** A 为基础历史数据；B 加既有财务因子；C 再加带原文的公告因子；D 在相同可用信息与调参资源下加入候选时序模型。模型不支持某类输入时，比较结论必须标明差异，不能冒充等条件胜出。
3. **按时间滚动，另留未见公司。** 训练、验证、测试按披露可得时点推进；训练标签的公开时间也必须不晚于训练截止日。跨越分割边界的标签窗口须清除；未见公司切片不参与参数拟合、因子筛选或调参，同一报告的修订和近重复不能跨集合。
4. **限制因子搜索。** 先定义少量有金融含义的公式、运算符和搜索次数上限，记录所有尝试与失败。在训练／验证集上选择，冻结后只评一次最终测试；多重试验与因子相关性需控制，不能反复看测试集挑“好因子”。解释或 LLM 打分不替代独立结果标签。
5. **评估误差、区间和稳定性。** 报告 MAE、按训练期尺度归一后的误差、分位数损失、区间覆盖和宽度；零尺度、缺失、负现金流分别处理。按行业、公司、报告年份、序列长度及版式切片，记录失败率和拒绝输出率，并用适合公司／时间相关性的重采样报告不确定性。
6. **审查模型自己的信息边界。** 预训练语料或截止日不明时，明确无法排除污染；优先做模型发布后的测试或前瞻留出。项目内的训练／测试切分不能证明基础模型完全没见过测试材料。

不使用只适用于收益排序的 IC／Sharpe 来替代现金流预测或信用风险效果。若做风险事件排序，需要另外定义事件、预测窗口及独立标签，并报告相同核查资源下的召回、误报和成本；当前没有这样的验证结果。

## 待验证的研究问题

拟检验的 H2：在相同披露时点、信息与计算资源下，加入有原文依据、能通过财务口径检查的文档因子，是否能改善季度现金流估计，并在未见公司、不同年份和报告更正后保持稳定。

消融将分别移除文本事件、财务口径控制和版本时点控制。对照包括只用结构化数据、普通文本抽取和带证据约束的抽取；人工核验子集区分“取错数字”与“数字正确但没有预测力”。故意违反时点的版本只作泄漏诊断，不参与合法模型排名。

这个问题有金融与 AI 的交叉研究空间，但目前只是研究假设。可发表性取决于新颖性、数据质量、强基线、统计证据及可复现结果；接上论文模型或堆叠 Agent 不构成已经取得的学术贡献。

## 实验依赖

先完成季度面板与版本登记，再交付因子历史视图和 CPU 简单基线；之后冻结评测，选择一个许可适用的小型时序模型作离线对照，再考虑文档因子与微调。这个顺序服务同一信用复核流程。

时序模型与因子挖掘仍为待验证方案。评测数据、合法标签、可运行脚本及资源测试完成前，不报告训练成绩或预测效果。
