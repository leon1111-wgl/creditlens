# 从财报核查走向多模态金融研究与风险分析

更新：2026-10-25。用户希望扩大项目目标，并参考华南理工吴庆耀老师参与的研究。本轮调整的是产品方向和实施顺序；论文里的方法与成绩不属于 CreditLens。下文明确区分已有模块、拟开发功能和待验证研究。

## 项目到底要做什么

**CreditLens 的目标是帮助投研和风险团队持续研究一家公司：读懂材料，跟踪变化，找出值得关注的信号，检验预测，留下可复查的依据。**

2026-10-25 补充港大实际项目与横向合作调研后，先将任务收敛到[两家公司、两期年度的现金流研究底稿](research/2026-10-25-enterprise-research-design.md)。第18轮已实现[跨公司材料研究与版本交接](20-research-tasks.md)：问题、采用理由、年度变化、人工候选解释和复核快照在同一任务内。微软与苹果口径不同，只计算各自变化，不作严格同行排名。具体参照包括[企业文档工作流合作](research/2026-10-25-hku-industry-projects.md)与[相关团队公开模型及基准](research/2026-10-25-hku-team-projects.md)。下一步补解释依据与可比材料，预测和因子模型仍待验证。

分析员不只问“这个数字对不对”，还会问：利润增长为什么没有变成现金？资本开支上升之后，资金压力会如何变化？类似企业是否也出现同样问题？公告里哪些信息值得加入研究？一个指标以前看起来有效，换个年份是否还成立？

平台围绕这些问题组织五项能力：

| 能力 | 使用者能做什么 | 当前进度 |
|---|---|---|
| 多模态资料研究 | 联合阅读财报、公告、表格、图表与扫描件，找到依据，比较不同材料的说法 | 已有两家公司固定 PDF 定位、真实 CPU OCR 与图文核对页面；通用阅读和视觉问答待做 |
| 企业变化与时序分析 | 按当时可得材料串起多期经营数据，观察变化，估计后续现金流及不确定范围 | 新增微软一个财年的季度数据整理与时间过滤；预测未开始 |
| 因子研究 | 从数字、文字和事件提出可解释信号，检验对企业风险或市场表现是否有增量信息 | 已有财务观察指标；文本因子、自动搜索与有效性检验待做 |
| 企业关系与组合研究 | 研究行业、已披露交易关系和相关风险；比较有成本约束的组合方案 | 研究设计阶段，无关系图模型、收益预测或交易执行 |
| 研究验证与协作 | 保存数据和实验版本，比较基线，发现不可靠结果，交给独立人员复核 | 已有复核身份、权限和事件记录；模型实验、监控和机构运维待完善 |

典型完整演示目标：选一组同行公司和历史日期 → 查看当时已公开的材料 → 对比现金流、资本开支和公告变化 → 生成带原文的研究信号 → 对比简单基线与模型预测 → 查看误差、失效案例和风险情景 → 导出研究底稿供复核。目前这条完整流程尚未全部打通。

先服务机构基本面投研、信用研究和风险分析团队；量化研究作为同一数据与实验体系上的扩展。财报核查成为所有研究共用的数据基础。正式授信、投资决策和交易执行仍由有权限的人或既有机构系统负责。

## 企业为什么可能需要它，现有产品做到哪里

需求判断沿用 2026-10-25 的 [岗位与业务调研](01-product-and-career.md)：用户提供的岗位重视金融数据、RAG／Agent、数值计算、模型验证、后训练与工程部署。官方团队介绍支持金融业务与模型、平台协同的方向，但不足以证明整个招聘市场排名。扩大后的项目应展示数据工程、模型实验和完整研究流程；不靠功能名称替代高级岗位的经验要求。

本轮补查 [Microsoft Qlib](https://github.com/microsoft/qlib) 与 [RD-Agent](https://github.com/microsoft/RD-Agent) 官方仓库：前者组织量化数据、模型、研究和组合回测，后者探索自动化研发与因子／模型研究。它们的 README 是维护方对功能的说明，本轮未安装测评，不将其结果当作独立验证。此前的 FinRobot、RAGFlow、Docling 等比较见 [首轮调研](02-open-source-and-papers.md)。

| 对照方向 | 借鉴什么 | 本项目要证明的价值 |
|---|---|---|
| Qlib 等量化研究框架 | 统一数据接口、模型基线、回测与实验记录 | 将公告原文和可得时间接到特征，追查某次模型判断用了什么；不重新发明交易引擎 |
| RD-Agent 等自动研究工具 | 生成假设、实现候选、执行实验并记录失败 | Agent 可以提出因子，但不能修改冻结测试集、成本假设或评分器来让自己高分 |
| FinRobot 等金融研究 Agent | 检索、计算、叙述与研究任务组织 | 同时检查证据、时间和模型失效，比较完成同一任务的成本与错误 |
| 文档智能与 RAG 产品 | 把杂乱材料转成可检索的结构 | 验证表格、附注和时间错位对研究结果的实际影响 |

企业痛点假设是：资料整理与模型研究分离，导致数字有出处但进入模型时已失去时间和口径信息；研究结果难回溯、难交接。需要通过从业者任务测试确认，尚未做客户访谈，不宣称这些产品不具备相似能力。

## 把研究做深：一个主问题，两条实验任务

主问题暂定为：**在财务披露不齐、发布时间不一致的情况下，把文本、数字、时间和企业关系结合起来，能否得到更稳定、可检查的金融研究信号？**

这是研究假设，不是已证明的创新。候选方法是在多模态时序模型中显式区分“已披露”“计算得到”“模型估计”和“尚未可知”，让证据质量与缺失状态随特征进入模型；再检查这种处理是否改善样本外误差和可靠性。文献查重与基线复现完成前不命名新算法或承诺论文发表。

**任务 A：公司经营与风险研究，先实施。** 以披露日为观察时点，估计下一目标季度的经营现金流与区间，分析资本开支及现金转化的变化。真实值取目标季度首次披露，后续修订单独登记。季度已开始时分为 nowcasting，已结束则退出这项预测实验。先跑去年同季、季节统计、线性和树模型，再比较加入文本与关系信息后的变化。报告时间外误差、区间覆盖及分行业失效情况。不能把现金流误差改称违约预测能力。

**任务 B：收益因子与组合研究，满足数据条件后启动。** 使用当时的可投资公司集合、可得行情和公告，研究下一月收益排序及其成本后的组合表现。观察时点、交易日历、执行价、停牌退市、公司行动、基准、换手、滑点、费率和容量限制必须先固定。所有组合使用同一约束；与等权、简单风格因子及树模型比较，分开报告预测指标与成本后收益、回撤、换手。统计关系不等于可交易收益。没有合法且足够完整的数据时只发布设计与失败记录，不用几条股价序列展示“有效策略”。

两项任务共同遵守：先冻结时间外测试集，再调参；另外保留未见公司切片；标签只在真实公布后进入训练；标准化、缺失填补、文本编码微调和图构建只拟合训练段；关系边带有效时间，禁止使用今天的行业成分、供应链或词汇统计回填过去。自动因子搜索记录尝试总数、复杂度、相关性和选择规则，避免大量尝试后的偶然赢家。模型预训练污染与当前网页版本无法还原历史的限制单独披露。

## 按可验收成果推进

1. **当前：把数据基础接起来。** 已有原文定位、观察因子和独立复核；本轮增加季度现金流整理，见下方复现。还没有完整多公司面板。
2. **接下来：公司研究工作台。** 多公司、多季度、首次披露与修订链；在页面查看趋势和公告变化，输出可复核的比较报告。先冻结一个小型开发集与未见公司／未来时间段，达不到足够覆盖不开始宣传模型成绩。
3. **随后：可比较的模型实验。** 同数据、同预算跑统计／树模型、时序模型和文本增量实验；记录失败结果、运行耗时与资源。先交付一条完整任务的可重跑报告。
4. **再扩展：关系与组合实验。** 获得合法历史成分与行情后，加入时点化关系和交易成本；优先接入成熟研究组件而不是自建交易系统。
5. **贯穿各阶段：治理与展示。** 模型与数据版本、权限、人工复核、运行监控、失败重试、部署与恢复。在线演示尚待上线；不能把本地 API 当成企业生产系统。

A100 40GB 仍留给冻结数据与基线之后的多模态／时序实验。当前数据整理和统计基线可以用 CPU；训练时先测短任务的显存、吞吐和外推时间，再提出租期与费用，获得费用授权才启动。

## 本轮实际落地：季度数据研究模块

微软 FY2025 四次官方现金流披露已整理为 18 项原始事实，包含直接披露的单季和累计数。导出后得到 12 个季度指标位置：前三季 9 个直接披露值，第四季 3 个由全年减九个月得到的候选值，始终标记待复核。不会把全年现金流当作第四季，也不会把推导值写回原始披露。

```bash
python scripts/export_quarters.py --as-of 2025-01-30 --output .run/january-snapshot.json
python scripts/export_quarters.py --as-of 2025-07-31
# 从官方网页重建；完整网页只保存本地

```
