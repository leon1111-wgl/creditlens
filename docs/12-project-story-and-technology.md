# CreditLens：项目用途、企业需求与技术实现

更新：2026-10-25。按用户提供的 LoopDesk 表达方式组织。下文是完整目标与分阶段实现方案，**“已有基础”不代表完整企业产品，“计划”不代表已上线，“研究”不代表已经有效**。实现与验收以 [当前状态](06-implementation-status.md) 为准。

## CreditLens 是什么

一个正在建设的企业 AI 金融研究平台，给投研、信用研究和风险团队用。

它要把读财报、查公告、看经营变化、找研究线索和检验模型放在同一个工作台里。分析员可以从一个问题开始，例如“这家公司利润涨了，为什么现金流反而变差”，一路查看原始材料、相关指标、历史变化和实验结果，再把带依据的研究底稿交给同事复核。

现在已有官方财报案例、图像与文本核对、数字校验、季度研究，以及跨公司材料研究和版本交接；接下来扩展可比材料与解释依据、公告跟踪、时序预测、因子检验和企业关系分析。

现在能完成的研究任务是：**查看企业现金流发生了什么变化，记下原因还缺哪些依据，交付一份同事能接手的底稿。** [研究任务](20-research-tasks.md)把数字、采用理由、口径、人工候选解释和提交快照接到一起，退回修订时保留旧版。目前使用微软与苹果样例，计算各自年度变化；严格同行比较和解释支持／反驳证据还要补齐。

## 企业需要什么

金融团队需要的是能帮助他们把研究做扎实、把错误找出来的工具。

- **材料太散。** 数字在 Excel，解释在附注，风险线索在公告，图表和扫描件还要单独看。分析员需要把同一家公司、同一件事的材料对齐。
- **数字容易用错。** 单季和累计数、美元和人民币、合并报表和分部数据、原版和修订版混在一起，算式没错也可能得出错误结论。
- **变化难跟。** 财报更新后，旧结论是否还成立，哪些指标发生变化，需要重新查哪些材料，常常要人工梳理。
- **研究容易“看起来有效”。** 模型可能用到了未来数据，因子可能只适合某几年，回测还可能漏掉交易成本。团队需要能检验失效、重跑结果的实验流程。
- **结果需要交接。** 复核员要知道用了哪些资料、怎样计算、哪里不确定、谁确认过，才能决定是否采纳。

这些是根据用户岗位材料、官方产品与研究资料形成的需求假设，尚未通过客户访谈或实际机构部署验证；不宣称已节省某个比例的工时。需求依据见 [岗位与业务调研](01-product-and-career.md)，竞品复核见 [独立顾问报告](research/2026-10-25-advisory-01.md)。

## 下一步怎样把一项研究做完整

研究任务和固定快照已接通，下一步补齐同口径同行材料与现金流解释。研究员记录材料选择理由，系统检查实际期间、币种、经营范围与固定资产现金支出定义。不能比较时保留原值和原因，不能悄悄改口径或挑另一家公司。

例如，“现金流下降是因为应收款增加”需要现金流调节表或对应说明。只有现金流总额时，底稿应列出缺少哪份依据；找到管理层解释时，明确它是公司说法。后续有样本外结果，才能进一步讨论这个线索是否帮助预测。

现有 AMD 与 NVIDIA 文档诊断材料不能直接排同行榜；本轮微软与苹果研究材料也有年度结束日和财年口径差异。当前文件不能证明在过去已经公开，历史模式因版本证据不足而拒绝。早期设计见[任务方案](research/2026-10-25-enterprise-research-design.md)，实际接口与已验收范围以[研究任务说明](20-research-tasks.md)为准。

## 技术实现

### 读懂材料：把正文、表格和原页一起用

**已有基础：** 对微软和苹果的固定官方披露页做数字定位，再让真实 OCR 模型看整页图片，逐项核对金额符号、年份、期间、单位文字、行标签和分区。页面同时显示原页、识别框和未通过原因；模糊、跨列或缺证据时保留不足，不自动修数字。这是已知位置核对，通用材料理解尚未完成。实际结果见 [OCR 实验](13-document-ai-experiment.md)。

**计划：** 在当前 OCR 基础上，结合版面解析、文本检索与视觉文档检索（Visual Document Retrieval），先找到相关页面，再抽取表格和文字。参考 **ColPali，ICLR 2025** 的页面多向量表示与后期交互匹配（Late Interaction），对比它与 OCR＋文本检索在财报上的召回、延迟和成本。检索模型负责找资料，金额仍由结构化抽取与数值校验检查；找到页面不等于读准数字。[正式论文](https://proceedings.iclr.cc/paper_files/paper/2025/file/99e9e141aafc314f76b0ca3dd66898b3-Paper-Conference.pdf)

新公司诊断已加入 NVIDIA 与 AMD：工作台可以切换任务，查看数值、日期、识别依据和原页。NVIDIA 先发现参考框问题，修正后又发现日期关联不足，原失败保留，新日期规则另作开发对照；AMD 在固定规则后检查，字词方法仍有两项货币符号关联不足，未为通过而放宽。当前不会把“金额读对”直接变成“整项可以用”，详见[诊断说明](17-new-issuer-transfer.md)、[日期对照](18-date-association.md)与[固定规则检查](19-issuer-evaluation.md)。

### 防数字用错：计算交给程序，结论带着依据

**已有基础：** 用严格数据结构（Schema Validation）记录原文值、归一值、单位、财务期间和来源；用精确数值计算与规则核对单季／累计、币种、缺失和冲突。计算出来的值保持“推导待复核”，不能冒充原始披露。

**计划：** 对生成报告逐项检查事实与引用（Claim-level Grounding），数字结论必须连到原始单元格和公式。原文不支持、口径冲突或缺少关键数据时，返回缺口与核查任务。大模型负责提出解释，校验器负责检查证据和计算；检索召回率、抽取正确率、计算正确率与回答质量分别测。

### 防偷看未来：只使用那个时点能获得的信息

**已有基础：** 按已登记公告日期生成季度快照；只有日期、没有时刻时，保守地从次日纳入。

**计划：** 建立按历史时点查询的数据层（Point-in-Time），同时记录公告时间、系统抓取时间和修订版本，分别支持“首次披露”“截至当时最新版本”和“今天最新修订版”。后来的更正不能悄悄覆盖旧实验。参考 **Qlib 的 PIT 数据库**；这不是本项目独创方法。当前抓取的官方网页还不能证明历史版本完整。[Qlib 官方说明](https://qlib.readthedocs.io/en/latest/advanced/PIT.html)

### 看经营趋势：先验证预测是否比简单方法更有用

**已有基础：** 季度现金流、资本开支和利润的整理与历史查看；尚无预测结果。

**研究：** 数据达到条件后，先预测下一目标季度的经营现金流，与去年同季、季节统计、线性和树模型比较，再测试 **Time-MoE，ICLR 2025** 等时序基础模型。按时间滚动验证（Walk-forward Validation），另外测试未见公司；报告误差、预测区间覆盖、失败行业与推理成本。Time-MoE 是时序模型候选，不自动具备文本理解或跨公司关系建模；不能把它在其他数据上的成绩直接移到财报任务。[正式论文](https://proceedings.iclr.cc/paper_files/paper/2025/hash/558d48c1f08675daa636e09bfe94a89e-Abstract-Conference.html)

### 找研究线索：把直觉变成可检验的因子

**已有基础：** 现金转化、资本开支负担等带公式和来源的观察指标；尚未证明预测能力。

**研究：** 把“利润增长却收不到现金”“融资依赖持续增加”等假设写成可复算的指标，再验证它是否有增量信息。参考 **AlphaForge，AAAI 2025** 的公式化因子发现与组合思路，建立候选公式、去重、复杂度约束和样本外验证。现金流预测、信用风险线索和股票收益 alpha 分别定义目标，不能互相替代；收益实验满足行情与成本条件后另行开展。[正式论文](https://ojs.aaai.org/index.php/AAAI/article/view/33365/35520)

### 研究企业关联：区分公开关系和模型猜到的关联

**研究：** 将有证据的投资、担保和交易关系，与模型学习出的统计关联分别记录，每条关系带来源和可得时间。参考吴庆耀老师参与的 **Melody-GCN、STDM、Cafe-GCN、Caracal**，逐步检验数字、文本、多尺度变化与关系信息能否互补。

先比较纯数字、加入文本、再加入关系的结果；缺失值与模型估计保留不同身份。模型相关性不证明风险传染的因果关系，组合研究还需历史成分、退市、公司行动与交易成本数据。论文出处与可复现边界见 [平台研究方案](11-financial-research-platform.md)。

### 让 Agent 做研究：提出假设，也接受失败

**已有基础：** 受限计算计划接口通过模拟响应测试；真实模型效果尚未验证。独立顾问分支用于开发建议，不等于产品已有自动研究 Agent。

**计划：** 参考 **R&D-Agent-Quant，NeurIPS 2025 Datasets and Benchmarks Track** 的研究—开发—反馈流程，让 Agent 提出假设、生成候选特征、调用检索与计算工具、执行实验，再根据误差提出下一轮建议。[正式论文](https://proceedings.neurips.cc/paper_files/paper/2025/hash/ac5c2b6e423883cbcacbcccf88491b78-Abstract-Datasets_and_Benchmarks_Track.html)

工具按白名单开放，候选代码在隔离环境运行，并限制时间、资源和网络权限；冻结测试集、评价器与交易成本由独立流程管理，Agent 不能为了提高分数修改它们。记录所有尝试和失败，避免只展示最好的一次。论文收益属于原论文，不是本项目收益。

### 让团队敢用：能复核、能重跑，也知道何时不该用

**已有基础：** API-key 身份与租户约束、独立复核、版本冲突检查、幂等操作和事件记录。当前事件哈希链不等于外部防篡改存储。

**计划：** 加入冻结评测集、数据及模型版本、漂移和分布外检测、预测区间校准、数据泄漏与提示注入测试、模型回退和监控。人工修正先形成候选样本，审核后进入版本化数据与评测，不能自动污染冻结测试集。证据不足或模型不适用时停止给结论并交人工处理。

这些工程控制需要实际验收；采用某个框架或遵循研究方法，本身不意味着已经达到金融监管要求。

## 目前与下一步

- **目前能演示：** 官方历史披露案例 → 数字与口径核对 → 指标／季度查看 → 原始依据追查 → 独立人工复核与导出。季度研究页是只读研究，不会自动把推导值批准成事实。
- **近期建设：** 多公司历史披露与修订链、公告变化跟踪、跨文档检索、真实模型评测与比较报告。
- **后续研究：** 现金流时序预测、文本与财务因子、关系模型、自动研究 Agent、有成本约束的组合实验。

数据不会因开发任务每 15 分钟运行就自动更新。现有功能可用 CPU；A100 40GB 留到合法数据、冻结任务和基线齐备后评估。任何租卡或付费服务先获得费用授权。
