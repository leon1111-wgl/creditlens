# 让图片识别与财报文本互相核对

日期：2026-10-25。原实验版本：v0.6.0。此实验已在 Windows / Python 3.12.14 本机运行。第 13 轮更新复现路径与保护机制，下面的模型结果仍是原始记录。

## 能帮分析员做什么

财报里的金额看起来很清楚，提取时却可能串到另一年、丢掉括号负号，或把旁边一列的美元符号一起读进来。文档核对页面把原页、文本层登记值、图片识别结果和检查原因放在一起，让人知道哪些地方值得再看一遍。

这是金融研究的数据入口。将来数字进入季度分析、因子和预测前，应该保留这样的依据和缺口。本轮结果还没有自动加入信用复核的批准条件，也不会改写事实或批准底稿。

## 实际怎样运行

1. 校验微软、苹果官方 PDF 的已登记 SHA-256。按已有开发事实选取六页，以 2 倍比例渲染**没有标记框的完整页面**。
2. RapidOCR 的检测和识别模型只接收整页图片。不给模型参考金额、标签、定位框或 PDF 文本；不按参考框裁剪后冒充整页识别。
3. 保存完整原始 OCR 文字、框和分数到本地，再转换为左上角原点的 PDF point 坐标。
4. 程序按已登记位置取候选，逐项检查金额与符号、年份、期间、单位文字、行标签；存在分区时也检查起止标签。数字不会因为参考答案而被猜测修正。
5. 分别保存“一致”“冲突”“证据不足”。页面叠加绿色登记框和橙色 OCR 框，支持公司／事实／状态筛选、定位区域／整页查看，以及核对记录导出。

页面读取保存的运行记录；刷新和“载入核对记录”都不启动模型。完整页图只从本地登记路径加载，API-key 模式要求带身份请求，不把密钥放进图片地址。不同租户目前看到的是同一组公开案例，不包含私有文档服务。

## 模型与复现配置

配置见 [document-ai.json](../configs/document-ai.json)，实际环境和结果见 [运行记录](../artifacts/document-ai-report.json)。

| 项目 | 本轮实际配置 |
|---|---|
| OCR 包 | RapidOCR 3.10.0 |
| 检测／识别 | PP-OCRv6 small 的 ONNX 制品，显式本地路径与 SHA-256 |
| 推理 | ONNX Runtime 1.31.0，检测／识别实际 provider 均为 CPUExecutionProvider |
| 并行 | intra-op 4、inter-op 1；未用 GPU |
| 渲染 | pypdfium2 5.14.0、Pillow 13.0.0，2 倍页面尺寸；旋转页拒绝 |
| 空间核对 | 交集占目标框至少 0.35，或识别框中心落在目标框；识别框越界超过 8 point 时保留不足 |
| 分数门槛 | 0.90；只作拒绝低分候选的工程规则，不是校准后的正确概率 |
| 金额规范化 | 严格解析千分符、括号和显式正负号；保留原字符串；不按答案修复字符或截取匹配子串 |
| 规则 | visual-evidence-1；配置指纹和源事实包指纹写入运行记录 |

本轮没有训练新模型。初次安装从 PyPI 获取依赖及包内模型；运行时显式验证两个权重哈希，缺失或不一致直接停止，不静默切换默认模型。许可依据是 [RapidOCR 官方模型归属声明](https://rapidai.github.io/RapidOCRDocs/main/model_licenses/)；代码、转换权重、原始财报和运行时各自保留许可边界，见 [第三方说明](../THIRD_PARTY_NOTICES.md)。

原始方法参考 [PaddleOCR 3.0 作者技术报告](https://arxiv.org/abs/2507.05595) 对文字识别、版面结构和信息抽取的区分。该报告介绍的 v5 成绩不能替本轮 v6 制品报成绩。视觉页面检索仍是下一阶段对照方向，ColPali 等出处见 [技术路线](12-project-story-and-technology.md)，本轮没有复现其效果。

## 结果与失败

| 已有开发样例 | 页面 | 登记事实 | 全字段一致 | 明确冲突 | 证据不足 |
|---|---|---:|---:|---:|---:|
| 微软 FY2025 10-K | 50、52、53 | 20 | 18 | 0 | 2 |
| 苹果 FY2025 10-K | 32、34、36 | 22 | 21 | 0 | 1 |
| 合计 | 6 页 | 42 | 39 | 0 | 3 |

保留的三项失败：微软 2025 净利润 `101,832`、2024 净利润 `88,136`，苹果 2025 现金及现金等价物 `35,934`。模型分别输出 `101,832 $`、`88,136 $` 和 `35,934 $`，识别框延伸到旁边列的美元符号。虽然包含期望数字，程序仍判证据不足，没有删字符或取子串使其通过。

六页本轮 OCR 调用合计约 11.88 秒，各页明细写入 JSON。它不含安装、模型初始化和 PDF 渲染，只是这台电脑上本次运行的记录，不是吞吐承诺或性能基准。

39/42 **不是通用文档理解准确率**：页面和事实位置已知，参考由开发者整理，未做独立双人标注或未见公司盲测。0 项冲突也不证明能发现所有真实错误。OCR 与文本层来自同一份材料，不能鉴定真实性；单位文字匹配不能独立证明配置中的币种。

## 失败和变更如何被拦住

缺字段、低分、乱码、跨列或多义候选保留不足；有明确不符则记冲突，不自动取绝对值或修负号。API 读取时核验源文件声明、事实集合、页面、配置及规则，使用源事实和发布的观察重新计算每项结果及统计。损坏、遗漏或不一致的记录返回 409，不能沿用一份旧的“通过”统计。

原页图片也核对 PNG 标识和 SHA-256。缺图提示本地复现；不根据 URL 参数读取任意路径。该机制检查数据一致性，不声称能抵御管理员同时重写全部证据、模型输出和指纹。

新增 21 项规则、存储和 API 测试，覆盖负号、错年、错单位、低分、空页、多候选、错列、无参考修复、阈值变化、坐标边界、报告损坏、图像损坏、鉴权和只读约束。测试中的人为 OCR 变体是程序回归样例，不计入上表真实 OCR 运行结果。CI 读取保存结果验证契约，不重新运行 OCR 模型。

## 如何重跑

从仓库根目录、已安装基础依赖的虚拟环境运行：

```bash
python -m pip install -r requirements-ocr.lock
python scripts/evaluate_document_ai.py --download --local-dir .run/document-ai
python -m unittest tests.test_visual -v
python -m uvicorn creditlens.api:app --host 127.0.0.1 --port 8765
```

上面的命令显式准备网页原页，报告进入 `.run/reproductions/document-ai-report.json`，不覆盖冻结报告。若只研究模型，去掉 `--local-dir`，页图和 OCR 也会进入独立复现目录。三组实验和逐字段对照见[安全复现说明](16-experiment-reproduction.md)。

打开 `http://127.0.0.1:8765/documents`。模型、原始 PDF、完整 OCR JSON 和整页 PNG 保留在本机；公开仓库只有必要的财务片段、来源、定位、配置和结果。使用其他系统或包版本需要重新验证，不能承诺逐字节相同。

## 下一步的验收条件

先固定一个包含未见公司的保留集，并做独立标注。对三项跨列失败做字词级位置与整行输出的并列实验，原基线保持不变，不能按单个答案选择更好输出。加入数字替换、负号丢失、旋转、压缩、模糊和真实授权扫描件，分别报告错误放行、拒绝与覆盖。合成退化图不冒充真实扫描件。

再比较通用表格结构解析与视觉模型：跨页续表、单位脚注、图表数值、正文与表格冲突分开测。只有任务、数据、模型许可和小规模推理脚本准备好后，才评估是否租 A100；当前 CPU 实验不需要租卡。
