# 一起核对完整日期、年份和金额所在列

更新：2026-10-25。对应 v0.8.1；NVIDIA 是已经观察过的开发材料，本页不报告未见公司成绩。

## 解决什么问题

财报常把 `Jan 26, 2025` 写成一整行。原来的数字保护规则看到年份旁边还有 `26,`，会要求检查，避免把相邻数字误当成同一金额。直接去掉保护会带来漏负号和串列风险。

日期关联规则先确认整行确实是完整日期，再确认其中的年份、财务期间截止日以及金额所在列相互对应。其他字段继续使用原来的规则。分析员按共同表头查看受影响项目，不必把同一个日期重复当作多个问题处理。

## 规则怎样工作

新模块 [date_evidence.py](../creditlens/date_evidence.py) 保留旧字词结果，再检查：

1. 年份本身已经由原数字规则正确读取，唯一未解决的保护原因是附近的数字片段；已有年份冲突不能被覆盖。
2. 完整日期在行级、字词级都一致，属于唯一父行，词组没有丢字、补字、漏标点或改变顺序。
3. 整行必须严格解析为英文月份名称、日期、逗号及四位年份，并通过日历合法性检查；不取碰巧等于答案的子串。
4. 年份框位于日期框内，金额位于该年份列下方，日期与登记的期间截止日相符。
5. 每个触发保护的附近数字都能归属于同一父行的日期。来自其他父行、没有词框的邻近数字或额外数字仍然阻断。

满足这些条件才记 `date_association.applied=true`。原年份已经一致时保持原样，不表示又完成了一次完整日期检查。金额、单位、行标签、分区和其他失败逐字段保留；任何一致结果都不会自动批准财务事实。

当前只支持有完整父行的英文文字日期；数字式日期、多行表头、中文日期、缺失年份和其他版式仍需单独设计、验证。当前空间检查是已登记位置上的核对，不是通用表格结构识别。

## 保留什么证据

[日期对照报告](../artifacts/date-diagnostic-report.json) 将原行级、原字词和日期关联结果放在一起。它绑定原报告、参考、模型配置及新规则代码的指纹，读取时逐项重算，不只比较最终计数。

原始 [v1 无效参考报告](../artifacts/document-transfer-v1-invalid-report.json) 和 [v2 修正参考诊断](../artifacts/document-transfer-report.json) 都保持不变。新报告是对已发布必要父行与完整词组的复算，没有重新推理；仅这些片段不能证明完整 OCR 没有遗漏。完整输入可另用下述只读工具核验。

四个日期表头共同影响 16 项事实，所以表头数和事实数分开记录。新旧结果不同反映核对规则的变化，不能叫作 OCR 模型准确率提升。材料包装发布日期仍未知，不能因为日期关联通过就接入严格历史回测。

## 怎样运行和查看

从仓库根目录运行，无需 GPU、模型调用或网络下载：

```bash
python scripts/evaluate_date_diagnostic.py
```

默认只新建 `.run/reproductions/date-diagnostic-report.json`。再次运行须通过 `--output` 指定该目录下另一个新 JSON 文件；不会覆盖已发布报告、旧实验或原页预览。通过验收后才能登记为发布版本。

如本机已经保存原始 PDF、两张原页、完整行与字词 OCR，可再运行：

```bash
python scripts/verify_date_raw.py --raw-dir .run/reproductions/document-transfer
```

该命令只读输入，在终端返回核验结果；缺文件或摘要不符即失败，不会自动下载或重跑。它检查 PDF／图片字节、完整 OCR 摘要、公开父行对应关系，再把父行索引映射回整页，逐字段比较新日期结果。这证明与所登记本地输入一致，不证明材料真实或最初模型运行的独立真实性。

启动 API 后打开 `/transfer`：先看四个表头，再筛选相关项目、比较新旧原因，查看原页日期／金额位置，导出同一来源的完整对照。`/api/date-diagnostic` 使用现有身份认证，保持只读；这些公开案例不是私有租户文档服务。

## 扩展验证范围

下一家公司须先登记官方来源与可得日期，独立检查 PDF 几何及参考表头，再固定规则、全部事实和排除理由，随后一次运行。至少覆盖年份单列与完整日期两种表头、相邻比较列和一个负值项目；按公司和物理表头分别计数，保留不足与失败。

跨页表格先定义续表识别、重复表头、单位脚注与完整页集合；图表先区分明确标注数字与近似估读。两类任务目前只有设计，没有新的识别或问答成绩。扩展任务的设计见[文档智能方案](08-document-ai-and-governance.md)。
