# 换一家公司，固定规则后再检查

更新：2026-10-25，v0.9.0。使用者是投研分析员和模型验证人员：先查看换一种财报版式后哪些字段仍能核对，哪些需要人工处理，再决定下一步改哪里。

## 实验设置

在查看 AMD 的 OCR 之前，选定官方投资者关系网站的 FY2025 年报两页、七种指标的两年比较，共14项事实。金额、表头和分区由 PDF 文本层准备参考；参考同时经过原页和坐标的工具辅助检查，尚不属于独立人工标注基准。

参考准备先按行标签、分区边界和年份列定位，不用预期金额搜索单元格。完整页面保持无标记，OCR 只读图片。参考、源文件、页面图像、13份运行文件、2份参考准备文件、六个执行库版本及模型配置在正式推理前固定。初次启动遇到 RapidOCR 延迟初始化问题，在渲染和识别之前退出；修复仅加载模型的步骤，再次冻结后才实际运行，见[启动记录](../artifacts/issuer-preflight-attempt.json)。初次冻结提交 `473a699`，有效冻结提交 `5d347e5`；没有根据识别成绩修改金额、框、评分规则或权重。

参考的14个原文金额反查一致，78个区域共156个角与 PDFium 原生坐标核对，最大差异0.5像素，属于渲染取整范围。[参考核验](../artifacts/amd-reference-preflight.json) · [选择与排除范围](../artifacts/amd-reference-provenance.json) · [来源研究](research/2026-10-25-amd-reference.md)。

## 结果与失败

| 固定核对方法 | 完整事实一致 | 冲突 | 证据不足 |
|---|---:|---:|---:|
| 行级 | 10 | 0 | 4 |
| 字词级 | 12 | 0 | 2 |
| 字词级加日期关联 | 12 | 0 | 2 |

两处净利润的货币符号和数字在字词输出中分开，因此字词规则能完成核对；两处现金金额则被识别为含 `$` 的单一词，位置超出登记金额框，仍保留不足。这里没有临时删除符号或扩大框来提高通过数。

四个日期表头的年份与期间检查都一致。两行日期能由既有字段检查核对；严格单行日期关联的 `applied` 是0，因此不能声称该实验验证了新关联规则的增益或实现了通用多行日期推理。非年份检查保持一致。

这是一个未用于调整本项目规则的发行人上的小样本已知位置检查。它不是全报告自动抽取、预训练未见数据、总体准确率或真实性鉴定。14个事实共用两页和四个表头，不能当成14个独立样本。运行后 AMD 已成为观察过的材料，下一次据此改规则属于开发诊断。

## 来源日期与金融口径

底层10-K和10-K/A均于2026-02-04提交；ARS包装报告提交日为2026-03-27。当前IR PDF与SEC当时登记附件不是相同字节；文档修改时间也不能证明公开时间。因此精确资产首次可得时间仍为未知，`point_in_time_eligible=false`，不进入历史回测。

现金流和资本支出使用持续经营口径，净利润使用包含终止经营的整体口径，字段名称和分区均保留；不能将这些值直接拼成现金转化率或整体自由现金流。前期比较值是本期重新列示的值，不冒充原年度历史快照。未评分列和行在推理前登记，缺失横线不改成零。

## 页面与接口

打开 `/transfer`，默认查看“AMD · 固定规则检查”，也可切换“NVIDIA · 日期规则开发对照”。两者的任务范围、来源与结果分别展示。支持按日期表头查看、筛出待查金额、比较三种方法、查看本地原页日期／金额位置，以及导出当前完整核对记录。切换任务或访问密钥会清空原来的详情与图片。

`GET /api/issuer-evaluation`沿用服务端身份验证，只读提供核验后的发布快照；发布文件或规则变化时拒绝返回旧结果。原页接口必须提供当前图片哈希，避免新图配旧坐标。完整图片需本地准备；新克隆仓库仍可查看公开的字段记录。

## 复现

查看公开结果只需主依赖。重新识别还需安装 `requirements-ocr.lock`、`requirements-pdf.lock` 中的可选依赖和登记模型。正式运行校验六个执行库版本，版本不同会停止，不默默替换。依赖和源站可能随时间变化，应保留原始安装与下载记录。

```bash
python scripts/evaluate_issuer.py --download
python scripts/verify_issuer_raw.py --report .run/reproductions/issuer-evaluation-report.json
```

默认写到 `.run/reproductions/issuer-evaluation/` 和 `.run/reproductions/issuer-evaluation-report.json`；有派生输出时拒绝覆盖。第二次确需重跑时显式选择新的 `--local-dir` 和 `--output`。下载仅接受登记官方源、允许域名和精确哈希；不会请求收费API。

```bash
# 本地完整输入与仓库发布结果核对
python scripts/verify_issuer_raw.py
# 核对成功且图像与发布结果完全相同后准备本地预览
python scripts/prepare_issuer_preview.py
```

完整核验已检查1份PDF、2张原页和4份完整OCR，共7个文件；公开35条必要父行与完整316行对应，所有14项三法结果映射原始父行索引后逐字段一致。核验脚本不重跑模型，不证明文件真实性，也不是第二批模型样本。[发布结果](../artifacts/issuer-evaluation-report.json) · [完整输入核验](../artifacts/issuer-raw-verification.json)。预览位于受实验runner保护的本地目录，错误图片或已有不同图片拒绝覆盖。
