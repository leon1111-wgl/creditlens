# 从利润到现金流：逐行核对变化

分析员看到“利润上升、现金流下降”，需要先知道差异出在哪些报表项目，再去查经营原因。本功能把现金流量表中的净利润、调节项和经营资产负债变动放在一起，逐行加总，并对照下一年度的变化。

这是研究任务的一份会计核对附件。它能回答“哪些列示项目的变化抵消了利润增长”，还不能单独回答“为什么发生变化”。后者仍需要附注、业务信息和可核对的解释证据。

## 怎样使用

在 `/tasks` 建立研究时勾选“附上经营现金流拆解”。进入“现金流拆解”，选择微软或苹果，查看三类金额贡献；展开逐行变化或单年度表，核查正负号、期间和原页。原有八项材料仍须分别决定采用或拒绝，附件不会覆盖这些决定。

填写“附件核查范围与待补证据”，保存后再提交复核。提交固定资料、规则计算、说明及摘要；复核员确认的是这份有明确范围的研究底稿，不是自动认定所有解释正确。旧任务没有附件时保持原状；可建立新任务使用新功能。

## 数据与算法

- 来源是微软与苹果 FY2025 官方年度报告的经营现金流表及 FY2024 比较列，记录原文件哈希、实际期间、单位、原始显示值、页码和定位框。只发布必要事实及定位，不再分发整份 PDF。
- 登记 52 个金额：微软每期 14 个贡献行及 1 个总计，苹果每期 10 个贡献行及 1 个总计。新事实包独立保存，原文档实验及旧材料不被覆盖。
- 使用 `Decimal` 对原表带符号值求和。净利润＋净利润调节项＋经营资产与负债变动应等于披露经营现金流；两期各行之差再与总额之差核对。每项派生值保留输入事实 ID。
- 缺行、重复、错符号、来源或期间不符、行名或分区变更均不能被补零或自动配对。正常结构但加总不平时保留计算值和差额，便于定位；结构失效时不给可用计算结果。
- 附件的四个经营现金流总额再次绑定旧材料的公司、来源、年份、单位及实际期间。提交前重新检查登记来源和规则是否改变。旧版已提交底稿直接读取冻结内容，不依赖新规则重新计算。

当前样例的会计分解如下，单位均为百万美元：

| 公司 | 净利润变化 | 净利润调节项变化 | 经营资产负债变动的变化 | 经营现金流变化 |
|---|---:|---:|---:|---:|
| 微软 | 13,696 | 11,092 | −7,174 | 17,614 |
| 苹果 | 18,274 | 3,605 | −28,651 | −6,772 |

四期加总和两组年度变化的差额均为零。这是两份固定披露的会计恒等式检查，不是模型准确率。不同公司期间和经营结构不一致，表格不构成同行排名。

## 复现与导出

将与登记哈希一致的官方 PDF 放到本地输入目录后运行：

```bash
python scripts/fetch_registered_sources.py --asset msft-fy2025 --output .run/downloads/cash-flow/msft-fy2025-10k.pdf
python scripts/fetch_registered_sources.py --asset aapl-fy2025 --output .run/downloads/cash-flow/aapl-fy2025-10k.pdf
python scripts/build_cash_flow_bridge.py --pdf-dir .run/downloads/cash-flow --output .run/reproductions/cash-flow-bridge-check.json
```

构建器核对原文件及固定表格分区；输出已存在或指向受保护输入时拒绝覆盖。它是针对这两张已知表格的原生 PDF 提取协议，不是任意财报的通用识别器。

含附件的冻结底稿使用 `research-handoff-2`，旧版仍为 `research-handoff-1`。两版都可用以下命令核对内部摘要与复核绑定：

```bash
python scripts/verify_research_export.py artifacts/research-cash-flow-demo.json
python scripts/verify_research_export.py artifacts/research-task-demo.json
```

导出核验不重新鉴定来源、计算金融结论或认证人员身份；自洽重写整份文件仍可能通过，哈希不是数字签名。网页下载保留服务端原始 JSON，避免浏览器重序列化坐标浮点数改变摘要。

## 边界与下一步

调节项并不全部是非现金项目，经营资产负债变动也不全部等于狭义营运资本。本实现沿用原表分区。FY2024 是 FY2025 报告中的比较列，不能直接当作历史当时已知的数据；当前也没有自动更新或现金流预测。

下一步优先为金额变化关联附注及候选解释，让每个解释标出支持、冲突或缺失的证据；明确完整材料范围后再进行解释评测。文档方面继续处理金额符号与跨页证据，不把已知模板提取扩写成通用多模态理解。
