# 财报金额与符号核对

日期：2026-10-25。这项功能服务财务资料进入计算之前的核查：数字、正负号和货币标记是否属于同一个单元格，是否混入旁边一列。它是识别后的规则诊断，不自动采用事实，也不判断材料真假。

## 从实际失败开始

AMD 原实验的两项现金及等价物识别为 `$5,539` 与 `$3,787`。数字与登记值相同，但美元符号与金额合成一个词，词框左侧超出原金额框，旧规则因此保留不足。不能直接删除 `$`、扩大框或从一串数字里找出与答案相同的部分，使结果通过。

新诊断保留原来的行级、字词级和日期检查，另行记录金额符号的判断。候选先按位置和唯一性选取，再完整解析原字符串；保留父行与词的一致性检查、列范围、识别分数和附近符号的依据。括号、负号、额外数字或相邻列无法排除时仍应保留不足或冲突。`$` 只与登记币种作有限的一致性检查，不能单独证明币种为美元。

## 页面怎样用

打开 `/transfer`，在“实验任务”选择“AMD · 金额符号开发对照”。上方比较四种规则的完整事实结果，逐项展开可同时查看旧不足和新判断。日期、单位、行标签及分区仍独立检查；金额核对通过不会替其他字段放行。

下方的“符号和错列反例”展示合成修改的文字、位置或识别分数，以及每个控制的事先预期与实际结果。这些是软件控制，不能与真实 OCR 记录合并成一个准确率。可导出当前 API 原始响应；访问密钥或任务变化会清空旧详情。

原有 AMD 固定规则检查和 NVIDIA 日期对照仍独立保留。诊断使用已经观察过的 AMD 材料，没有新的公司盲测、模型训练或图像识别。

## 证据与复算

运行结果绑定来源报告、参考资料、实现版本和控制清单。API 读取时检查发布摘要，并重新计算全部项目和反例；只改汇总或重算外层哈希不能授权一个伪造结果。完整 PDF 与模型文件不需要重新下载。

固定开发材料的结果：14项旧资料完整复算，仅两项现金金额使用新关联；原来的12项一致、2项不足保留在原实验，新诊断中14项字段一致。34项合成控制（4个合法正例、30个拒绝反例）均符合预期。它们是已观察材料诊断和软件控制，不是新的识别准确率。

另外读取两页保留的完整OCR，共316条父行；核对35条公开父行及14项事实，映射父行索引后逐字段与规范摘要均相同。这个检查不重新读取PDF或图片，也不证明原始模型执行或材料真实性。

~~~bash
python scripts/evaluate_currency_diagnostic.py --output my-currency-check.json
python scripts/verify_currency_raw.py --raw-dir .run/reproductions/issuer-evaluation
~~~

第一条只新建 .run/reproductions/my-currency-check.json，已有文件会拒绝覆盖。第二条需要原实验留下的四份完整OCR JSON；缺失时明确失败，不自动下载或运行模型。公开仓库的日常页面使用最小证据包，完整OCR与原文仍遵守各自再分发边界。

## 仍待验证

这种检查依赖已登记位置和保存的识别证据。跨页续表、中文币种说明、多行数字、复杂合并单元格、缺失括号和新版式的泛化需要独立数据与评测；不能凭这两处开发问题的修正宣称通用多模态理解能力。
