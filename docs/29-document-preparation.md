# 材料准备：缺页能发现，修正有记录

材料处理人需要知道一份文档能否继续核对，也需要把未处理完的问题交给同事。新入口把同一文档的登记页作为一组检查：缺一页、重复提交一页，或者某页识别输出损坏，都保留为待修正。每次修正产生新的尝试，旧记录仍可查看和导出。

这里检查的是**已登记的证据页**。例如当前 NVIDIA 案例登记了物理页146和148，两页齐全不代表整份年报完整，也不代表已经理解跨页表格。页面接收 OCR JSON，当前入口不提供 PDF 上传、自动 OCR 或内容入库。

![材料准备页面](images/document-preparation-desktop.png)

## 怎样使用

启动工作台后打开 `/document-preparation`。分析员可以新建记录和提交修正版，查看者和复核员只能读取。生产 API-key 模式使用服务端身份，本地演示身份选择不能覆盖密钥权限。

1. 选择“缺一页样例”，新建记录。结果指出缺少哪一页。
2. 选择“坐标错误样例”，提交修正版。页数齐了，但问题页仍显示错误字段。
3. 选择“完整样例”，再次提交。结果变为“准备通过，等待内容核对”。
4. 点击任一次尝试，查看当时的页集、问题和来源绑定，并导出该次 JSON。页面标题保留任务当前版本，尝试区明确显示正在看的历史版本。

三个样例中的 `SAMPLE` 文字、坐标和处理人均为合成输入，只借用公开登记的页码与尺寸，不是新的识别实验或企业使用记录。输入也可在折叠编辑器中修改；原始正文不会保存到准备记录数据库。

## 四句话验收

| 模块 | 输入是什么 | 什么算正确 | 常见错误 | 怎样发现与恢复 |
|---|---|---|---|---|
| 整组检查 | 同一登记文档的页面输入、来源索引和版本 | 预期页逐页出现一次，原始四角、数组结构和字词证据通过检查 | 缺页、额外页、重复页、空识别、坏坐标 | 返回页码、输入位置和错误路径；整组待修正，改正后重新提交 |
| 诊断记录 | 检查摘要、调用身份、版本与幂等键 | 当前版本与历史尝试对应，不持久化原始 OCR 文本 | 同一请求重发、同时修改、换材料沿用旧任务 | 幂等重放、事务内 CAS、材料绑定检查；新材料另建任务 |
| 历史与导出 | 工作区身份、任务及尝试编号 | 只能读本工作区；旧尝试导出不受后续修正影响 | 旧稿被覆盖、跨租户读取、最新资料缺失影响旧记录 | 服务端校验、冻结摘要；从同一已提交数据库恢复读取历史 |
| 页面交接 | 历史列表、原始输入、某次导出 | 当前版本和历史版本分开显示，切身份清除数据 | 异步旧响应覆盖新视图、写成功但读取失败被当作全流程成功 | 请求代次检查、清空旧内容；保留原始写请求和幂等键，重试不会因标题版本更新另写一条 |

## 实现与接口

`batch_input.py` 在登记清单预检后调用上一版单页入口，再检查清单是否发生变化。重复页不会任选其中一份；有效空 OCR 与结构损坏分开报告，但都不能让整组进入准备通过。没有字词定位也会保留为不足。

`batch_attempt_store.py` 使用 SQLite 事务保存任务、尝试和幂等请求。重试必须匹配当前修订号及原有材料绑定；通过后的任务不能继续覆盖。持久化字段采用明确的数据结构，只保留哈希、来源版本、计数及错误路径，不保留原始文字和词数组。哈希用于检查内部一致性，不是防管理员篡改的数字签名。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/document-preparation/examples` | 当前登记材料的合成样例 |
| GET / POST | `/api/document-preparation/tasks` | 列出／新建准备记录 |
| GET | `/api/document-preparation/tasks/{id}` | 当前状态及尝试目录 |
| POST | `/api/document-preparation/tasks/{id}/retry` | 用 `{revision, payload}` 提交修正 |
| GET | `/api/document-preparation/tasks/{id}/export?attempt_id=...` | 导出指定尝试；省略编号时导出最新尝试 |

写请求要求 `Idempotency-Key`。API 拒绝重复 JSON 键、非有限数值和过大输入，保留既有跨来源写入与身份限制，响应使用 `no-store`。全量页面输入只在请求处理期间使用；重新提交时需要调用方再次提供。

`prepared_not_indexed` 仅表示登记页集与输入结构通过。所有尝试保持 `queryable=false`、`automatic_approval=false`。纯检查器中的 `database_written=false` 指财务内容未写入；外围记录的 `attempt_metadata_persisted=true` 表示小型诊断摘要已经保存。

## 复演与结果

```bash
python scripts/replay_document_preparation.py
```

默认输出 `.run/reproductions/document-preparation-replay.json`，同名文件不会覆盖。再次运行可指定新的文件名，例如 `--output another-preparation-run.json`。脚本在独立临时数据库里复演三次尝试，重新创建 Store 后读回旧记录，并检查旧导出不变、正文标记未落入数据库和导出。任务编号和时间每次不同，业务判定与检查结果应相同。

- [一次实际复演](../artifacts/document-preparation-replay.json)：缺页 → 坐标损坏 → 准备通过，三次尝试分别保留。
- [真实浏览器验收记录](../artifacts/document-preparation-ui-verification.json)：完成三次提交、刷新后读回、历史选择、身份清理、只读限制及两次下载；下载文件与相应 HTTP 导出逐字节相同。

准备记录复演未读取原始 PDF 或整页图片，也未运行新模型。SQLite 已提交记录可以在服务对象重建后继续读取；进程中断后的后台任务抢占、自动续跑、索引提交／回滚、文档删除传播仍未实现。登记哈希没有重新对实际 PDF 字节验真。跨页表头继承、表格合并和图表解释需要另设数据与验收，不能由页集完整性检查推导。
