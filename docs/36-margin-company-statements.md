# 公司怎么解释，数字能否对上

投研人员查到一项毛利变化后，通常还会阅读管理层讨论。这两步需要接起来，但不能混成一个结论：报表可以复算出毛利率下降，公司可以解释自己认为的原因，原因是否成立还需要进一步核实。

`/margin` 在原有会计分解后增加“公司怎么解释，数字能否对上”。选择公司、载入说明后，可以查看原文章节、保留限定词的中文转述，以及对应金额、比率或变化方向的核对结果。说明单独导出，不改写原计算记录和已有审批。

## 两个容易误读的例子

微软 FY2025 的总毛利金额增加，但总毛利率下降。这不是自相矛盾：金额与比率是两个指标。微软还披露 Microsoft Cloud 毛利率为 69%；它属于特定业务范围，即使与总公司计算出的比率接近，也不能用来核对全公司数据。页面保留这条公司说明，同时指出现有分类没有对应数据。

苹果产品毛利金额增加、产品毛利率下降。公司对这两个指标给出的主要因素和抵消项不同，系统分别保存。产品、服务和总公司的毛利率按原文的一位小数核对；两个已舍入比率的差，不直接当成未舍入的精确变化。总公司比率这一条仅登记表格数值，不从产品和服务的解释拼出一个公司未说过的总归因。

## 输入、正确标准、错误与恢复

| 项目 | 本模块的约定 |
|---|---|
| 输入 | 已登记的公司说明、原文位置、范围、两期日期、来源摘要，以及同一报告版本的收入和成本计算 |
| 正确标准 | 主体、期间、报告和业务范围相符；金额增长、比率和百分点不混用；按披露精度复算；保留公司原有主要／抵消限定 |
| 常见错误 | 将 Cloud 当全公司，将金额增长当毛利率上升，忽略部分抵消，用舍入差代替精确变化，将公司解释当独立事实 |
| 发现与恢复 | 数字冲突单独显示；范围缺失停止关联；来源或父报告版本不符返回失败并要求重新载入；身份或公司切换清空旧说明，迟到响应不覆盖新页面 |

## 实现边界

核心使用结构化契约和 Decimal 算术。先重新计算关联的毛利报表，检查保存结果与输入是否一致，再核对登记说明的主体、完整期间、范围、指标类型、单位与小数位数。金额从百万美元换算为十亿美元时显式保留公式；百分比增长与百分点变化使用不同检查种类。

来源目录单独绑定原文捕获摘要和财报 PDF 摘要。实验适配层固定目录及代码版本、复算结果，并通过另一套有理数运算核对数字。只读接口必须携带当前毛利报告摘要，避免页面把后来加载的说明挂到另一版计算上。当前只支持登记字段，没有执行自由问题理解、自动 Claim Extraction 或 NLI。

“按披露精度一致”表示舍入后的数字一致。它不等于原始值精确相等，更不证明公司解释真实、完整，或已量化某项原因对毛利率的贡献。页面中的产品／服务分类也不等于微软的经营分部。

备案事件分别是2025年7月30日和10月31日；本次核对的是2026年10月26日可读取的版本，不能反推当日网页字节。说明和财务金额均来自同一公司披露，不构成两份独立证据。输入由 AI 辅助整理，尚无独立人工金标准。公开可读不等于无限再分发，仓库不保存完整 HTML、PDF 或新页图。
