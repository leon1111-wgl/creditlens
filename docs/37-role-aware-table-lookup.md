# 区分证据用途，再检查财报金额

研究员按行名和年份找金额时，需要知道失败发生在哪里：是表头不清楚，还是数字本身不可靠。上一版词级检查把所有相关文字一并检查，单位说明中一个未用于取数的低分词，也可能让金额候选停下来。

本轮保留整行与原词级方法，新增一项独立对照。行名、年份和单位继续使用整行依据；金额以及附带符号使用完整字词检查。没有采用的锚点字词问题仍保留记录，不用更高的父行分数替换金额词分数。

## 输入、正确标准与失败处理

| 环节 | 输入 | 什么算正确 | 容易怎样出错；如何发现与恢复 |
|---|---|---|---|
| 确定查询位置 | 完整已保存 WordPage、行名、年份 | 只有唯一行名、适用年份组与单位说明时继续 | 同名行或表头低分时停止，回到原页确认；不借参考框补出分区 |
| 检查金额 | 该金额行全部父行、全部原始词与符号 | 文字守恒、位置有效、分数过门槛，所有词都有明确用途 | 丢失负号、框越界、跨列、多个数字或剩余符号均保留失败依据 |
| 比较方法 | 相同六页与相同查询输入 | 原整行、原词级结果保持逐字段一致，再评分新增方法 | 输入或旧结果变动时拒绝复演，不把换材料当作规则进步 |
| 查看和导出 | 经过核验的保存报告 | 统计、具体查询、原页与导出来自同一份快照 | 换身份、实验或案例清空旧状态；原页缺失时提供官方来源，报告仍可导出 |

参考答案只在候选产生后评分。金额匹配不确认币种、完整财务期间、报表范围或业务批准；原始识别分数也不是经过校准的正确概率。

## 在工作台使用

六份保存输入的实际对照如下。这里的“匹配”要求金额与位置都符合既有参考，仍属于开发对照。

| 方法 | 符合参考 | 错取 | 依据不足 |
|---|---:|---:|---:|
| 原整行位置 | 26 | 0 | 16 |
| 原受保护词级 | 22 | 0 | 20 |
| 按证据用途 | 30 | 0 | 12 |

新版恢复微软短期债务和苹果收入两期共4条旧回退，并新增微软净利润和苹果现金两期共4条匹配，没有新增回退。剩余12条按最先遇到的问题分别为6条同名行、6条锚点整行低分；先遇到低分不说明更后的跨列问题已经解决。旧统计和逐条结果全部保留。

打开 `/table-lookup`，选择“按证据用途：三种方法对照”，点击“载入实验”。顶部保留全部登记记录；“结论或金额不同”筛选同时检查三种方法，不会漏掉只在第三种方法发生的变化。转移表可以选择整行或原词级作为起点。

选中一个行名与年份，查看每种方法的候选、问题及原始父词记录。原页按钮使用当前报告绑定的图像；没有本地原页时通过官方链接核对，不自动重新下载。导出包含全部公司和查询，不随页面筛选删减。

```powershell
python scripts/evaluate_role_table_lookup.py --verify-saved
python scripts/evaluate_role_table_lookup.py --ocr-root D:/acl-xwf/creditlens/.run/reproductions/document-ai-words --output role-table-lookup-new.json
```

保存结果核验与完整 OCR 提取复演分别记录。后一条命令需要已经保留且摘要一致的六份输入；缺失时停止，同名输出不覆盖。公开仓库仅保存必要证据和可复现结果，完整页面、OCR 与原始 PDF 不作为本轮新增发布材料。

这批微软和苹果材料已经用于开发，42 条登记记录对应 40 组独立查询输入。苹果短期与长期债务存在同页同名查询，仍保留两条参考及歧义；没有加入独立人工金标准或新公司盲测。本轮没有新增 OCR、视觉模型推理或训练。
