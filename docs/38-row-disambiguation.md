# 同名财务行：把查询意图说明白

研究员查苹果的 `Term debt` 时，资产负债表中会出现两条同名行。单凭行名和年份，系统无法知道要查哪一项。现在可以先看全部同名原行及附近文字，在原页检查它们的位置，再明确选择本次所指行。

这个操作在 `/table-lookup` 的“按证据用途：三种方法对照”中使用。选中有同名歧义的查询，点击“查看全部同名行”。页面不会默认选择第一行，也不会利用事后参考中的流动／非流动标签替使用者作选择。

## 输入与正确标准

输入是完整整行识别结果、行名、年份，以及明确给出的原行索引。索引保持原始顺序；其他同名行和干扰文字不被删除或改名。来源文件、页图、完整识别结果、查询与规则版本分别绑定，换一份输入后不能继续使用旧选择。

选择后按整行版面规则检查单位、年份表头、完整金额、列位置和识别分数。这一步没有使用词级金额重组；即使选择了某一行，低分、缺列、年份冲突和额外符号仍可能导致不足。界面保留原自动结果，辅助选择不计入旧实验的自动取数成绩。

邻近文字按几何位置选取，是回查线索，不是系统理解出来的报表分区。识别分数也不是经过校准的正确概率。币种、报表范围和完整财务期间仍需按后续事实采用规则确认。

## 常见错误与恢复

| 可能出错的地方 | 怎样发现与处理 |
|---|---|
| 未选行或把别的查询的行号带过来 | 没有默认值；缺失、越界或不属于该行名的选择会被拒绝 |
| 原行选对，但金额跨列或表头不可靠 | 继续返回取数不足，保留原文和具体原因；不能靠人工点击跳过数字检查 |
| 来源版本已经改变 | 返回冲突，重新载入当前实验与候选后再选；不覆盖旧保存报告 |
| 快速切换公司、查询或身份 | 清空旧选择、原页和导出；迟到的请求不能恢复旧结果 |
| 本机没有保留原页 | 明确显示原页不可用，使用官方来源链接核对，不自动下载 |
| 使用者选错会计范围 | 仍可回查全部同名行和上下文；系统不将点击行为视为范围正确或复核批准 |

## 保存、复跑与用途

只读接口返回保存提取结果，选择不写入业务数据库，不自动进入已有研究底稿和审批。导出包含原查询、全部同名候选、所选行、取数结果及来源版本；它是本次查询的说明，不是人工标注或审批记录。

`python scripts/evaluate_row_disambiguation.py --verify-saved` 检查保存结果和必要来源关系。完整输入重放另需已有的本地识别文件，按脚本帮助指定新输出路径，不覆盖冻结结果，也不触发新的OCR。

显式选行实验只覆盖已用开发材料中的4组不同查询、8条显式选择路径，不计算问答准确率或人工一致率。真实独立参考仍待完成。
