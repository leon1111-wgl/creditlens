# 重新核对导出的选择记录

研究员把一条财报取数结果交给同事后，同事需要知道：这份记录对应哪次查询、哪条原行，金额和来源是否仍与登记结果一致。表格取数页面现在可以重新打开“导出本次选择”得到的 JSON，逐字段核对，并单独保存检查结果。

## 输入与正确标准

输入是一份最多128 KiB的单次选择导出，以及本机仓库里通过来源检查的冻结报告。页面支持选择文件或粘贴原始JSON；选择文件时保留原字节，不先解析再重写。检查服务不保存上传文件，不访问文件中提供的网址或路径。

通过表示文件内容与某一条已登记选择逐字段相同，包括原查询、所有同名候选、所选原行、金额、页图与来源版本。数字类型也要相同，`true`、`1`和`1.0`不能互换。空格和对象键顺序可以不同；原始字节摘要与内容摘要分别记录。若其他工具重新序列化时把`792.0`写成`792`，本契约会报告类型差异，应使用保留数字类型的原始导出。

这里的可信参照是本地安装的冻结报告。摘要用于辨认本次内容，不是数字签名，不能证明是谁导出的，也不能证明收到的文件从未被替换。另一条完整合法记录同样可以通过。财务含义、会计范围、人工独立参考与复核批准仍由各自流程确认。

## 如何使用

在`/table-lookup`展开“核对已导出的选择记录”，选文件或粘贴内容，再点击“核对记录”。页面显示一致、差异或暂时无法检查；金额等上传内容不会被自动加入研究底稿。修改输入、切换身份、查询或重新选行后，旧核对结果和旧下载入口会清空。

本地命令可在没有网络的情况下使用，但需要完整的可信项目版本和冻结小型结果。它不依赖原始PDF、完整OCR或模型服务。具体参数及退出码见[CLI与控制实验说明](research/row-selection-verification-experiment.md)。

## 常见错误与恢复

| 错误 | 如何发现和恢复 |
|---|---|
| 改了金额、原行、候选或来源字段 | 列出不一致的字段位置；回查原始导出和来源，不自动修正上传值 |
| 文件引用另一版本的报告 | 说明无法与当前登记版本对应；不能据此断定文件曾被篡改 |
| JSON不完整、重复键、非有限数字或过深 | 拒绝解析，重新取得完整单次选择文件；不会把后一个重复键悄悄覆盖前一个 |
| 上传超过128 KiB | 读取到上限就停止；使用单次选择导出，不能上传整套实验或原始材料 |
| 可信报告暂不可读或来源检查失败 | 显示检查服务不可用；恢复可信版本后可用原文件重试，不将历史记录判为错误 |
| 读取文件或网络请求迟到 | 通过请求版本丢弃旧响应，新身份或新文件的结果不会被覆盖 |

接口在鉴权后读取受限流；只返回固定问题代码和可信字段位置，不回显上传的额外键名或内容。网页把JSON送到当前工作台服务检查；只有本地CLI不需要连接服务。
