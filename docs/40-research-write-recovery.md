# 保存或提交后没有收到结果，怎样继续

研究任务与解释补充底稿现在支持保存、提交、退回和复核确认的同请求重试。主要解决一种情况：服务端已完成写入，浏览器却因网络或响应异常没有收到结果。此时既不能简单认定失败，也不应再创建一个相同操作。

## 输入、验收、错误与恢复

| 项目 | 要求 |
|---|---|
| 输入 | 当前身份、研究或补充稿ID、操作、预期版本、原提交内容；复核还绑定快照摘要。页面为每次新操作生成独立幂等键 |
| 什么算正确 | 同一请求只执行一次，重试返回首次完整响应；页面另外读取服务端当前版本，不能用旧回执覆盖后续更新 |
| 常见错误 | 写入后响应丢失、回读失败、同一键被用于不同内容、过期版本、身份或租户改变、回执存储失败 |
| 怎样发现和恢复 | 结果不确定时保留原请求并显示重试入口；明确拒绝时保留草稿；版本冲突可选择放弃本页未保存改动并重新载入；回执写失败则整个事务回滚 |

## 页面操作

正常保存后，页面显示已确认的操作及当前服务端版本。连接失败、响应不是有效JSON或服务器返回5xx时，页面保留原始请求正文和幂等键，暂停编辑、切换任务和其他写入。点击“重试原操作”使用同一请求，不重新组装当前表单。

收到首次结果后仍需读取当前记录。如果其他人员已推进版本，页面展示新版本，并说明首次回执没有覆盖它。当前版本回读失败时，继续保留重试入口；列表刷新失败不会再次执行已完成的写入。

明确的4xx拒绝会解除待确认状态并保留表单。若此前出现过连接异常，本次被拒绝不证明第一次没有成功，仍应重新载入服务端版本。对未保存的表单，只有明确点击“放弃本页未保存改动并刷新”才用服务端内容替换；载入失败时原表单继续保留。

切换身份会清除当前页面的待确认请求和内容，旧身份的迟到结果不能恢复它们。请求只在页面内存中保留，关闭或刷新页面后不自动续传；这不是浏览器持久草稿或通用后台任务恢复。

## 事务与兼容性

四个已有PATCH及操作接口新增可选`Idempotency-Key`，长度8至128字符。不带键的调用沿用原CAS版本行为。带键的请求在同一SQLite事务内完成业务更新、事件、快照及回执写入，任一步失败不留下成功一半的结果。

回执按租户及幂等键索引，绑定用户、角色、实体类型、实体ID、动作及规范化完整请求。相同租户内复用键而改变任一绑定时拒绝，其他租户的键独立。回放前重新检查角色、对象访问范围及参与者自审限制；回执不是授权凭证。

回执返回首次响应，因此可能是历史版本。历史内容和事件摘要用于检查存储一致性，不能证明管理员没有同时改写全部内容。重试已提交操作不重新读取当前来源或重新批准；它只取回已经完成的事务结果。新的操作仍按原有来源、版本、角色及复核规则执行。

旧研究记录、旧快照、旧导出结构与冻结实验保持原样；此次没有新增金融事实、独立人工参考、模型训练或预测能力。数据验证与故障复演结果见[第37轮记录](iterations/2026-10-26-37.md)。
