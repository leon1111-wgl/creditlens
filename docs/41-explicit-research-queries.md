# 按公司、指标和期间查证据

研究任务中的“按范围查证据”提供三个明确入口：查一个数字、核对两期是否可比、整理一家公司经营现金流变化的依据。自由填写的研究问题仍用于说明背景；程序只执行使用者选定的公司、指标和年度。

## 怎样使用

打开 `/tasks`，建立或载入任务。先在“材料采用”确认需要参与计算的数字并保存，再切换“按范围查证据”。查数字本身不要求采用；未采用的材料会保留提示，但不能据此计算已确认的年度变化。

- 查指标：选择公司、经营现金流或固定资产现金支出、年度，查看金额、实际期间、单位、合并范围、原页与来源版本。
- 比较：明确选择前项和后项。当前计算同公司同指标的 FY2024 → FY2025 变化；不自动重排、不把相同 FY 标签当作实际期间相同，跨公司保留证据及阻断原因。
- 经营依据：选择同公司两期 CFO，分别查看会计分解、公司明示解释、待核假设与独立核实缺口。公司解释的本期金额和年度增量分别核对披露精度，金额相符不等于原因已证实。

当前材料为微软和苹果已登记的历史披露。选择未登记年度时返回“未登记”，不补零，也不推定公司没有披露。经营证据仅支持 FY2024 至 FY2025 的 CFO；固定资产现金支出不代表全部资本投入。

## 四句话验收

| 模块 | 输入 | 什么算正确 | 常见错误 | 发现与恢复 |
|---|---|---|---|---|
| 查指标 | 当前任务版本及一组公司、指标、年度 | 只返回所选证据及原文位置；未知组合不补值 | 找到别的公司、错年度、未登记当零 | 核对选择和证据身份；更换范围后重新查询 |
| 比较 | 有顺序的两项观察及采用状态 | 口径检查通过后返回原公式、输入及结果；不满足则停算 | 跨财年、跨指标、重复输入、未采用却计算 | 显示具体原因；确认正确输入并保存后重查 |
| 经营依据 | 同公司两期 CFO 与当前登记资料 | 会计分解、公司说法、假设分别呈现；保留独立核实缺口 | 把公司解释或复核批准升级为已证实原因 | 显示证据类别和来源；补充材料另走复核流程 |
| 页面与导出 | 当前选择、身份、任务版本和原响应 | 改选、编辑、身份或任务变化后清除旧结果；下载与响应一致 | 迟到响应覆盖新选择、旧结果错配材料 | 比较版本及材料绑定，失败保留清楚原因，重新载入再查 |

## 接口与数据流

`POST /api/research/tasks/{task_id}/evidence-query` 是只读查询。使用 POST 是为了传递结构化选择，不产生任务事件、回执或提交快照。查看权限按服务端身份和租户检查；当前版本不符返回 409，字段、类型和数量不合法返回 422。

```json
{
  "revision": 2,
  "task_kind": "comparable_change",
  "observations": [
    {"issuer_id": "MSFT", "metric": "cfo", "year": 2024},
    {"issuer_id": "MSFT", "metric": "cfo", "year": 2025}
  ]
}
```

后端先验证当前任务与来源，复用既有任务验收、可比性和公司说明核对，再按显式选择投影结果。结果包含选择摘要、任务版本、材料摘要、所选观察、来源绑定、公式和缺口；`Decimal` 计算沿用既有规则，不执行文档中的指令或任意生成代码。完整字段见[接口契约](research/research-query-contract.md)。

前端保留服务端原始响应。下载前重新核对任务、版本、材料和选择；查询中的改选或编辑使该次响应失效。写入结果未确认时暂停查询，待恢复当前记录后再操作。来源摘要用于检查绑定和变化，不能证明报告真实。

## 可复现验证与边界

固定案例及其请求、结果见[实验报告](../artifacts/research-query-report.json)，覆盖情况见[案例说明](research/research-query-cases.md)。运行：

```bash
python -m unittest tests.test_research_query tests.test_research_query_api tests.test_research_query_experiment
python scripts/evaluate_research_queries.py --verify-saved
node scripts/check_research_query_ui.js
```

这验证的是结构化范围选择、既有证据投影和失败行为，不是自然语言理解或问答准确率。固定案例包含明确标注的合成请求和模拟采用意见；尚无独立人工 gold、未用于开发的新公司评测、历史时点查询或因果验证。旧任务、审批和冻结报告保持原样；新的只读补充不会继承旧审批。
