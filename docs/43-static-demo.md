# 静态演示

[在线演示](https://leon1111-wgl.github.io/creditlens/)是 GitHub Pages 上的静态页面，只回放仓库中已经保存的结果。它用于浏览工作台，不代表完整服务；保存、提交和复核需要按 [README](../README.md#本地运行) 在本地运行。

## 包含的页面

| 页面 | 静态演示中的内容 |
|---|---|
| 介绍页 | 放大镜沿保存的识别片段移动，读出取值、页码、定位框和单位原文 |
| 表格取数 | 三项保存的取数实验、单位适用性检查、同名行候选与选择结果 |
| 毛利率变化 | 登记的毛利率分解与公司说明核对 |
| 季度研究 | 预设截止日及各公告日前后的微软 FY2025 季度快照 |
| 研究任务 | 三个登记的模拟业务场景及其快照、任务检查、公司解释和预设范围查询 |
| 文档实验 | 保存的 CPU OCR 方法对照与图像退化结果 |

信用复核、解释补充底稿、参考核对、原页核对、跨页证据、新公司核对、材料准备和 FinQA 实验室只在本地服务中提供，导航中标为“本地”。

## 怎样录制

`scripts/export_static_demo.py` 在进程内启动 FastAPI 服务，使用演示身份和临时状态目录，不运行 OCR、模型或网络请求：

1. 读取页面需要的 GET 响应，按演示身份分别核对；三种身份返回相同内容时只保存一份。
2. 研究任务使用 `data/demo/research-scenarios.json` 中三个明确标注为模拟的业务场景，通过 `ResearchTaskStore` 的创建、更新、提交、复核接口回放；财务数字来自登记的官方材料，不新增数值。
3. “按范围查证据”是只读查询，录制两家公司 × 两项指标 × FY2024/FY2025 的全部组合。
4. 响应以内容摘要命名保存在 `data/`，`data/manifest.json` 记录请求与文件的对应关系、应用版本和源提交。

GitHub Actions（`.github/workflows/pages.yml`）在 main 上的测试工作流通过后，按同一提交重新录制，再用 `scripts/check_static_demo.js` 检查（拉取请求也会运行录制与检查，但不部署）：每条录制都要按页面的请求方式经由回放脚本取回，写入必须被拒绝，页面不能残留服务器路径，也不能发布图片或 PDF。

```bash
python scripts/export_static_demo.py --output site
node scripts/check_static_demo.js site
python -m http.server 8000 --directory site
```

## 原页预览

官方 PDF、整页 OCR 和页面渲染不随仓库分发，静态演示也不发布这些图像。预览改为“重建示意”：把仓库中已保存的识别片段按原坐标绘制在空白页上，图中注明不是原页图像；金额、年份和行名的框线仍由页面按保存的定位记录绘制。核对原文请打开官方文件对应页码。

## 写入与未录制的请求

- 保存、提交、复核、新建任务和上传核对在浏览器内被拒绝，不发送到任何服务器；页面草稿只留在当前标签页的内存中。
- 未录制的读取（例如任意研究截止日或其他年度）不会成功：页面沿用自身的错误文字，同时出现一条需要手动关闭的说明，提示改用本地服务。
- 页面顶部始终显示“静态演示”提示。导出按钮在浏览器内生成文件，内容与录制结果一致。

录制内容与本地服务使用同一份保存结果和规则，但静态页面不能证明服务端鉴权、并发写入或恢复流程；这些仍以测试和本地运行为准。
