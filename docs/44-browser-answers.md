# 页内问证据

访客在[问证据](https://leon1111-wgl.github.io/creditlens/ask.html)页输入一个关于微软、苹果 FY2025 年报的问题，浏览器内的规则引擎把问题读成公司、指标、财年、单位与口径，再按登记的数字作答。每个说出的数字都附读数：**数值 · 页码 · 定位框 · 单位 · 核对结果**。不需要服务器、密钥或模型，也不是录制回放。没有登记或读不懂的部分会说明缺什么，不用相近的数字代替。

## 能回答什么

| 类型 | 例子 | 做法 |
|---|---|---|
| 查数 | 苹果 FY2025 服务毛利率；微软 FY2025 营业收入是多少亿美元 | 返回登记值与读数；美元量级按要求精确换算，原值并列 |
| 两期变化 | 苹果 FY2024 到 FY2025 经营现金流变化了多少 | 先过可比性检查（同公司、同报表行、同来源与单位、口径依据、相邻不重叠财年、同历法与长度），再给差额与变动率及公式 |
| 是否可比 | 微软和苹果 FY2025 的经营现金流能直接比吗 | 同公司两期给出检查结果；跨公司只并列，列出不可比的原因 |
| 排名或跨公司差额 | 谁的净利润更高；微软收入比苹果多多少 | 不排名、不相减，说明原因，只并列两家的登记值 |

登记范围：两份 FY2025 10-K 中 FY2024、FY2025 的合并报表行，共 66 个年度数字（营业收入、产品与服务收入、营业成本及分类成本、毛利、净利润、经营现金流、固定资产购建现金流出、三类债务、流动资产、流动负债、现金类项目）和 12 个毛利率登记计算。资产负债表项是财年末余额，利润表与现金流项是整个财年的发生额。完整清单在页面“能回答什么、不能回答什么”中。

会明确拒答并说明原因：其他公司、子公司、分部、产品线和地区；母公司报表；季度、半年、月度、滚动 12 个月和自然年；与财年末不符的日期；未登记的指标（营业利润、EPS、总资产、自由现金流、比率等）；人民币等其他币种；指标之间的差额或比值；无法对应财年的相对时间（今年、去年）。

## 怎样读问题

`web/src/understand.ts` 用封闭词表读问题：每一段文字都必须是公司名、登记指标、财年或日期、单位、口径词、意图词或列出的虚词。读不懂的字会被指出，整句不作答。会改变含义的词（其他公司、分部、母公司、季度、自然年、未登记指标、其他币种、排名）单独识别，并给出拒答理由。

- 歧义词不猜：“利润”“债务”“现金”（微软）会请访客指明；“现金”对苹果按“现金及现金等价物”理解并写明。
- “产品/服务”与收入、成本或毛利率连用时组成分类指标；不能组成时请访客说明，不会悄悄丢掉。
- “赚了”“卖了”这类动词短语只在没有点名指标时代表净利润或收入。
- 错字修复只做一处或两处单字修正，修正后的词必须是唯一可读的公司或指标名，且不能改动已读懂的词的含义；每次修复都在答案上方写明。
- 规则不判断“对不对”：问题里带数字（例如“是不是 2817 亿”）会被拒答，不做核对式问答。

## 答案与读数

`web/src/compose.ts` 生成答案卡。标题中的每个数字必须是某条读数的登记值、该值的精确量级换算、列出公式的派生值，或同一读数中的年份、日期、页码与天数，`compose.test.ts` 逐条检查。

- **数值**：报表原文（含括号负值）与单位；有要求的量级时并列换算值。
- **页码与定位框**：PDF 物理页（苹果另注印刷页）与 PDF 点坐标。
- **单位**：印刷单位表头原文；单位规则适用时注明。
- **核对**：已保存 OCR 的结果。`role_layout` 读到同值记为一致；未选出时写明原因（同名行、锚点置信度低），数值以登记事实为准；毛利率分解的分类金额来自 OCR 片段与 AI 辅助转写，未经独立人工确认，照实标注。
- **重建示意**：按仓库保存的识别片段绘制该页，黄框为登记定位、虚线为 OCR 片段，不是原页图像，也不发布页面图片。

## 与 Python 后端一致

`creditlens/evidence_answers.py` 接收显式计划（公司、指标、财年、类型、量级、口径），不读问题文字。两期发生额复用 `research_materials._annual_change`，余额使用同形状的时点规则，跨公司复用研究材料的并列规则。`scripts/build_browser_pack.py` 生成 `creditlens/ask-pack.json`（CI 用 `--check` 防止过期），`web/src/answer.ts` 与 `rules.ts` 是逐项移植：

```bash
python scripts/build_browser_pack.py --check
python scripts/export_answer_parity.py          # 生成 web/tests/fixtures/parity.json（不入库）
cd web && pnpm install --frozen-lockfile && pnpm typecheck && pnpm test && pnpm build
```

`parity.test.ts` 比较 14,247 个导出计划的完整答案和 572 组扰动后的可比性规则输入，必须逐字段相同。本地服务的 `/ask` 使用同一份打包脚本 `creditlens/ask.js`，不需要 Node。

## 写入

本页只读：不保存问题，不写入研究任务、采用决定或复核记录。两期变化是描述性计算，答案写明“未经分析员采用，不写入研究底稿”。研究任务等页面的写入在静态演示中仍按原规则拒绝；页内“模拟”写入本轮没有实现。

## 评测

所有题目都是 SYNTHETIC；登记数字来自官方年报。下面的数字衡量的是“把问题读成正确的计划并据此作答或拒答”，不是模型能力，也不是独立人工金标准。

| 测量 | 对象 | 结果 |
|---|---|---|
| **盲测首轮**（在 `a05f450` 运行） | 146 题，另一个模型（Sonnet）只按 [BLIND_SCOPE.md](../tests/browser_answers/BLIND_SCOPE.md) 写成，`7d51612` 提交、未经开发者阅读；评分规则 `f6431f1` 先于运行提交 | 正确 114、错答 2、弃答 30；应拒答的 58 题全部拒答；可答 88 题中正确 56、错答 2、弃答 30；RS(0) 0.7808，RS(10) 0.6438 |
| 同一题集修复后重跑（**已看过，非盲测**） | 同上 | 正确 145、错答 0、弃答 1 |
| Python ⇄ TypeScript 一致性 | 14,247 个计划与 572 组扰动规则输入 | 全部一致 |
| 覆盖集（开发者编写） | 每个登记指标两种说法（书面、口语），各类问题与陷阱，111 题 | 全部通过 |
| 开发者自测（开发者编写） | 46 个新说法，针对错数字 | 发现 3 类错误并修复，作为回归保留 |

首轮的两次错答都把读懂的问题答偏了：bl-004 “硬件产品那块一共卖了多少钱”丢掉了分类词，给出了总营收；bl-014 “毛利润赚了多少”把“赚了”当成第二个指标，多给了净利润。30 次弃答都是词表缺口（如“总销售成本”“PP&E”“非流动的定期债务”、英文所有格、错字）。修复按类别进行，并为每类加了对照用例（`web/tests/reader.test.ts`）；修复之后的结果不再是盲测数字。首轮完整记录在 [blind-first-run-a05f450.json](validation/blind-first-run-a05f450.json)。

评分方式见 `web/tests/blind.ts`：说出的（公司、指标、财年）集合、问题类型与要求的量级都要与题目一致才算正确，说了数字但任一项不符即为错答；应拒答的题只要没有说出数字即为正确，排名题只允许“不排名、只并列”。评分器比较的是计划与状态，答案文字由 `compose.test.ts` 另行约束。

## 已知缺口

- 封闭词表之外的说法会弃答，开发者自测之外仍会有未覆盖的口语和行业用语；弃答不会给出数字，但会让访客改写问题。
- 不支持指标之间的派生计算（营运资本、自由现金流、净债务、比率）和跨公司差额，这是有意的范围限制。
- 修复之后没有新的盲测；新的测量需要另一套未看过的题。
- 只在本地生产构建和 Node 测试中验证，未在真实手机上验证。
