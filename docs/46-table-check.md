# 截图核对：浏览器内 OCR 读表与加总核对

v0.35.0 的候选功能。访客粘贴或上传一张表格截图，浏览器内的 OCR 把每个数字框出来，再按读出的数字做确定性的加总核对：上方各行之和是否等于“合计”行、小计是否成立、同比变动是否与两列相符。对不上的行连同算式一起标出。

页面从不给出“正确值”。它只说三件事：读到了什么、在哪里读到、哪些核对没有通过。核对没有通过可能是表本身不平，也可能是 OCR 读错或表格结构认错，页面把这三种可能并列写明。

## 评测协议

本节在任何评测运行之前提交，之后不改；结果另写在下文“结果”一节。

### 引擎（`configs/table-check.json`，`table-check-1`）

- **OCR**：PP-OCRv5 mobile 检测与识别（PaddlePaddle，Apache-2.0）的 ONNX 版本，取自 Hugging Face `webnn/PP-OCRv5-ONNX` 固定修订 `006b441`，合计约 21.3 MB；字典 18,383 字。
- **运行时**：onnxruntime-web 1.30.0（MIT），从 jsDelivr 按版本取，约 14.3 MB。浏览器内 WebAssembly SIMD、单线程；不用 WebGPU。
- **下载前点击**：模型与运行时只在访客点击“加载识别模型”后下载，按钮上写明合计约 35.6 MB。每个文件下载后核对 SHA-256，不符即拒绝运行。
- **不能运行时隐藏**：浏览器不支持 WebAssembly SIMD 时，不显示上传和加载控件，只说明原因。
- **表格结构**只从 OCR 框和文字重建：按垂直位置分行，按数字右边缘分列，年份表头、行名和缩进也只从框读出。不使用 HTML、XBRL 或任何参考值。

### 核对规则（确定性，读数之后才运行）

- **合计行**：行名以 Total / 合计 / 总计 / 小计 开头的行。在同一列向上逐行累加：遇到另一条合计行时把它作为一项并跳过它所汇总的行；行名以 Less / 减 开头的行取相反数；纯文字行（标题）不计入。累加过程中任一前缀之和在容差内等于合计值，即“相符”，记下所用各行；没有任何前缀相符，即“不相符”。
- **横向合计**：表头中有 Total / 合计 列时，同一行其余数字列之和与合计列比较。
- **同比变动**：表头中有 Change / % Change / 增减 / 变动 列，且左侧恰有两列年份时，按读数重算差额或百分比（按印刷的小数位四舍五入）。
- **容差**：每个参与项和合计各允许半个末位单位的四舍五入误差。
- **不核对**：所需的格读不出完整数字、列对不齐或项数少于 2 时，记为“未核对”，并写明原因。未核对不算相符，也不算不相符。

### 数据

- **开发集**：苹果、微软的报表页（XBRL 对照开发运行 42712316145 的产物，干净渲染），在页面里转成与发布页相同的灰度 WEBP（质量 0.68）；另加合成表格。开发期间可以反复查看。
- **测试集**：XBRL 对照保留集首轮（运行 42712945764）已发布的 21 张报表页（`creditlens/grounding/*.webp`，哈希见 `index.json`）及其已发布的标签框。冻结提交之后只运行一次；冻结之前，本引擎不在这些页面上运行。
- **变体**（标注 SYNTHETIC）：同一批测试页由浏览器 canvas 重新编码为 JPEG 质量 0.60，和经 `blur(1px)` 滤镜模糊后的版本。只报告，不参与上线门槛。

### 指标

- **格值准确率**：分母是测试页上位于表格单元格内的数字标签（排除行名内数字 `in_text_cell` 和文本块内标签；破折号表示零的标签单列）。被标签框选中的引擎数字格（覆盖框 35% 以上或格中心落在框内，与项目 visual-evidence-1 相同）恰有一个、数位与括号符号都与印刷文字相同，为“正确”；有格但数位或符号不同，为“读错”；没有格，为“漏读”。破折号标签读成破折号格为正确。
- **读错率** = 读错 ÷ 分母。
- **核对误报率**：测试页是发行人已审计报表的干净渲染，按印刷数字应当相符。干净变体上每一条“不相符”都计为误报；误报率 = 不相符 ÷（相符 + 不相符）。另按答案键把误报分为“读数造成”（同一算式用标签值相符）与“结构造成”（标签值也不相符，说明算式认错）。
- **耗时**：GitHub Actions ubuntu-latest（4 vCPU）上的 Playwright Chromium，单线程 WASM；每页从图像解码到核对完成的时间，不含下载；另报模型初始化时间与下载字节数。

### 上线门槛（测试集、干净变体、首轮）

| 项 | 门槛 |
|---|---|
| 格值准确率 | ≥ 90% |
| 读错率 | ≤ 1.0% |
| 实际完成的加总核对 | ≥ 40 条 |
| 核对误报率 | ≤ 5% |
| 每页耗时 P95 | ≤ 30 s |
| 模型初始化 | ≤ 15 s |
| 下载合计 | ≤ 40 MB |

全部满足才上线：页面进入“证据”导航和静态演示。任一不满足，页面不进入导航和导出，只在本文报告结果。JPEG 与模糊变体只报告。

### 运行在哪里

- 所有真实 OCR 都在 GitHub Actions 的 Playwright 作业里运行，不在开发机上运行，包括开发机上的浏览器。
- 本地与 CI 的单元测试只测确定性部分（金额语法、分行分列、核对规则），用构造的框，不加载模型。
