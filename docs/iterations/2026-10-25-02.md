# 第 2 轮：先拦住会改变财务判断的错误

日期：2026-10-25。版本：v0.2.1。计算规则：cash-debt-review-2。

## 谁需要，为什么这轮先做这个

目标仍是企业信用分析员与复核员。他们不仅需要算出一个数，还需要知道这个数什么时候不该算。检查上一版实现时发现：负经营现金流乘以 80%，会变得没那么负，导致“下降 20%”情景反而改善结果；同一指标有两个冲突数值时，公式虽已阻断，同比表仍可能展示两行结果。这些问题会直接影响底稿解释，优先于增加新模型或新页面。

本轮沿用 2026-10-25 [第 1 轮报告](2026-10-25-01.md) 已核验的 HSBC、JPMorgan 岗位及 AlphaSense、FinRobot、RAGFlow 官方资料，没有新招聘抓取、客户访谈或竞品实测。岗位中的验证、可靠服务和工程交付要求，支持我们把这次工作用于展示可复现的错误发现与修复能力。商业产品具备来源引用，并不能说明本项目更强；我们能证明的贡献是公开规则、明确失败条件和可运行的检查。

[广东文件与 OECD 报告的既有调研](../08-document-ai-and-governance.md) 提出了模型、数据及人工监督问题。本轮将其中“验证与版本治理”落实为程序行为，不声称通过监管认证。文档智能以后提取出的数值，也必须先通过这些检查再进入信用复核。

## 具体怎么改

| 原来的风险 | 现在的处理 | 对使用者的含义 |
|---|---|---|
| 负现金流乘以折扣后反而改善 | 百分比下降情景只接受正经营现金流；零值或负值阻断该指标 | 需要重新定义适用于现金流缺口的情景，不能沿用同一公式 |
| 当前指标冲突仍进入同比表 | 只有唯一可用的当前值与唯一可比的前期值才能进入比较 | 不展示来源尚未确认的增长率 |
| 导入 value 与 raw_value 不一致 | 按明确数值语法解析原始显示值，再与归一值精确核对 | 数字抄错、千位分隔错位会在导入时被拒绝 |
| 把亏损取绝对值当成正利润 | 绝对值现金支出转换仅允许用于 capex | 不能通过归一化抹掉利润符号 |
| 更新规则后继续确认旧版结果 | 保留旧快照、事件和导出；旧规则案件的修改与复核返回 409 | 先核对材料并按新规则重新建案，不悄悄改写历史 |

原始显示值检查支持千位逗号、小数、显式符号和括号负数；含糊的 OCR、百分号、科学记数法或双重符号拒绝导入。它只检查事实包内部一致性。上传者如果同时改动原始值和归一值，仍可能骗过一致性检查，所以必须继续核对官网或原页，不能把本功能称为真实性鉴定。

工作台增加旧规则提示、停止旧案写入按钮，并解释情景为何未计算。服务器对同一限制独立检查；禁用按钮不是权限边界。

## 怎样证明改动确实有效

新增 [控制场景脚本](../../scripts/evaluate_controls.py)。输入是一份官方微软事实包及 14 份人为修改的副本，分别覆盖缺失、币种、期间、未来披露、重复冲突、负值、原始值不一致和错误来源等情况。所有修改副本都明确标记为 synthetic_counterfactual，官方样本与原始网页没有被修改。

- 修复前在本地提交 03d55b4 的实现上运行：15 项中 9 项通过、6 项失败。[原始运行记录](../../artifacts/financial-controls-before.json)
- 修复后：相同 15 个检查全部通过。[运行记录](../../artifacts/financial-controls.json)
- 56 项 unittest 通过，新增原始数值解析、情景边界、冲突比较和规则升级检查。15 个场景已包含在测试中，不能把两组数量相加当作独立样本量。
- 官方基准算式保持不变：简化自由现金流 71,611，20% 情景 44,378.6，单位均为百万美元。模拟完整流程仍为 5 个事件，事件链与快照校验一致；5 个观察因子导出正常。
- 本机服务已重启到 0.2.1。通过真实 HTTP 验证：旧案可读、可导出，写入返回 409 且事件未变；新建官方案例使用规则 2，计算值及事件校验正常。
- JavaScript 语法和文档链接检查通过。本轮没有重跑浏览器交互与视觉验收，README 截图仍来自 v0.2。

15/15 是预先指定的程序控制场景通过数，**不是模型准确率、真实企业错误检出率或金融业务效果**。没有运行 LLM，没有训练，也没有新增预测标签。CI 配置新增控制场景命令，远端 CI 尚未运行。

复现：从仓库根目录执行 `python scripts/evaluate_controls.py` 与 `python -m unittest discover -s tests -v`。前后记录保留输入哈希、场景预期和实际结果；拒绝导入与阻断计算分别记录，不混成一个模型拒答成绩。

## 局限与下一步

当前仍只有一家公司的少量官方事实和人工构造的失败情况，不能据此推断真实文档上的覆盖率。没有通用 PDF/扫描件解析、自动更正公告关联、独立外部审计日志或生产部署验收。旧案需要手动重新建案，原案与新案之间尚无自动关联。

下一轮优先准备带页码、表头和金额定位的权威金融文档小样本，将真实解析错误接入同一套验证，并单独报告误拒绝与漏检。待数据、冻结评测和训练脚本齐备再提出 A100 40GB 试跑方案；本轮无需 GPU，未调用收费服务。

发布状态：目标公开仓库已存在，但连接器写入权限问题仍在，本机只检测到旧账号的 Git 凭据。源代码继续保存在本地，未绕过登录、未再次发起无人处理的登录流程，也未宣称已经推送到 GitHub。
