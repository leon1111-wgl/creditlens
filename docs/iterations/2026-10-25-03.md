# 第 3 轮：让财务数字指向 PDF 原页

日期：2026-10-25。版本：v0.3.0。财务计算规则仍为 cash-debt-review-2；本轮新增文档定位，没有改变公式。

## 这轮解决什么企业问题

信用分析员看到一个现金流或债务数字后，复核员通常还要打开原始材料，确认它属于哪一行、哪一年、什么数量单位。只有官网首页链接不够；如果来源是长 PDF，逐页寻找会增加核查步骤。本轮把页码、金额位置、行标签、年份及单位表头保存到事实中，再带入现有案件和底稿。

这是一项待真人试用验证的效率假设，目前没有客户访谈、核查耗时或节省比例数据。目标用户仍是企业信用分析员和复核员，功能服务现金流及债务复核，没有扩成通用金融平台。

招聘与竞品复核沿用 2026-10-25 [第 1 轮调研](2026-10-25-01.md)：HSBC、JPMorgan 岗位中的数据处理、评测和工程交付，与用户提供的金融文档/风险因子岗位相符。AlphaSense、FinRobot、RAGFlow 已覆盖研究、Agent 或文档检索；本项目的可展示贡献是数值位置、口径校验和人工复核在同一条流程中可重跑。没有新增市场排名、竞品性能对比或采购意愿结论。

## 这次用的是什么材料

从 [微软官方 filing 页面](https://microsoft.gcs-web.com/node/33951) 找到 FY2025 10-K，披露日期为 2025-07-30；下载其 [官方 PDF](https://microsoft.gcs-web.com/static-files/9640e86d-a99f-4502-934d-1d3c883fa786)。文件共 158 页，使用第 50、52、53 页的利润表、资产负债表和现金流量表。它们与现有官网财务表属于同一发行人、同一报告期。

源文件 SHA-256 为 `1d13a76168650bb5efb42f29c6da81aa673e44217d082357ec0815afc70abf2e`。下载时间、filing 元数据链接、解析器版本、选页及标签配置、坐标约定、使用限制均进入 [来源登记](../../data/examples/msft-pdf-provenance.json)。完整 PDF 和渲染页留在本地，不随公开仓库分发。

披露日期说明财务信息的披露时间，不能证明今天下载的这份 PDF 在 2025 年当天已有相同字节。FY2024 比较数也属于 FY2025 文件的信息集，不能倒填到 2024 年。

## 程序如何工作

1. 先核对原文件哈希，文件改变就停止，不沿用旧版页码和标签配置。
2. 用 PDFium 读取数字 PDF 的文字及字形坐标，按财务表标题、单位、期间表头、年份列和行标签定位。
3. 金额必须落在对应年份列下；缺单位、缺金额、年份重复、行标签重复或列错位时拒绝该次解析。扫描件没有文字层也不会被猜成零。
4. 保留括号负数。资本开支按既有规则转为正现金支出，其他指标不擅自取绝对值。
5. PDF 提取完成后才读取 HTML 参考包，对照 20 个指标/年份组合的数值、单位、期间和转换。解析器没有把参考答案当作金额搜索词，也不会用参考值修补 PDF 输出。
6. 将带定位的事实包接入原有建案、计算、核查和独立复核流程。工作台可展开坐标，并提供原始 PDF 的页码链接；底稿导出保留定位信息。

位置使用页面左上角为原点的 PDF point，金额、行标签、年份、期间和单位各有独立框。普通 HTML 事实不新增空字段，旧数据包的序列化哈希保持一致，避免破坏既有幂等请求。

方法参考 [PDFium Python API](https://pypdfium2.readthedocs.io/en/stable/python_api.html)。采用固定版本 `pypdfium2==5.14.0`。初次尝试 pdfplumber 的读取在本轮等待期间未完成，已终止该进程；未形成可比较的运行时测量，不据此宣布哪个解析器更快。PDFium 的读取和渲染已实际运行。

## 实际验证结果

- 三页中选取的 20 项事实全部与官方 HTML 包一致。[逐项结果](../../artifacts/pdf-crosscheck.json) 记录 PDF 值、参考值和页码。它是同一公司的跨格式一致性检查，**不是独立真实性验证、通用 PDF 准确率或模型成绩**。
- 已渲染并检查三页叠加定位框，确认所选金额、行标签、年份及单位在对应可见位置。尚无双人独立标注或 bbox 精度基准。
- 70 项 unittest 通过，新增 14 项：位置与符号、缺失/重复/错位拒绝、越界坐标、年份冲突、文件哈希变化、跨格式不一致、旧包哈希兼容及新接口权限。人工构造的测试与真实披露检查分别报告。
- 本机服务已运行 v0.3.0，HTTP 验证 PDF 案件含 20 个定位、事件链有效，导出底稿包含原页信息。[实际草稿底稿](../../artifacts/pdf-review-memo.md)
- 浏览器已在窄屏（可见内容宽 482px）创建 PDF 案件并展开坐标，在 1280px 桌面检查证据台账、坐标展示与链接目标。[界面截图](../images/pdf-evidence-workbench.png) 原站 PDF 是否自动滚动到锚定页取决于查看器，本轮未验证该交互。
- JavaScript 语法、文档链接与 Python 编译检查通过。核心依赖即可运行工作台和测试；只有重新解析/渲染 PDF 时才需安装 `requirements-pdf.lock`。远端 CI 仍未运行。

复现命令：

```bash
python -m pip install -r requirements.lock -r requirements-pdf.lock
python scripts/build_pdf_pack.py --download --render-dir .run/pdf-preview
python -m unittest discover -s tests -v
```

已缓存文件会先核对哈希，不重复下载。网页或 PDF 内容变化时需要人工核验后调整登记；脚本不会自动信任新版本。

## 还没做到什么

这是固定文件、三页、十个行标签的数字 PDF 适配器。未实现通用表格发现、扫描 OCR、视觉语言模型、图表理解、跨页续表、中文财报适配和更正公告关系。单位表头提供数量级，美元币种依据本发行人的报表口径配置；不能从任意 `$` 符号推断币种。

合法坐标、相同数字和哈希都不能证明财报真实。用户导入的定位仍需核对原页，界面不会将其提升为官方解析结果。当前来源核对仍依赖固定官方材料和人工检查。

下一轮先加入第二家企业及不同版式的标注样本，把固定版式失败记录成可比较的解析任务，再决定是否引入 Docling/MinerU、OCR 或视觉模型。先扩数据和失败覆盖，不用这 20 个一致结果决定租卡。没有训练、预测或付费调用。
