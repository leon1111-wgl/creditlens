# 第 4 轮：第二家公司暴露的口径与版式问题

日期：2026-10-25。版本：v0.4.0。计算规则升级为 `cash-debt-review-3`。

## 为什么做这一轮

企业信用分析员处理的报告不会都长得像微软财报。如果只在一家公司上演示成功，无法说明换一种版式时程序会正确处理还是悄悄取错。本轮选择苹果 FY2025 年报，沿用现金流、短债覆盖与独立复核任务，检查三个容易影响判断的细节：分行且居中的日期表头、重复但期限不同的行名，以及没有现成合计行的流动资金。

岗位和竞品证据沿用 2026-10-25 [第 1 轮调研](2026-10-25-01.md) 的 HSBC、JPMorgan 官方岗位与 AlphaSense、FinRobot、RAGFlow 官方资料。数据处理、评测、可靠服务与可复核结果仍是本轮交付主线。本轮没有新增招聘统计或竞品性能测试；“减少跨公司核查错误和寻找原文时间”是待真人验证的业务假设，没有客户访谈或效率百分比。

下载的 PDF SHA-256 为 `3eb270b22acb7d8d8e9c32a43dc221dec3345f8e4bca02755fdbc1ee16c823de`。本机直接请求 SEC HTML 返回 403，未绕过限制；参照 [发行人 filing HTML 发布副本](https://d18rn0p25nwr6d.cloudfront.net/CIK-0000320193/c636d8a7-8025-47d2-9b13-bcf5465343b3.html) 的财务表，记录了参考数值及文件哈希，并检查 PDF 可见原页。参考值在运行新解析器之前保存，解析器不读取答案来定位金额。

## 发现了什么，怎样修正

**日期表头不能套用微软模板。** 原有“同一行年份、金额右对齐”适配器在苹果三张表全部拒绝，具体原因保存在 [逐项核对记录](../../artifacts/aapl-pdf-crosscheck.json)。这是已知版式不适用的失败记录，不是旧模型准确率为零。新适配器核对月份、日、年份及顺序，再按年份中心划定列区间；金额跨列、缺表头或缺单位就停止。

**同名行必须保留所在分区。** “Term debt” 同时存在于流动与非流动负债，“Marketable securities” 同时存在于流动与非流动资产。程序用明确的分区起点和终点约束行定位，将分区标题和坐标一起保存。没有分区时遇到重复行名不会默认选第一行。工作台和底稿都能看出该数值来自哪个期限分区。

**算出的合计不能伪装成原文数字。** 苹果没有直接对应本项目流动资金口径的合计行，因此保留现金及现金等价物、流动有价证券两个事实，短债覆盖率使用四项原始证据：

```text
(35,934 + 18,763) / (7,979 + 12,350) = 约 2.6906
（现金及等价物 + 流动有价证券）/（商业票据 + 流动部分定期债务）
```

以上金额单位均为百万美元。77,723 的非流动证券与 78,328 的非流动定期债务没有混入这个公式。合计和分项同时提供时不擅自择优；分项缺失、重复、单位不同或时点不同会阻断。可用现金、担保和租赁范围仍需额外核查。

**财年不总是相隔 365 天。** 苹果两个所选年度都是 52 周。事实包显式声明周历财年后，程序允许相隔 364／371 天的年度期末；现金流等期间指标还必须有符合 52／53 周的完整期间且两期长度相当。不同周数的流量不直接给出未经调整的同比。没有声明时不擅自推断。FY2024 数值仍是 FY2025 披露中的比较数，不倒填到 2024 年的信息集。

规则含义变化，因此升级计算规则并冻结旧案写入。原有 v2 案件仍可读、可导出，原事件和快照保持不变。新字段为空时不写入旧事实包序列化，原有幂等哈希兼容检查继续通过。

## 实测到了哪一步

- 苹果 22 项原始事实的数值、单位、期间、原始符号及转换与登记参考全部一致；三个带定位框的原页已逐页查看。加上微软样例，目前是两家公司、六个固定页面、42 项不同的指标／年份事实。不能将这个开发样例结果称为通用解析准确率。
- 86 项 unittest 通过，新增 16 项测试，覆盖分行表头、重复行的分区、错误日期与列位置、分项计算、财年、截止日期、新入口权限、幂等、租户与完整模拟复核。原来的 15 个财务控制场景包含在测试内，没有重复计作独立评测样本。首次运行有一项测试把既有业务校验状态码误写成 409；按接口的 422 契约修正测试后通过，未为测试放宽业务规则。
- 桌面浏览器完成苹果建案、两项核查、提交、切换独立模拟身份并确认，产生 5 个事件、版本 5。HTTP 检查事件链有效、22 项原页定位和底稿的分区／公式引用；[验收记录](../../artifacts/multi-issuer-http.json) 与 [实际底稿](../../artifacts/apple-review-memo.md) 已保存。这不是银行用户验收。
- 1280px 桌面与 497px 窄屏检查了案例入口、财年数据和证据台账。选择案例会更新未手动改动的建议截止日；手动截止日经浏览器验证保留。没有再次验证原站 PDF 查看器是否自动跳页。
- 浏览器发现 0.9953 的现金转化率被两位小数显示为 1，已把比例展示精度提高到四位小数。内部 Decimal 计算和导出保留完整计算值；界面仍是四舍五入展示。
- JavaScript 语法、Python 编译和本地文档链接检查通过。[苹果因子快照](../../artifacts/apple-factor-snapshot.json) 导出 5 个观察因子，没有预测标签；压力情景未混入观察因子。

## 下一步与限制

目前仍是两个固定哈希、预先选择页面和行标签的适配器，没有通用表格发现、OCR、图表理解或视觉模型。两个开发样例既不能证实研究假设 H1，也不能支撑预测训练。下一步把页面／表格任务与失败分类固定为小型评测清单，加入尚未适配的中文或不同产业报告作为保留样本，再做同页、同任务的通用解析器对照，避免靠不断手写适配器宣称泛化。

当前继续使用 CPU；没有租卡、付费 API、训练或投资收益实验。Git 凭据清单仍只有旧账号，未重复发起无人处理的登录；GitHub 发布和远端 CI 未完成。本轮代码、数据契约、报告及主页文案先保存在本地。
