# 第 6 轮：把时序和因子研究接到财报核查之后

日期：2026-10-25（北京时间）。用户要求在简介里加入时序与金融因子，并依据前沿、已正式发表的研究。本轮交付是文献核验、研究计划和主页更新，版本仍为 v0.4.0，没有新增预测程序或实验成绩。

## 为什么加入

看完一份财报后，信用分析员还要看多期变化、判断哪些线索值得继续追查。现有指标与原文定位提供基础；历史序列和经过验证的因子可以沿着这条线扩展，具体价值仍待验证。

岗位和竞品定位沿用同日 [第 1 轮调研](2026-10-25-01.md)，继续聚焦数据处理、模型评测与可复核工程。本轮新增 TimesFM、Time-MoE 与 AlphaForge 的正式论文和作者仓库对照，没有新招聘统计或客户访谈。它们分别提供预测或因子研究方法，不能直接当作已经满足本项目的企业工作流。

## 查到了什么

核验 ICML 2024 的 TimesFM、ICLR 2025 的 Time-MoE、AAAI 2025 的 AlphaForge、ICLR 2026 的时序异常检测研究，以及 RFS 2020／2026 两篇金融机器学习论文。逐项出处、迁移用途和限制见 [研究计划](../10-time-series-and-factors.md)。2026 年的新技术发布 TimesFM-3 另列，未将其写成新的顶会论文；核对了下载权重与企业部署有关的许可限制。

有两点直接影响设计：预测误差大不等于企业风险高；收益因子的有效性也不能直接转成信用风险结论。因此先研究带原文的财务因子与现金流估计，再用独立标签检验风险提醒。

## 改了什么

主页和 README 加入大白话解释：时序是把多个季度连起来看，因子是把财报和公告中的线索变成可比较的指标。当前可用的观察因子与后续自动挖掘分开写，保留本地演示版说明。

新增研究计划，明确企业使用者、季度现金流目标、公告时间、标签首次公布日、因子搜索预算和样本外验证。补充一个容易忽略的细节：上一季财报发布时，下一季可能已经开始，所以当季估计与真正的未来季度预测要分开评分。

## 检查与下一步

核对发表信息、作者代码入口及现有因子导出实现；检查文档链接、主页源文案一致性和 Git 修改范围，不改动其他主页项目。未下载权重、未训练、未新增评测分数或支出。

下一步是把多期官方披露整理成带版本的季度面板，检查累计值转单季和标签可得日，再运行简单基线。现有两家公司年度演示样例不足以验证时序预测或发现可靠收益因子。
