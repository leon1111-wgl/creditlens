# 第 10 轮：让模型实际看财报图片，并把看不清的地方留下来

日期：2026-10-25。版本：v0.6.0。用户本轮要求继续迭代、把多模态做好。

## 为什么先做这一项

投研和风险分析员最终要把数字用于研究。如果提取时串列、漏负号或丢单位，后面的因子和预测即使运行正常，也会用到错数据。本轮把已有文字层解析与真实图片识别接到同一个核对页面，先交付能看、能查、能发现不确定性的基础能力。

招聘与企业需求沿用同日 [岗位调研](../01-product-requirements.md)，没有新增客户访谈或市场统计。此任务直接对应文档处理、模型推理、金融口径、评测、失败定位和工程部署能力。它是平台的资料入口，不缩回只有财报核查的产品；时序、因子和企业关系仍沿 [平台方案](../11-financial-research-platform.md) 推进。

独立研究分支本轮提交了 [OCR 实验建议](../research/2026-10-25-advisory-02.md)。借鉴 RapidOCR／PaddleOCR 的官方推理与输出方法，复用已有 Docling、RAGFlow、ColPali 的比较方向。现成产品已具备文档识别和检索能力，CreditLens 需要实际证明的是：金融字段如何带着位置、口径与失败原因进入研究流程。没有实测这些竞品，不声称本项目识别更准。

## 做成了什么

- 本机 CPU 运行预训练检测和识别模型，对微软、苹果六张完整无标记页图做 OCR。模型不接收参考金额、框或 PDF 文本。
- 识别后按位置检查金额符号、年份、期间、单位文字、标签和分区，保留一致、冲突、证据不足三类状态。
- 新增文档工作台，原页与识别框叠加，逐字段对照，可筛选问题、切换公司、查看整页、导出记录；信用复核与季度研究页已有入口。
- 结果绑定源事实包、配置与模型指纹；读取时重算字段与统计，图片哈希不符则拒绝。API-key 模式保护记录和图片请求，密钥不进入图片 URL。
- 预训练权重、完整原页和完整 OCR 留本地。没有调用付费 API、租卡或训练，也没有自动改变现有事实与复核状态。

## 实际结果

六页的 42 项已有开发事实中，39 项全字段一致，3 项证据不足，0 项明确冲突。三个不足都是数字与相邻列美元符号混读。没有人为修掉这些失败，也没有把 39/42 当成通用准确率。完整条件、三个原始输出和复现命令见 [实验说明](../13-document-ai-experiment.md)。

独立代码审查提出两个具体问题：阈值配置最初只写入报告、未传入判断；报告最初只核对包哈希、没有验证字段和统计。两项已修复，并加入阈值变化与 11 类损坏记录测试。复查还发现完全相同的重复识别行会在存储层被去重，导致合法的不足记录被误拒绝；现按最大重复次数合并，保留多义候选，并增加回归验证。顾问意见被落实为检查，不只保留一份建议文档。

全部 134 项 unittest 通过，其中本轮新增 21 项。四个页面的 JavaScript 语法、Python 编译和本地 Markdown 链接检查通过。CPU 模型重新运行后仍是 39／0／3；CI 验证保存结果和程序，不重新跑 OCR。

浏览器验证 1280px 桌面、497px 窄屏（内容宽 482px），检查了微软与苹果切换、失败筛选、整页／区域切换、原页定位、分区字段及空筛选清除旧图。实际下载的 JSON 与同次 API 响应一致。完整键盘、跨浏览器、网络故障注入未验收；原页可视检查不能替代独立标注。

## 本轮边界与下一步

这是**已知位置的图文一致性核对**，不是任意财报自动抽取。还没有真实扫描件泛化、跨页续表、图表推理或通用视觉问答；数字一致也不代表材料真实。页面使用保存的历史运行记录，没有变成实时公告系统。

下一轮优先固定未见公司样例和独立参考，针对跨列错误比较字词级位置，再补扫描退化与真实扫描件切片。不同方法保留完整结果，不能逐字段择优后声称模型提升。通用表格和视觉问答在这之后比较。当前不需要 A100，只有真实模型与数据门槛达到后再给出付费方案。

代码与主页的发布状态、远端 CI 链接以 [当前验收](../06-implementation-status.md) 和 [机器记录](../../artifacts/verification-summary.json) 的本轮条目为准，公开仓库不等于已上线的企业生产服务。
