# 第21轮：把金融研究变成三项能检查的任务

日期：2026-10-25。接续第20轮金额核对，其发布提交 `37d7144` 已通过[远端 CI](https://github.com/leon1111-wgl/creditlens/actions/runs/40190329327)。本轮响应用户追加的任务范围、证据完整性和工程验收建议。

## 为什么做

之前已经有官方数字、现金流拆解和独立复核，但使用者还容易把几个不同层次混在一起：找到数字就认为问题答完，表内加总相等就认为经营原因已经解释，底稿获批就认为所有假设成立。这会让正确的计算支持过度的结论。

第一版因此收敛为多模态金融证据工作台，逐项交付查指标、比同口径变化、整理经营解释证据。时序、因子和更广的平台继续作为后续研究方向。企业用户仍是投研和风险团队；岗位及竞品依据沿用2026-10-25已有公开调研，没有新增客户访谈或机构效果。

本轮重新核验用户提供的 FinQA、ViDoRe V3 和 Anthropic 原文：借鉴可复算程序、视觉检索/回答/区域定位分开评测，以及固定任务使用明确工作流的原则。出处和适用限制见[任务验收说明](../24-research-task-acceptance.md)，不把引用论文算作本项目成果。

## 本轮完成

- 新增只读检查层。八张指标证据卡、四项同公司年度变化及经营解释缺口分别输出。原文可定位和人工采用分别判断；跨公司仍不排名；没有登记的公司解释明确为空，不写成企业没有披露。
- 增加两条身份受控接口和“任务检查”页面。结果绑定任务ID、当前版本和材料摘要；保存、切换任务或身份后旧检查失效，未保存不能继续检查或下载。下载保留原始响应字节。
- 保留旧任务、复核、导出和规则。检查已复核任务时，经营原因仍为证据不足。材料漂移返回409，已有冻结底稿继续可读，不用新结果覆盖旧快照。
- 建立固定开发题库和可重跑脚本，分别核对结果字段、引用定位与拒绝行为。题目由AI辅助拟定，独立人工确认均待完成；固定选择器执行，不解析题目自然语言。
- 更新 README、项目故事与 GitHub 主页入口。解释“证据建模”是数据结构、关系与来源管理；每个模块补上输入、正确标准、常见失败及恢复方式。

资料分支负责核心检查与25项测试；实验分支负责题库和复跑工具；研究分支独立审查；main负责API、界面、旧版兼容实测与发布。

## 独立审查推动的修改

1. 当前检查只绑定当前版本，关联旧快照不代表重新评估或批准旧稿。自由问题不参与任务状态判定，防止“全部资本投入”这种问题被固定PPE卡片的可用状态误代替。
2. 新比较详情起初遗漏闰年提示。已补双方实际日期和天数、365/366天差异说明及计算输入，不把同口径误写成相同时长。
3. 验收题目录的布尔版本号和非字符串variant起初未严格拒绝。已补类型检查和反例，坏目录给出可解释失败。
4. 材料漂移测试改为在已提交任务上真正改变登记读取结果，验收返回409后再次比较旧导出字节；不只mock整个检查函数。

## 已验证

浏览器实测已复核任务：八项资料可回查、四项自身变化可计算，跨公司仍不能排名，经营解释仍缺经营附注、公司明示解释和独立核实。新建模拟草稿未采用任何事实时，资料可见但比较阻断；编辑后结果清空且下载禁用，保存新版本后可重查。切换只读身份清空旧结果，重新载入后仍可读取检查。

实际下载为85,136字节，与API原始响应逐字节相同。桌面和497像素窄屏均检查；窄屏文档宽482像素、面板450像素，没有整体横向溢出。前述行为见[浏览器验收](../../artifacts/research-acceptance-ui-verification.json)和[实际结果](../../artifacts/research-acceptance-example.json)。模拟角色与测试草稿不代表客户使用。

完整测试和题库结果以本轮[验收记录](../../artifacts/research-acceptance-verification.json)为准。测试数字用于工程回归，不能改写成模型准确率。

## 仅完成设计、阻塞与下一步

通用文档接收、解析、校验、入库、可查询、失败重试、修订与删除传播目前形成了状态和验收设计，未实现完整上传流水线。开放式问题理解、逐句支持度验证、图表估读、跨页表格和独立人工测试集也没有在本轮完成。

下一轮优先补一项有原文和明确归因主体的经营解释证据，保留适用期间与核查范围；同时由人对候选题逐题确认，建立独立测试集。公司原文解释只能写“公司将其归因于……”，不能自动当作独立证明。暂不租GPU；本轮无模型调用、收费API、训练或大文件下载。
