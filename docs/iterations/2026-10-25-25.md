# 第25轮：先检查收到的材料，再判断识别结果

2026-10-25，v0.17.0。本轮围绕新材料入口完成原始OCR检查、材料身份检查、单页准备CLI、只读页面、实际导出和独立审查。没有下载大文件、调用付费服务或训练模型。

## 为什么做

研究人员需要查清一个数字出错在哪一步。识别输出缺框但残留文字，不能被当成正常空页；同一份PDF换个编号，也不能扩成两份独立材料。否则后续金额核对看似合理，输入与统计已经失真。

需求及岗位主线沿用2026-10-25已核验的[企业研究任务](../research/2026-10-25-enterprise-research-design.md)、[实际产业项目参照](../research/2026-10-25-hku-industry-projects.md)与[金融文档及治理研究](../08-document-ai-and-governance.md)。本轮对应Document AI工程、数据质量、来源管理和模型验证能力。同行及开源参考继续使用现有Docling、MinerU与视觉文档研究记录，关注解析之后如何检查输入和保留失败；未新增竞品实测、客户访谈或市场结论。不能据此声称优于这些产品。

## 完成了什么

1. 原始四角在任何包围框转换之前检查，拒绝NaN、Infinity、非法类型、越界、自交、凹形及结构冲突；保留合法旋转框与明确空输出。
2. 来源清单先通过原有冻结验证，再检查PDF、参考包、路径、页面及证据身份，拒绝同资产换编号重复登记；合法不同版本继续保留。
3. 单页准备CLI绑定登记页、尺寸和摘要。错误时返回具体字段；修正可重试，完整结果独占写出，同名不覆盖，状态明确为尚未入库。
4. 新公司核对页增加输入检查面板，展示固定预期、旧与新行为和失败路径，提供原响应下载。API认证、只读和失败状态与现有入口一致。

完整输入、正确标准、常见错误、恢复方式和运行方法见[功能说明](../28-document-input-preflight.md)。

## 实际验证

| 验证 | 结果与范围 |
|---|---|
| 原始OCR固定控制 | 25项符合预期：6通过、19拒绝；旧转换器接受其中11项应拒绝输入。全部为合成开发控制 |
| 资产固定控制 | 2项符合预期：当前登记通过、重复同PDF拒绝。未重新读取PDF原字节 |
| 本机CLI | 坏角点退出2且无目标结果；修正后退出0；再次同名退出2，已有文件字节不变 |
| 界面与下载 | 实际载入25行与2项资产控制；密钥变化清空结果和导出；22670字节下载与API逐字节一致；无浏览器控制台错误 |
| 软件回归 | 714项运行，712通过，2项因Windows符号链接权限跳过；新增50项包含两个核心模块、CLI、语义重算及API |
| 历史保护 | 96个原有来源、配置与结果文件规范化摘要不变；3个原有诊断API响应字节不变 |

可检查的结果：[固定开发报告](../../artifacts/document-input-checks.json)、[CLI验收](../../artifacts/document-input-cli-verification.json)、[页面与HTTP验收](../../artifacts/document-input-ui-verification.json)、[实际截图](../images/document-input-preflight-desktop.png)。没有独立人工题、跨浏览器或新窄屏验收；这些不能用软件测试数量代替。

## 独立审查与采纳

两条实现分支分别交付原始OCR适配与资产预检，主分支逐项合并。研究顾问独立复现旧NaN丢失、空框残留文字和真实清单复制资产问题，再验证新入口、原始输入探针、来源绑定、报告篡改拒绝及API边界，见[第十六份审查](../research/advisory-16.md)。

审查提出两项修改并已落实：诊断控制失败时仍保留完整候选报告，不能先抛错丢掉失败；页面将旧转换器行为标为“接受／拒绝”，并逐行展示固定预期和是否符合，避免把旧转换成功误读为内容正确。顾问验证不能代替独立人工标注，本轮仍明确没有新的模型效果主张。

## 限制与接续

新预检需要显式调用，旧冻结runner没有自动迁移。来源摘要只比对登记声明，不是PDF验真；结构通过不代表识别文字正确或财务口径可比。单页CLI的失败重试与独占落盘不等于完整任务队列、服务重启恢复或通用入库。

下一组工作优先将新预检接入一个明确的未来输入任务，并在获得合法材料后保留原始四角、冻结跨页表格参考与失败条件；同时继续准备人工独立核验题。跨页与图表目前仅有任务设计，未新增模型结果。既有实验继续可复现，不通过覆盖旧报告掩盖缺口。
