# 第26轮：材料没处理完，就保留待修正

本轮交付 v0.18 的材料准备流程：同一文档的登记页一起检查，缺页或某页损坏时留下明确问题，修正后生成新的尝试。处理人可以接着做，同事也能看到之前为什么失败。

## 为什么做这组改进

投研和风险分析依赖可用材料。如果只显示“上传成功”，却没有说明哪些页没解析，后续查指标就可能把未处理误当成未披露。本轮针对材料处理与交接人员，先把登记页集、输入质量和修正历史接起来，尚不接入搜索或财务审批。

招聘与竞品依据沿用 **2026-10-25** 已核验的[产品需求](../01-product-requirements.md)、[文档智能与治理调研](../08-document-ai-and-governance.md)、[产业项目参照](../research/2026-10-25-hku-industry-projects.md)和[跨页任务建议](../research/2026-10-25-advisory-11.md)。公开岗位中的数据质量、可复现评测和后端可靠性要求支持本轮优先级；Docling、MinerU 等解析工具及产业尽调项目用于参考材料处理步骤。没有新增客户访谈，也没有在相同材料上与这些产品做效果对比。

## 本轮完成

三条既有隔离分支分别实现整组输入检查、诊断记录与重试、独立审查，main 负责 API、页面、复演和验收。

- **整组检查：** 从服务端清单确定一份文档的全部登记证据页；缺页、重复页、额外页、空识别及坏坐标都会保留原因，阻断整组准备通过。登记页不等于全 PDF 页集。
- **记录与重试：** SQLite 保存摘要、错误、来源绑定和每次尝试。幂等重发返回原结果，CAS 拒绝过期修改，换材料不能沿用同一任务。已保存的旧尝试可以独立导出。
- **操作页面：** `/document-preparation` 接通新建、修正、历史选择和导出，沿用白灰蓝配色及 Times New Roman／宋体。服务端角色决定是否可写，切换身份后清空已加载内容。
- **存储边界：** 仅保存小型诊断信息；原始 OCR 文字和词数组不进该数据库。本轮未下载大文件，不改主应用既有数据，页面演示使用独立本地状态。

具体输入、正确标准、失败处理与 API 见[功能说明](../29-document-preparation.md)。

## 审查发现与处理

独立顾问检查了租户、身份、并发、幂等、原文保留和历史导出，并提出以下修正：错误路径允许固定的字段分隔；当前材料载入失败时仍保留历史列表；切身份清空隐藏字段；异步响应按请求代次隔离；旧幂等响应读回后重新取得当前任务版本。

还修复了一个较隐蔽的重试问题：写请求已经成功、随后结果读取失败时，页面原先可能根据更新后的修订号生成第二次写请求。现在相同输入保留首次请求正文与幂等键，后续重试仍对应原尝试。界面代码路径另用 Node 内存故障控制检查，和真实浏览器的正常流程验收分开报告，见[顾问记录](../research/advisory-17.md)。

一份顾问测试产生的临时目录在清理时被自动审批拦截，已保留且未换方式重试；不涉及主应用数据库。本轮复演脚本自己的隔离临时数据库已正常释放。

## 已验证之外

当前实现为同步请求和已提交诊断记录的恢复读取，未实现后台解析队列、崩溃任务续跑或搜索索引事务。准备通过后仍然不可查询、不会自动批准；真实文件字节、识别内容、表格语义和财务口径需要后续核对。

跨页表格和图表继续沿既有设计准备来源、表头／脚注关联与拒答标准。下一组应选择一项明确的跨页任务和可公开的参考记录；没有合法输入时先完善版本传播与失败恢复，不反复重跑现有样例当作新模型成绩。本轮无需 GPU，也没有产生训练或付费 API 费用。
