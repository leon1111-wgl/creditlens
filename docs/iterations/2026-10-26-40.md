# 第40轮：完整读单位说明，再决定能否展开数量级

日期：2026-10-26。版本：0.32.0。

## 为什么做

研究员查到金额后，往往需要把“百万”换成基础数量级，再准备比较。如果表头写着“以百万计，但收入以十亿计”，只读到前半句就会产生错误的换算依据。主开发和独立顾问以合成页面复现：旧文字、版面、词级、角色及显式选行路径都可能保留候选并声明 million。原模块没有把这些候选自动写入研究事实，也没有证据证明既有六页存在同类错误；本轮修的是后续使用时不能忽略的单位适用性缺口。

业务与岗位判断沿用2026-10-25的[产品需求](../01-product-requirements.md)和[企业研究设计](../research/2026-10-25-enterprise-research-design.md)。已有 FinQA、TAT-QA、OHRBench 等参照强调数值依据与处理阶段分别验收；本轮采用这一设计思路，没有新增客户访谈、市场结论或外部模型结果。

## 本轮完成

新增独立单位检查，读取完整单位原文、原行名、已选金额及定位证据。完整语法支持明确量级和已登记的每股、股数、面值例外；未知尾缀、按行或按年例外、隐含每股行以及证据不对应均不能展开数量级。包含例外时，只对有限明确金额行类别适用主量级，未知类别保留不足。没有借参考金额或框放行。

通过时用隔离的 Decimal 上下文展开量级，原始值、乘数、结果分别保存；币种、完整期间、报表范围仍未知。原方法没选出金额时，新检查不会补出一个数或解除原拒绝。旧模块、报告和评分保持原样，新增结果单独绑定来源。

只读 API、`/table-lookup` 页面和单次原响应导出已接通。可选择四种自动方法或已经明确选中的原行。切换身份、实验、样例、方法或原行后清空旧结果，迟到响应不能恢复旧下载；导出时再次检查当前选择。输入、验收、错误及恢复详见[使用说明](../42-unit-applicability.md)。

## 已验证

保存材料包含42条登记记录、40组不同查询与8条显式选择路径。单位检查共有176次：文字26可展开／16原未选出，整行26／16，词级22／20，按证据用途30／12，显式选择8／0；没有新增单位阻断。176不是独立金融样本数，也不是新的模型评测分母。

20种合成场景分别经过五条提取路径，共100次检查符合预期，其中50次旧规则选出的候选被新单位检查阻断。它们包含未知例外、混合量级和隐含每股行等控制，与真实登记材料分开保存。公开[检查报告](../../artifacts/unit-applicability-report.json)只使用已有小型证据，不重下原始文件或运行 OCR。

## 独立审查与取舍

核心分支负责完整单位语法及证据检查，实验分支负责固定报告、复算与只读存储，顾问负责反例和页面异步状态审查，main负责 API、页面和实际运行。采纳了顾问提出的 Basic／Diluted 保守处理、未知例外阻断及导出临点绑定检查；将错误方法类型和超大几何值转为固定契约错误，避免异常输入产生无法解释的内部错误。完整意见见[独立审查](../research/advisory-31.md)。

没有直接修改旧单位解析器，因为旧实验的实现摘要与报告链已冻结；新层让旧接受结果和新阻断原因都可追查。旧 API 的候选元数据不因此升级为经过新检查的财务事实，使用者须查看单独的单位核查结果。

## 仅设计、阻塞与下一步

本轮不确认币种、完整期间、合并范围或材料真实性，不扩大为通用语义理解。完整页面 OCR 没有重放，登记页已经用于开发，真实独立人工参考仍为0。没有模型训练、客户试用、效率收益或跨公司有效性结论。

跨页续表、图表及未参与调参的材料仍须合法来源与独立参考。后续优先获得这些输入，再检验表头、脚注和量级规则能否覆盖实际新材料；不通过重复当前控制扩大成绩。
