# 工作台与历史数据，下一步先补什么？

日期：2026-10-25。独立研究分支：`research/advisory`。核查起点：`69d7aad`。本文只提出建议，不修改产品代码；主分支同期新增的功能须另行验收。

**建议本轮把季度脚本接成一条能实际使用的研究流程，随后把开发重心移到多家公司历史披露与修订版本。** 工作台解决“用户能不能用”；时点数据解决“研究结论是否成立”。以当前代码看，后者是预测、因子和关系模型的主要瓶颈。界面完成后继续堆图表、聊天入口或模型名称，不能解除这个瓶颈。

可向使用者这样解释项目：选一家公司和研究日期，看看当时有哪些资料、现金流发生了什么变化，点开数字查出处，把疑点和判断交给同事复核。正在补的是多家公司和多个季度的比较；预测与因子有效性仍要等历史数据和样本外实验验证。

## 企业场景、招聘与竞品：为什么这个顺序更有价值

本轮沿用 [2026-10-25 岗位与业务调研](../01-product-requirements.md)。最直接的使用者是机构基本面投研、信用研究和风险分析人员。他们需要回答“现金流为什么变化、当时能知道什么、计算是否可比、同事能否复查”。整理同一份资料反复耗时、研究与数据口径脱节，是待验证的产品假设；目前没有从业者访谈数据，不宣称已经替企业节省了多少时间。

用户提供的岗位中，投研 Agent、金融大模型应用、模型评测及数据工程最能对应这一交付物。可以展示的能力是：可靠数据接口、财务期间处理、检索证据、模型评价和实际流程。后训练岗位还需要真实模型实验和训练记录；图模型岗位还需要时间合法的关系数据与消融；现阶段都不能只靠平台名称证明。JPMorganChase 的 [官方 ML 团队介绍](https://www.jpmorganchase.com/about/technology/research/machine-learning) 是同日研究的方向性依据，不是整个就业市场的统计样本。

竞争判断需要收窄。Qlib 官方已经实现用于财报版本的 [PIT 数据库](https://qlib.readthedocs.io/en/latest/advanced/PIT.html)，文档明确解释后来修订的数值为什么不能放入早期回测。因此，“财报可按历史日期查询”不能单独当作 CreditLens 的独创卖点。该功能与本项目的数据问题接近，值得借鉴其版本组织和查询语义；本轮只核查文档，没有安装测评。

FinRobot、RAGFlow、Qlib 和 RD-Agent 的既有比较见 [开源调研](../02-open-source-and-papers.md) 与 [平台方案](../11-financial-research-platform.md)。它们分别覆盖研究任务、资料处理、量化实验及自动研究。不要声称它们没有证据、时间或审核能力。CreditLens 更具体的价值假设是：**一个研究信号被导出或交接后，原文位置、数字口径、何时可知、如何计算、是否经过人工复核仍能一起查到。** 是否更好，应使用同一批任务比较错误、返工和总耗时，而不是比较功能名。

本轮不建议重新实现交易引擎，也不建议增加无任务约束的多 Agent 聊天。独立研究分支负责提出建议与反例，主实现负责选择和验证，已经可以形成可检查的协作方式。

## 三项排序建议与验收条件

排序按接下来三轮可交付成果安排。第二项是平台研究深度的主要依赖；第一项范围应收紧，完成即可推进第二项。

### 1. 本轮：交付可操作的季度研究工作台

围绕一个具体任务：“截至某日，微软各季度现金流和资本开支有什么变化，哪些数字需要进一步核实？”让用户选截止日、看趋势、查看证据与计算式，并导出同一份快照。研究页应明确显示目前只有微软 FY2025 历史样例，避免用户误认为已连接实时数据。

建议验收：

- 页面、API 与导出采用同一份服务端快照；截止日变化后同时更新数据、证据和导出，不把旧图与新日期拼在一起。
- 公告当天还没有新值，次日才可见；早于首份披露的日期展示“当时尚无可用披露”，不能默认跳回全年最新值。
- Q4 的三个候选值持续标为“由全年减九个月计算，待复核”，可以显示但不能与直接披露值混用同一图例；没有值时显示缺口，不能补零或外推。
- 每个已显示的数值都能打开期间、单位、来源 URL、原始事实和公式。阻断状态要显示原因，不能只隐藏异常点。
- 图表说明金额单位和期间。三个指标可同时比较，但同比、增长率或季节结论必须满足数据条件，不能以单一财年画“周期规律”。
- JSON 或可读报告保留实体、截止日、数据指纹、原始事实、状态和限制。记录代码版本与规则版本作为后续重跑依据；现有 `snapshot_sha256` 只是可见证据的指纹，不能被说明成整份计算环境或整个产品的完整性证明。
- 新接口沿用既有身份与租户边界；在接口错误、加载失败和无可用数据时给出明确状态。前端正确显示不能替代 API 层校验。
- 至少覆盖公告日／次日、空快照、推导状态、页面导出一致性与未授权访问的验收；完成一次从页面切换日期到下载结果的实际操作。现有核心时点测试继续通过。

这些验收检查的是本轮功能正确性。真实用户是否更省时，需要之后用等难度任务、包含核查返工的总时间验证；目前不设“节省 30%”之类已达成表述。

### 2. 下一轮：建立多公司时点数据与修订链的最小版本

先把“同一家公司、同一指标、同一期间的两个版本”表示清楚，再增加公司数量。面板的第一批目标可以是少量公司、两至三个财年的工程开发样例；具体数量按覆盖的错误类型决定，不能当成训练数据充分性的门槛。微软和苹果的会计日历不同，苹果周历季度在适配完成前须明确拒绝，不能套用整月季度。

建议以 SEC 提交记录和原始 filing 为版本入口。SEC 官方说明其聚合 JSON 会随提交更新，Frames 会选最接近日历期间的最后申报事实，还提醒不同公司期间起止可能不同。因此 Frames 可用于受限探索，不应直接承担历史首次披露标签；companyfacts 可帮助发现事实，但每个研究值仍要回到 accession 和原始期间。此处是根据 [SEC API 文档](https://www.sec.gov/search-filings/edgar-application-programming-interfaces) 作出的工程选择，不表示 SEC 接口自动保证本项目的全部历史回放正确。

建议数据契约和验收：

| 问题 | 最小记录与行为 | 验收例子 |
|---|---|---|
| 属于哪家公司、什么数值 | 稳定公司 ID、taxonomy/tag、期间、流量或时点余额、单位与币种、范围与口径映射版本 | 同名不同指标、合并与分部、不同币种不能静默合并 |
| 当时是否公开 | 文档 ID／accession、公告或公开时刻及其证据、精度、时区；只有日期时继续保守开放 | 新公告、比较栏回述和修订在各自可得时间之前不可见 |
| 系统当时拿到了什么 | 抓取时间、原始哈希、解析器版本、数据版本；区分“当时公开”与“系统已经取得”两种回放 | 后来抓到历史 filing 不假装本系统当年已经运行；新抓取不覆盖旧文件登记 |
| 为什么有两个版本 | 原始事实不覆盖；显式记录修订／重述或待解决关系、选择规则及依据 | 较晚版本加入后，原来的历史快照与旧实验仍可重建 |
| 怎样从累计得到单季 | 操作数、公式、可比性判断与审核记录；派生值单独保存 | 年末减九个月的值不会自动变为 reported；范围不明时阻断 |
| 标签用哪个版本 | 首次公开目标值与后续修订分别保存，标签可得时间独立于观察时间 | 使用后来修订值的敏感性分析单列，不偷偷替换主实验标签 |

把“原始首次披露”“截止日之前最新可用版本”“今天最新修订版本”作为三种明确查询，不能让默认的 latest 混进历史回放。同一经济期间在后续报告中重复披露，可能是重复、重分类或重述；先保留冲突，不能仅按数值相同就认定为同一版本。`basis_id` 字符串相同也不是实际合并范围未变化的充分证据。

数据验收至少包含：正常披露、后来修订、同值重复、未解决冲突、错单位、52／53 周日历、累计差分、原网页失败八类情况。有真实官方修订案例才标记为真实验证；合成修订只验证软件行为，必须单列。每个样例可从登记回到原始材料与哈希。若取不到足够合法历史材料，交付覆盖清单和失败记录，暂不启动模型排名。

### 3. 后一轮：冻结一项现金流任务，跑可复现的 CPU 基线

第二项形成足够长的多公司数据后，才开始这一项；一轮时间不够不勉强宣布模型阶段完成。优先选经营现金流作为连续目标，暂不同时承诺收益预测、违约概率和组合优化。

任务必须用具体日期定义：观察时刻是什么，目标季度何时开始／结束，标签何时首次公开。如果观察时刻已进入目标季度，单独归为 nowcasting；目标季度已结束的样本不能混称真正的未来预测。企业异步披露时，不以相同的“Q1”文字替代相同的经济时间。

建议验收：

- 先冻结数据清单、任务定义、标签版本、时间分割和未见公司切片，记录样本被排除的原因；三种指标不当作三个独立企业样本。
- 训练标签的公开时间必须早于训练截止，标准化、补缺、特征筛选和公司关系均只使用训练时可得资料。测试期调参和自动因子反复尝试须被隔离并记录。
- 先运行去年同季、简单季节统计、线性及一个树模型；缺少去年同季历史时，单独报告基线覆盖率，不能只在自己有利的样本上比较。
- 同时报告 MAE、按公司规模适当归一化的误差、覆盖率、样本数及失败切片；零附近不盲用 MAPE。区间方法若实施，应另留校准段，报告实际区间覆盖与宽度。
- 保存固定的代码、配置、种子、特征、标签和预测输出，陌生使用者能一条命令重跑。先展示误差和失败，达到完整实验条件后才比较时序模型或文本增量。
- 因子先称为“待验证研究信号”。现金流预测误差降低不能改称违约识别提高；没有完整行情、历史成分、退市和交易成本数据，不提供有效投资收益结论。

本轮与下一轮都不需要租 A100。只有冻结任务、合法数据和 CPU 基线之后，明确需要比较的多模态／时序模型，并备好训练脚本，再用短实验实测显存、吞吐与时间，提出费用申请。数据更新、在线托管和模型训练是三件不同的事。

| 不宜写成 | 应保留的准确表达 |
|---|---|
| “已经是企业级实时金融研究平台” | “面向企业研究流程建设的本地演示与研究工具；实时采集、部署运维和真实模型评价待完成” |
| “已实现多模态金融预测” | “固定 PDF 页面已有事实定位；通用视觉理解和预测模型尚未完成” |

| “来源来自官网，所以是真实无误的事实” | “可追溯到官方披露的数值；一致性检查不能鉴定材料真实性或消除源数据错误” |
| “Q4 已有三个季度真实值” | “Q4 三个累计差分候选值，仍待口径与修订复核” |
| “证据指纹证明结果完整且不可篡改” | “指纹用于检查已指定输入是否变化；计算规则、身份与存储治理需要其他记录” |
| “因子／预测已有效” | “已有观察指标；有效性需由冻结的样本外实验检验” |
| “论文成果说明本项目会有同样收益” | “论文提供方法参照；数据、目标、成本和实现不同，效果必须重测” |

另外，`docs/05-roadmap-and-github.md` 的“当前 v0.4”行仍写 86 项测试，而实现状态已经写 103 项。主分支应将旧基线和最新验收分开表述，避免主页或路线图混用不同时间的完成状态。研究分支不直接修改这两个文件。

重点防漏的不是一个日期字段，而是整条加工路径：后来的比较栏不能倒填过去；后来的修订不能覆盖首次披露；目标公司未来文本不能进入训练期向量适配；今天的行业与供应链关系不能当作旧时点关系；因子搜索不能反复窥探冻结测试；新模型也可能在预训练中见过历史结果，使用现代大模型回测旧数据时必须单独披露这项限制。
