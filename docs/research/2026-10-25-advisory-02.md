# 用真实页图做一次财务证据核对

日期：2026-10-25。研究分支：`research/advisory`。复核主仓库起点：`6b80030`，v0.5.0。本报告是独立实验建议；未在主工作区安装依赖、启动进程或运行 OCR，没有训练、云 API 或费用支出。只有主实现实际运行后，结果才能登记为完成。

**本轮建议做“页图 OCR 与已有财务事实的一致性核对”。** 从已登记的微软、苹果官方数字 PDF 渲染页面，用真实 OCR 模型只看像素独立识别，再按已有位置检查金额、年份、期间、单位和行标签。把一致、冲突和证据不足分开显示，允许人回到原图复核。它能验证一条真实视觉输入链，不需要先租 GPU，也不需要把范围扩大到通用扫描件、图表推理和整份报告问答。

## 业务价值和本轮范围

分析员拿到数字后，需要确认文字层有没有读错、年份列有没有串列、括号负号或数量级有没有丢失。视觉识别提供另一条读取路径，有机会发现文字层解析与可见页面之间的不一致。两条路径仍来自同一份披露，不能构成独立真实性证明；具体能减少多少返工需要用户任务测试。

沿用 2026-10-25 的 [岗位与业务调研](../01-product-and-career.md)、[文档智能方案](../08-document-ai-and-governance.md) 及 [平台设计](../11-financial-research-platform.md)。它能直接展示金融文档处理、模型推理、结果评测、错误定位和人工复核能力。没有新增招聘市场统计、客户访谈或竞品优劣结论。RapidOCR、PaddleOCR 已提供识别能力，本项目应证明的是模型输出如何接受财务口径和证据约束，而不是将调用 OCR 包写成算法创新。

主仓库目前有两份固定数字 PDF、六页、42 项带位置的开发事实，已有金额、行标签、年份、期间和单位框；部分苹果事实还有报表分区。现有 `build_pdf_pack.py` 用 PDFium 读取文字层并生成带框预览，没有 OCR。这些基础足以进行本轮实验，但不是盲测数据或独立标注集。

## 实验如何避免拿答案帮助识别

建议拆成两个独立步骤，让数据依赖在代码层面可检查。

1. **独立识别。** 输入经过哈希检查的 PDF、固定页码和渲染配置。生成无叠加标记的整页图像；只把像素输入 OCR。此步骤不接收事实金额、年份、行标签或参考框，也不从 PDF 文字层补识别结果。先保存原始 OCR 输出与哈希，再进入下一步。
2. **后验核对。** 读取冻结的 OCR 输出和既有事实包，把图像坐标映射到 PDF 坐标，依据位置寻找候选，再检查文字、数值与口径。候选选择只看预先定义的空间规则，不能因为某个候选正好等于参考值才选中它。

页码本身已经人工选择，后验匹配也使用已有框，因此本轮仍是受控核对。即使第一步跑了整页检测，也不能由此声称已经解决全报告找页、找表或未知字段抽取。

特别注意：现有 `build_pdf_pack.py --render-dir` 输出已画上彩框，不能直接拿这些预览图当 OCR 输入。必须重新生成干净页图，识别后才绘制叠加层。否则视觉输入已经受参考位置干预，彩框还可能干扰数字。

建议冻结一个主渲染分辨率，并记录 PDFium 版本、page box、旋转、图像尺寸、颜色通道和最终哈希。PDF point 转像素使用实际宽高与变换；不要无条件复用旧预览的 1.8 倍系数。旋转、裁切或内部缩放不清楚时应拒绝匹配。若比较两个分辨率，两个结果都保留，不能每个字段挑较好的那个作为主结果。

## 从 OCR 输出得到三个核对状态

RapidOCR 通常给出文本行框，一行财务表可能同时包含标签和几个年份的数字。整行包含正确金额，不能证明它位于正确年份列。官方支持 `return_word_box=True`，可以取得更细粒度内容与位置；其结构仍应按实际安装版本验证。若无法唯一关联到目标列，保留证据不足。分数用于排序或拒绝低质量输出，不是已经校准的正确概率。[输出与字词位置说明](https://rapidai.github.io/RapidOCRDocs/main/install_usage/rapidocr/usage/)

| 状态 | 建议判定 | 不能做什么 |
|---|---|---|
| 一致 | 所要求的金额、年份、期间、数量级和行标签都有唯一、足够清楚的空间证据；分别与登记参考相符 | 仅金额一致就放行整条事实；将一致等同真实或已审核 |
| 冲突 | 有明确、可定位且按冻结规则可解析的证据，与参考至少一个字段不符 | 为了匹配而自动把 O 改成 0、删除负号、改单位、移动年份列 |
| 证据不足 | 无识别、分数不足、候选多义、文字损坏、缺单位／期间、跨列或变换不可靠 | 把缺失当零；把不确定的候选当成确定冲突或确定一致 |

字段级结果先保存，再按规则聚合；同时存在明确冲突和其他缺失时保留全部原因。整条事实只能在所有必需字段通过后进入“一致”。年份正确而期间表头缺失、金额正确而行标签不清，都还不够。

金额核对保留 OCR 原始字符串与标准化过程。允许哪些空格、千位符和括号形式事先确定；规范化不允许按参考值猜字符。资本开支沿用明确的现金流出转换，其他指标不能随意取绝对值。单位表头有“millions”不等于识别出 USD；币种若仍来自发行人配置，标为配置依据，不能算作视觉识别成功。分区和周历口径同样不得被金额匹配替代。

若追加“裁剪已知金额框后再识别”的诊断，必须作为另一组结果，注明参考位置已输入识别器；它可以帮助区分全页检测失败与字符识别失败，不能合并进全页结果提高分数。

## 本轮验收和可视复核

目标交付是可运行脚本、冻结清单、原始 OCR、本地可视结果和机器可读核对报告。建议至少包含以下验收：

- 两家发行人的指定页面均实际经过 CPU 模型推理；执行失败、模型下载失败和超时单列，不能以静态样例顶替模型输出。
- 全页输入的哈希和实际 provider 可追查，识别步骤不能读取事实包；更改参考金额不应改变已保存的 OCR 输出。
- 核对结果引用具体 OCR 项、源框与原始文字；原页上同时区分参考框和 OCR 框，选中结果能看出为何一致、冲突或不足。
- 原始页面与文字输出用安全的本地方式展示；字符串按文本转义。若增加 API，只服务已登记结果，不开放任意本机路径或任意 URL 抓取；复用现有鉴权。
- 合成控制覆盖：改金额、改年份、改数量级、删负号、缺字段、跨列多义、坐标变换错误和重复候选。它们验证核对器，不计入真实 OCR 识别成绩。
- 至少检查一处实际一致、一处实际失败或不足；若真实样例未出现某类结果，不制造真实失败。所有候选及人工检查意见保留。
- 核对器故意接收冲突参考时不能自动修成一致；不得覆盖原事实、自动批准案件或把一致标为可信训练标签。

展示结果时，分母是冻结任务清单，缺失和失败都在其中。分别报告事实级一致／冲突／不足计数、字段级原因、实际完成页数、冷启动与热运行耗时、环境和内存口径。只有六页时不渲染成稳定的生产延迟指标。共享的单位表头会被多条事实复用，不能把这些字段当作独立样本计算漂亮置信区间。

42 项来自已经适配的两个开发样例，既有参考也没有双人独立标注。本轮最准确的结果名称是“已知位置财务事实的视觉—文本一致性核对”，不是“通用 PDF 抽取准确率”或“多模态模型准确率”。程序测试通过率与真实 OCR 核对结果另行报告。数字 PDF 转成图片也不等于真实扫描件测试；后续添加噪声、遮挡或倾斜时须标为受控图像扰动。

## 下一步如何变得更强

若本轮能稳定复现，应优先解释失败：是检测不到小字、串列、符号错、字段关联错，还是参考本身有问题。随后加入未用于调整规则的新发行人／新报告，独立标注页面、表格与字段，再比较“整页发现＋字段关联”和本轮已知位置核对的差距。只有到那时才逐步讨论通用抽取指标。

扫描件、图表、跨页续表、视觉检索和 VLM 可以按失败类型依次加入。ColPali 适合研究相关页面检索，不能代替这次金额与财务口径核对；更大的模型也不能修复错误的评测分母。当前使用预训练 OCR 的 CPU 推理已经足以建立一项真实模型实验，暂无租卡或训练的必要。

可用的大白话介绍：“现在除了读取 PDF 的文字，还会把页面当作图片再看一遍，检查两条读取路径对数字、年份和单位的判断是否一致；看不清或对不上的地方交给人处理。”发布时应加上“当前在固定官方样例中验证”，并明确这不是财报验真。
