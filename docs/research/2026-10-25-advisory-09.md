# 第18轮独立审查：跨公司现金流研究任务

审查日期：2026-10-25。研究工作区包含主分支 `2058f4a`，本轮只写此报告，其他工作区只读。不新增 OCR、训练或模型成绩；复用前一轮的[实际产业项目调研](2026-10-25-hku-industry-projects.md)与[任务设计](2026-10-25-enterprise-research-design.md)，不重复生成市场综述。

## 企业任务与本轮边界

把材料整理、数值采用、变化计算、候选解释和独立复核接成一次研究交接，是本轮的主要价值。微软与苹果已有材料适合检验这条流程，但不构成严格同行基准。两家公司业务结构、财年截止日及年长不同，本轮可以展示各自变化与比较限制，不应据此生成跨公司高低排名、投资结论或预测效果。

只有八项 CFO／PPE 现金支出事实时，不能解释全部经营变化。研究员可记录待核查假设；缺乏应收变动、税款或管理层讨论等材料时，应把缺口交接出去。一个引用指向现金流总额，不等于它支持某项变化原因。

## 先给实现者的必要约束

1. 观察值身份绑定发行人、披露字节版本与原事实 ID。两家公司都有 `cfo-2025`，不能仅凭本地 ID 关联；引用还应属于当前任务登记的材料集合。
2. 建案时固定材料版本与摘要；新提交不能无声重新读取已变化的文件后沿用旧依据。已提交快照应独立保留采用／拒绝、假设、引用、口径、计算和覆盖缺口的完整版本。
3. 复核身份按用户 ID 分离，不能只检查 role 不同。退回重编产生新修订，旧快照和指定版本的导出保持可回看；当前草稿导出与历史快照导出需明确区分。
4. 当前材料模式与历史时点模式分开。申报日、今天抓取到文件和历史资产版本证明不是同一字段；缺证明时拒绝历史回放，不给文件补日期。
5. 原始 PDF、整页图、完整 OCR 与本地数据库继续留在本地。公开截图不显示密钥或非公开身份；新增界面采用既有服务端身份依赖，切换时清空旧数据并取消失效请求。

## 实现与验收接续

本顾问只读审查了两个实现分支的 `research_materials.py`、`research_task_store.py` 及专属测试，另审查主工作区的 API 和 `tasks.html`。核心材料与存储实现没有发现阻塞问题：固定登记的两份事实包按规范 JSON 摘要核验；新范围依据显式保留人工核对方法；所有创建、编辑和提交者均按用户 ID 排除自审；提交会固定整份材料、采用决定、候选解释、口径、计算与缺口。规范 JSON 摘要不等于原文件字节摘要，接口也明确没有重新下载原始 PDF。

另外独立运行了一个临时数据库控制流程：直接加载两个分支的真实实现，读取微软和苹果原有事实包的临时副本，不运行 OCR 或模型，不修改主库材料。结果如下。

| 控制 | 实际结果 |
|---|---|
| 八项全局观察身份与四项年度差额 | 通过；差额与上表算术核对相符，跨公司排名始终为空 |
| 同一用户更换为复核角色、另一租户导出 | 分别拒绝为 403、404；没有因角色不同而允许自审 |
| 退回、修改采用与假设、重提、独立复核 | 新快照形成；按旧快照 ID 导出的对象与修改前逐字段相同 |
| 临时事实文件被修改或删除 | 新提交均拒绝为 409；旧快照仍可导出且内容不变 |

这是对真实样例材料和软件控制的验证，不是新增模型成绩、金融解释质量评分或真实机构用户验收。

页面初版发现三项 P2 问题，均已复读确认修复：一是重提后只显示当前快照，现返回按任务和租户核验的历史目录；二是身份切换未清空旧身份标签及建立任务表单中的自由文本，现连同隐藏私有内容清理；三是“披露金额”列显示归一后的 PPE 支出正数，现改为“计算用金额”，明示流出绝对额，保留原表括号核查入口，比较栏目改用“固定资产现金支出”。

目录修复后又在主工作区真实实现上运行一个针对性控制：退回重提形成两条快照目录，两条 ID／摘要分别匹配可导出的不可变内容。本顾问另外查看了主开发生成的桌面、窄屏截图及 `artifacts/research-task-ui-verification.json`；截图仅有公开样例与模拟身份，没有密钥或原页全文。真实浏览器操作由主开发执行，不作为本顾问独立重复验收的成绩。

主开发在实际下载时发现另一项真实失败：前端把响应解析后再次 `JSON.stringify`，会把 `792.0` 写成 `792`，导致下载内容按 Python 规则复算时与快照摘要不符。现下载保留服务器响应原文；仍先验证响应、状态和身份代际，再把原字符串写入文件。本顾问已复读此修复，没有看到摘要或身份保护被绕过。最终浏览器下载文件的重新核验由主开发记录，不能把此前临时数据库对象一致当成下载文件已验证。

迟到响应已有身份代际检查，动态文字采用 `textContent`。实际材料响应仅包括八项事实、必要坐标、行名与短范围依据、来源及规则元数据；未包含整份 PDF、整页图片、完整 OCR、密钥或绝对本地路径。响应材料的来源核验和用户核查记录仍是不同状态，不能因 OCR 实验通过就自动采用。
