## 为什么做这组附件

上一轮可以指出经营现金流增加或减少，但只有总额不能说明变化构成。本轮把同一张合并现金流表的完整调节行接进研究底稿，帮助分析员定位下一步该查什么：净利润变了多少，哪些调节行抵消或放大了差额，原文在哪里。它能减少手工转录和漏行风险，但没有真实用户效率测量，也没有建立经济因果识别。

附件的准确名称应是“登记资料的会计核对与年度差额分解”。残差为零不证明披露真实、不证明企业健康，也不代表逐项人工采用或审批通过。原有八项事实的采用决定仍单独控制年度比较；即使某项 CFO 被拒绝，附件可以供阅读，但不能因此恢复被阻断的计算或把候选解释改成已证实。

## 冻结和人工判断的边界

1. 新附件以独立版本冻结来源集合、完整行身份、登记资料和计算摘要。源文件变更或计算规则与旧记录不匹配时拒绝新提交；既有快照不依赖在线文件重建。
2. 默认不启用附件时，创建请求的幂等规范内容不加入新 `false` 字段；旧任务的 v1 内容与历史导出保持不变。v2 才携带附件，不能通过读取时补默认值改写旧快照。
3. 附件要在页面和导出中明确“登记资料会计核对、未逐项人工采用”。复核确认的对象是包含此边界的冻结底稿，不把残差零直接显示为“来源验真”或“经营原因已证实”。
4. 复核者看到的是提交时的附件和摘要。退回重提形成新快照，旧附件、旧复核意见和旧导出可重现；离线检查器需要分别支持 v1／v2，不能默默丢弃未知字段。

原文分母、分类和独立求和已交两个实现代理与主开发。

先完成了有实际旧版本依据的兼容控制：从 Git `fc8a683` 读取旧存储实现，在临时数据库中创建、采用、提交及独立复核 v1 任务，再用本轮存储实现读取同一数据库。旧导出的规范 JSON 字节保持相同；省略新开关和显式传 `false` 两种重试都命中原幂等任务；扩展后的离线检查器仍接受未改写的 v1 快照。此控制没有改主数据库，规范 JSON 对照不替代实际浏览器下载验证。
