# 金额符号诊断与独立误放行控制

2026-10-25。这一轮处理一个已观察到的具体问题：AMD 公开证据中，`$5,539` 和 `$3,787` 的完整 OCR 词框包含美元符号，向金额参考框左侧多出一段。旧规则保守地标为不足，其余日期、单位和行名检查一致。新规则尝试解释这种完整货币金额，旧结果继续保留。

这不是新的 OCR 或新发行人盲测。材料来自已经看过的 AMD 固定报告，模型不重新运行，参考金额也不发送给识别器。已有 14 项事实全部重新计算，不只展示两个发生变化的现金项目。

## 必须防住什么

把美元符号识别进同一个词框，有时只是版面问题；把其他币种、负号、旁列数字或额外文字忽略掉，则可能把错误数字放行。检测不能为了匹配参考值而删字符、截正确子串或挑一个词。

核心规则由 [currency_evidence.py](../../creditlens/currency_evidence.py) 实现；本分支独立写控制条件、输入及报告计算。条件先明确“该通过还是不能通过”，然后运行候选规则；程序不按候选结果生成期望，也不在失败时删题或把期望改成通过。

独立复核确实找到了一个遗漏：`C`、`CAD`、`HK`、`EUR` 若位于 `$` 金额旁的另一父行，而守卫只找数字或符号，就可能被忽略。这几项被补入控制清单，分别保留有词框和无词框的情况；修复针对未归属邻近文字的检查，不修改旧发布报告。这样的控制针对这次规则问题，不代表覆盖了所有提示攻击或金融文档格式。

## 34 项手工控制

所有控制使用单独手工构造的 `Fact` 与 `WordPage`，不是修改真实企业披露，也不冒充真实 OCR 输出。它们独立于 AMD 的事实 ID，因此测试即使使用一页一个事实的合成发布源，仍会执行完整控制集。

| 类型 | 应有行为 |
|---|---|
| 完整 `$1,234`；同父行分开的 `$` 和 `1,234` | 数值、位置与其他字段完整时可以一致；原本就一致的拆词情况不算新关联成果 |
| 负值 CFO 参考与 `$(1,234)`、`$-1,234` | 正确保留负号，可以一致；不能把所有负数一概拒绝 |
| 正值参考遇到负号／负括号；负参考却没有负号 | 不能一致 |
| 残缺括号、错误数字、两个金额拼在一起 | 不能通过截取或字符修补变成一致 |
| `€`、`¥`、`C$`，以及分离的 `C/CAD/HK/EUR` 前缀 | 不能仅因含 `$` 或数字相同就认作登记的 USD |
| 金额框跨列、邻近额外数字、负号、右括号或币种父行 | 必须保留疑点；无词框父行不能被静默丢弃 |
| 父行低置信度、父词文字不守恒、重叠父行或无词框 | 不能获得自动一致 |
| 年份错误、单位缺失或单位口径错误、金额缺失 | 金额关联不能消除其他字段的冲突与不足 |

共 4 项正控制、30 项反控制。每项结果都包含中文题名、修改说明、预期、完整合成输入及摘要、旧日期规则结果、新金额规则结果、非金额字段是否原样保留，以及是否满足预期。失败也留在报告里。

这些数量是软件控制，不是 34 份文档、34 家公司或模型准确率。正确负值参考的改变只发生在明确标注的合成 `cfo` 事实中；真实 AMD 参考从未改写。

## 报告如何防止悄悄换结果

[currency_diagnostic.py](../../creditlens/currency_diagnostic.py) 先通过已发布发行人快照验证原报告与冻结清单，再核对读取到的原始字节摘要、参考包和 OCR 配置。重建保留下来的完整父行及其全部词，逐项重算旧日期结果与新货币金额结果。

新结果必须保留旧金额检查，日期关联及所有非金额字段逐字段不变。发布验证重新计算每项证据、状态、理由、输入、预期及汇总；只改计数或保留同样通过数不能混过去。规则与实现文件记录规范换行后的 SHA-256，范围不包含无关的 UI 样式文件。

公开入口：

- `build_currency_diagnostic(root)`：重新构建全量诊断与控制结果。
- `validate_currency_diagnostic(root, report)`：逐字段复算并校验报告。
- `currency_diagnostic_view(root, report)`：同时返回已验证诊断及产生它的同一个发行人快照，供只读页面使用。
- `control_catalog()` 与 `synthetic_control_inputs()`：展示固定期望以及独立合成输入，供审阅和复现。

报告将真实材料和合成控制分开：`summary` 只统计已发布发行人事实，`controls.summary` 单独统计控制。`currency_association_applied` 只统计实际新增关联，旧规则本来一致的事实不会自动计入它。

## 能证明什么，仍不能证明什么

公开证据复算只核验已经保留的父行与词。新规则会检查扩展邻域及其他年份列，旧的精简证据不保证包含所有新增检查所需内容，因此还要用本机保留的完整 `ocr-words`／`ocr-lines` 单独复算全部事实，核对父行来源索引与全部结果。完整 OCR 审计与 API 的公开片段校验分开记录。

完整原 PDF 已按存储要求清理，本轮不自动重下。即使完整 OCR 对照通过，也不宣称重新校验过 PDF／图片字节，不证明材料真实性或原模型执行来源，更不代表人工批准。完整 OCR 不上传到公共仓库。

## 如何重跑

```bash
python -m unittest tests.test_currency_diagnostic -v
python scripts/evaluate_currency_diagnostic.py
```

脚本默认仅新建 `.run/reproductions/currency-diagnostic-report.json`，已经存在就拒绝覆盖；可以指定该目录下另一个新的 JSON 文件名。所有来源和结果校验在写入前完成。原发行人报告、参考包、模型权重和公开冻结文件不被修改，不下载文件、不启动模型、不收费。

本分支实际运行了 10 项诊断契约测试，全部通过；对已发布 AMD 公开证据的内存复算覆盖全部 14 项，旧日期规则为 12 项一致、2 项不足，新金额关联后为 14 项一致，其中只有 2 项实际应用新关联，非金额检查均未改变。34 项合成控制全部符合固定期望。该结果尚不包含本轮独立的完整 OCR 核验，发布与该核验由主分支整合记录。

后续应继续用未参与规则调整的新材料评估，并单独报告合理拒绝与错误放行；不能把这次已观察问题的修复包装成金融多模态模型的泛化提升。
