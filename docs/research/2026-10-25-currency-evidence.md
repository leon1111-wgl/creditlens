# 货币符号与完整金额的独立诊断

日期：2026-10-25。新规则：`currency-evidence-1`。入口：`crosscheck_currency_fact(Fact, WordPage, min_confidence=0.9)`。

财务研究中的一个符号错误就可能改变后续计算。负号丢失会把现金流出看成流入；币种前缀归错列也会让本来不能比较的数值进入计算。本实验只处理一类已发现的问题：识别模型把货币符号与金额合成一个完整词，导致词框向左超出已登记的纯数字区域。

这是一项读取已保存 OCR 结果的后处理诊断。没有下载新材料、运行 OCR、训练模型或调用付费接口，也没有改旧字词规则、日期规则、事实包或冻结报告。

## 已观察到的问题

AMD FY2025 官方年报的资产负债表物理第 74 页，现金及现金等价物的两个 OCR 词分别为 `$5,539` 和 `$3,787`。原登记金额框仅包含数字；识别词框因包含美元符号，向左比旧规则容许范围多伸出一段。旧规则因此保留 `insufficient / merged_or_misaligned_region`，没有把模型数值自动采用。

本实验已经看过这两处材料及失败结果，属于已观察开发诊断。不能称为新增发行人盲测、独立样本外准确率，或模型识别能力提升。

## 新规则如何决定能否关联

规则以旧日期诊断为基线，完整保留其结果和 `legacy_amount`。只有金额检查恰为左侧合并越界、旧守卫为空、父行和候选词唯一时，才尝试解释这一不足。

1. **先固定候选位置。** 沿用已有金额框的空间命中，不按期待金额查找字符串；只处理完整的单一词。父行与词逐字符守恒，词框必须在父行中，父行分数达到已有门槛。
2. **确定列的边界。** 检查同排至少两个完整四位年份父行与词。每个表头都要守恒、独立、不重叠、不重复且分数足够；用表头中心之间的中线建立列界，再与登记期间框的横向范围取交集。当前列按空间命中选择，不按期待年份或金额选择。年份表头旁未归属的文字、数字或符号同样会阻断。
3. **只解释左侧延伸。** 右侧、上方和下方仍使用原有 8 点范围，完整父行和完整金额词都必须留在唯一列内。数字框、年份框与期间框也必须在同一列，行名位于金额左侧。没有足够的相邻表头、越列或几何关系不明时继续保留不足。
4. **检查邻近未归属内容。** 以完整金额词的邻域检查其他父行和词，而不只检查较小的原数字框。任何非空外部内容都可能是符号、币种前缀或脚注，即使其 `words=[]` 也不能丢掉。该守卫使用已有 8 点间隔及垂直重叠规则，不按期待文字设置放行名单。
5. **解析整个货币金额。** 支持明确的完整形式，例如 `$1,234`、`$-1,234`、`$(1,234)`、`($1,234)`。严格保留括号、负号及零的符号，不切出碰巧匹配的子串，不修补 OCR 字符。多余数字、错误逗号、百分号、残缺括号、额外币种前缀或格式不支持都拒绝。
6. **最后比较有符号金额。** 候选、语法和空间归属确定后，才与登记的原始有符号金额比较。`$` 仅与已登记的 USD 元数据做一致性检查；它本身不能区别美元、加元、港元等币种。没有独立新增币种证明，旧单位检查也没有被替换。

失败尝试保留旧金额检查及全部证据，并给出明确的拒绝原因。成功时只把金额项改为一致。年份、期间、单位、行名、分区和日期关联元数据逐字段不变，`automatic_approval` 始终为 `false`。

旧金额已经一致时，本规则不重做货币检查。此类 `applied=false` 结果不能包装成“通过了新的币种验证”。新模块导出稳定的 `CURRENCY_REASON_LABELS` 中文原因映射，供界面说明失败。

## 审查中发现并修复的问题

初稿只对邻近数字、负号、括号和货币符号做额外守卫。独立审查在真实保存页旁加入单独的 `C`、`CAD`、`HK` 或 `EUR` 父行，发现字母前缀会被忽略；`C` 与 `$` 可能共同表示其他币种，不能放行。

修复将该狭窄邻域内的所有非空外部文字纳入守卫，包含没有词投影的父行。测试覆盖前缀有词和无词两种情况，并增加年份表头旁未归属文字的阻断。该修复只在新关联尝试中生效，不改写旧结果。

另增加合法负值正例及负零控制：有完整负号或括号的金额可以按负值核对；当参考显示 `(0)` 而识别只剩 `$0` 时，也不能因为数值相等就认为符号完整。

## 本实验实际验证

使用保存的两页完整 `WordPage` 重算 AMD 原有 14 个事实：

| 原日期诊断 | 新独立诊断 | 数量 | 说明 |
|---|---|---:|---|
| 不足 | 一致 | 2 | 两期现金及现金等价物；完整符号、父词及列界均满足新条件 |
| 一致 | 一致，未触发新规则 | 12 | 原结果保留，不称为新增货币验证 |

所有 14 项的非金额检查和原日期关联元数据逐字段不变。公开报告中的必要父行片段也用于回归，但公开片段本身不能替代完整页的遗漏证据检查。

本地保留的完整词结果字节摘要：

- 第 74 页：`d74970051ff1c9781ebc335b7546a0b5af911e81b3d28cc98b64eac696942d39`。
- 第 76 页：`751e9aac054803e3e0a91f0472a6d1933b752702b9f4b09842bbf13eeea80f78`。

16 项专属测试通过，包含完整正值、三种完整负值写法、负号或括号丢失、负零、错误金额、额外数字、错误币种、分离字母前缀、低父行分数、父词冲突、缺词、跨列、重复候选、缺失或错误相邻表头、未通过的期间/单位/行名，以及已观察的 AMD 必要证据。

复查命令：

```powershell
python -m unittest tests.test_currency_evidence
```

本结果说明这套受限规则能解释已观察的两处完整货币词，不说明所有货币布局或未知公司文档都可处理。词位置仍来自原 OCR 适配器的识别序列投影，不是本实验新增的字符定位。跨页表格、没有可靠表头、多个词共同组成金额及其他币种的通用处理均未由本实验建立。即便诊断一致，事实仍需要既有的采用理由和独立复核流程。

## 用保留的完整 OCR 检查公开片段是否遗漏

新增只读工具 `scripts/verify_currency_raw.py`，仅读取已保存的两页 `ocr-words-*.json` 和 `ocr-lines-*.json`，不读取或重新下载 PDF、整页图片，不运行 OCR，也不写入完整识别文本。

工具先验证旧发行人报告、冻结清单及来源登记，再重算新版公开货币诊断；随后逐页核对完整 JSON 的规范哈希、类型、页尺寸、行数、字词到父行投影，以及公开父行的 `source_line_index` 是否准确指向完整页。最后使用完整页重算旧行级、字词、日期和新货币结果，映射父行索引后逐字段及摘要比较。新 `column_bounds.current_header_index` 也参与映射，词在父行内的 `word_index`、`year_word_index` 等不会误映射。

```powershell
python scripts/verify_currency_raw.py --raw-dir .run/reproductions/issuer-evaluation --report artifacts/currency-diagnostic-report.json
python -m unittest tests.test_currency_raw
```

`--raw-dir` 是发行人 ID 子目录的上一级；本实验实际文件位于其 `amd-fy2025/` 下。`--report` 也可以指定未发布的本地候选报告，核验成功不代表批准发布该候选。默认 stdout 只输出摘要、逐事实状态和哈希，不含完整 OCR。篡改、漏行、重复 JSON 键、非有限数、非法索引、类型改写或新报告不能复算时，返回结构化拒绝及非零退出码。

本实验实际 CLI 核验通过：第 74、76 页分别有 101、215 个完整 OCR 父行；公开片段分别保留 19、16 个，共 35 个父行，14 个事实全部在映射后精确一致。核验的货币诊断报告字节 SHA256 为 `625909663cbd55ad92e384a279f2b05690e405bd27980a78d507ce3b04afb964`。

9 项专属测试通过，包含带真实索引偏移的完整双列合成页、JSON 空白兼容和类型/内容篡改拒绝、父行投影、非法索引、漏行、公开资料和新报告变更、只读 CLI，以及一个关键反例：给完整页加上公开片段未包含的 `CAD` 父行时，即使片段仍通过，完整页重算也会拒绝一致性结论。

这项检查证明的是保留下来的 JSON 与冻结登记及当前规则一致。它**未检查 PDF 或图像字节，未证明原始模型执行真实发生，也没有增加独立评测样本**。相关字段在摘要中明确为 `false`，公开 API 仍只承诺公开片段的复算范围。
