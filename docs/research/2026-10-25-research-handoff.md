# 研究底稿怎样保存、提交与交接

日期：2026-10-25。本文说明第18轮新增的研究任务存储模块及专属测试。材料比较、API 与网页由同轮其他分支接入；本文的验证范围不代表这些部分已经完成整体验收，也没有运行新模型。

研究员要交接的不是一张数字表。下一位同事需要知道：研究的问题是什么，用了哪一版材料，哪些数字被采用，哪些被排除，解释还有什么缺口，以及自己确认的到底是哪一个版本。本轮将这些内容存成同一份不可变底稿，避免数字还是旧版、解释却被后来修改的情况。

任务沿用[上一轮设计](2026-10-25-enterprise-research-design.md)。当前材料是微软、苹果各两期的经营现金流和固定资产现金支出，共八项观察值。这是跨公司工作流样例，尚未建立严格同行基准；不能因为都叫 FY2025 就排名，也不在这里增加金融预测或自动因果结论。

## 这次实现了什么

[research_task_store.py](../../creditlens/research_task_store.py) 提供独立的 SQLite `ResearchTaskStore`，复用已有 `Actor` 身份，由服务端材料模块取得固定材料。客户端只能提交研究问题、选材理由、观察值的采用决定和待查解释，不能自己填写租户、替换来源或传一个任意文件路径。

一次任务按以下顺序完成：

1. 分析员建立任务。系统保存当时的材料、版本摘要和服务端冻结时间。建任务的幂等键防止重复点击产生两份任务；同键换内容或换创建身份返回冲突。
2. 分析员对八项观察分别选择采用或拒绝，并写明理由。观察 ID 包含公司、披露文件哈希与原事实 ID，引用必须属于当前任务，不能仅用 `cfo-2025` 连接不同公司。
3. 分析员可以登记零到三个候选解释。状态只有“待查”和“未评估”，引用只表示关联材料，不代表已经证明因果关系。没有依据时允许不填解释。
4. 提交前，全部观察都要有决定和理由，并写清材料覆盖与局限。被拒绝的观察可以作为缺口交接；不要求把每项都标成采用才允许提交。
5. 系统重新检查当前注册材料及比较结果，再将问题、选材理由、材料、决定、解释、比较结果和局限一起存入快照。提交之后不能改字词或决定。
6. 另一身份确认或退回。创建过、编辑过或提交过这个任务的任何主体，都不能只切换成 reviewer 角色来复核自己的工作。
7. 退回后可编辑并重新提交，产生新的快照。旧快照、旧意见和旧导出仍可查看，不用后来数据覆盖之前的研究记录。

历史模式目前明确拒绝，错误码为 `historical_version_unverified`。当前材料模式也不接受一个历史 `as_of` 日期。财务期间、报告披露事件、今天取得的文件和历史上可得的文件版本，是不同的概念；本模块没有把当前比较列变成历史时点数据集。

## 接口与保存内容

以下是 Python 服务接口；网页路由由主分支接入。请求模型均拒绝未知字段，并限制文本长度、列表数量、重复记录、无效状态和非整数版本号。

| 接口 | 内容与约束 |
|---|---|
| `list(actor)` / `get(task_id, actor)` | 只返回同租户任务。读取允许 viewer、analyst、reviewer；跨租户按不存在返回 |
| `create(actor, payload, idempotency_key)` | analyst 建立固定材料任务；相同请求重试返回同一任务当前状态，不要求重新取得材料 |
| `update(task_id, actor, revision, decisions, hypotheses, coverage_note)` | analyst 在 draft 或 returned 状态修改整组研究内容；未知或重复引用被拒绝 |
| `act(task_id, actor, revision, action, note, snapshot_sha256)` | submit、approve、return；复核操作必须匹配当前快照摘要及任务版本 |
| `get_snapshot(task_id, snapshot_id, actor)` | 同时检查任务、快照及租户，不能拿另一个任务的快照 ID 读取 |
| `export(task_id, actor, snapshot_id=None)` | 默认导出最近一次提交；可以指定旧快照。只导出所选冻结内容及其复核意见，不混入当前草稿 |

供 API 复用的模型是 `ResearchTaskCreate`、`ResearchTaskUpdate`、`ResearchTaskAction`，以及嵌套的 `ResearchDecision`、`ResearchHypothesis`。

`get` 返回任务字段、服务端材料 `bundle`、当前编辑内容、`comparison`、`contributors`、`events` 和 `review_history`。另有 `snapshots` 目录，按提交顺序列出每个快照的 ID、摘要、创建时间、提交人和版本，供页面选择旧底稿。`snapshot` 为 null 或下面的对象：

```text
snapshot
  id / sha256 / created_at / submitted_by / revision
  content
    task_id / tenant_id / task_revision / store_version
    question / selection_reason / material_mode / as_of
    bundle_id / bundle / bundle_sha256 / materials_frozen_at
    decisions / hypotheses / hypothesis_scope
    coverage_note / comparison / contributors
    submitted_by / submitted_at / automatic_approval=false
```

导出中的 `review` 与 `review_history` 只引用所选快照；不会拼上当前新版本的批准状态。首次提交前没有冻结底稿，导出会拒绝。审批意见保存在任务的历史记录中，冻结内容本身不被审批动作改写。

## 为什么旧记录不会被后来资料覆盖

建任务时复制服务端材料并记录规范 JSON 的 SHA-256。提交时再取注册材料，摘要发生变化或文件缺失都会阻止新提交；旧任务不会悄悄换数。读取旧任务、快照和导出只使用已保存内容，不依赖源文件此刻是否存在。

新的采用决定会重新计算比较结果；提交前再次核算，结果或规则发生变化时必须先更新可编辑任务，不能静默冻结另一种计算。已经提交的快照继续按其保存版本展示，不因当前规则升级而重算。

写操作在 SQLite `BEGIN IMMEDIATE` 事务中执行，任务更新另带 revision 条件。快照插入、任务状态、复核记录和事件一起提交或回滚。忙锁返回可重试冲突；陈旧页面不能覆盖较新内容。此处是本地事务与软件控制，没有完成高并发负载、备份恢复或机构生产部署验收。

存储校验使用内容摘要，能够发现内容与记录摘要不一致。它不是外部签名存证，无法防住有数据库写权限、同时重写内容和全部摘要的管理员。默认 demo 身份只是操作流程演示，不是真人认证；正式身份认证、SSO 和外部审计仍需另行建设。

## 已运行的专属验证

命令：

```bash
python -m unittest tests.test_research_task_store -v
```

20 项测试全部通过。其中 18 项使用临时 SQLite 和明确标注的合成八项观察，材料与比较函数由测试替身提供；另外 2 项调用真实注册材料模块及微软、苹果的固定事实包，验证八项观察的交接、四项公司内年度计算，以及自定义材料根目录缺文件时的处理。未重新读取原始 PDF 或运行 OCR，不冒充模型评测。覆盖内容包括：

| 场景 | 验证结果 |
|---|---|
| 完整提交、独立批准、导出 | 问题、材料、采用理由、解释、计算与局限共同冻结，导出引用同一快照 |
| 退回、修改、重新提交 | 生成新快照；指定旧快照的内容及旧复核结果保持相同 |
| 切换角色自审 | 创建、编辑或提交过任务的主体均被拒绝 |
| 同键重试与并发 | 同键同请求只建一份；不同内容返回冲突；同 revision 并发更新只成功一次 |
| 跨租户、跨任务快照访问 | 读取与导出均被拒绝 |
| 缺一项决定、缺局限说明 | 提交被阻止；全部拒绝但说明缺口、零假设可以提交 |
| 公司内同名事实、未知或重复引用 | 不靠短 fact ID 连接数据，错误引用不保存 |
| 材料变更、删除或比较规则改变 | 阻止未经确认的新提交；旧快照继续可读 |
| 历史模式、伪造字段、空理由、非法状态与非有限输入 | 请求被拒绝，不产生新版本或事件 |
| 草稿对象被外部修改、保存内容损坏、数据库忙锁 | 返回对象修改不影响数据库；摘要不一致阻断读取；忙锁返回冲突 |

这里证明的是任务保存和交接控制，以及真实注册事实包与存储服务的联动。网页操作、API 与导出的一致性，由主分支整合后另行验证；尚未完成的部分不能据本文件写成已上线。也没有真人试用、节省工时、解释准确率或投资效果数据。

下一步应在同一任务上完成真实材料与页面交接验收，再补附注解释证据、材料更新差异和更完整的历史版本。无需为了这个存储流程租 GPU，也没有新增付费服务。
