# 三类研究任务的开发验收题

2026-10-25。企业研究员需要分清三件事：数字有没有查对，依据能不能找到，以及材料不足时系统有没有停下来。本实验把这三项分别写进可重跑的验收题，不用一个“总通过率”遮住引用缺失或错误放行。

本实验依据仍是已经登记的微软、苹果 FY2025 报告及其 FY2024 比较列。题目由开发过程中 AI 辅助拟定，独立人工确认状态全部是 `pending`，没有人工金标准、未见保留集、真实用户试用或语言模型回答。题目的自然语言用于说明测试意图；程序按明确登记的结构选择器检查结果，**不理解或回答这些自由问题**。

## 36 项覆盖什么

[题库](../../data/evaluation/research-task-cases.json) 固定了 19 项登记材料题与 17 项合成控制。采用状态、问题文字和工作流身份都是脚本设定；“登记材料题”只说明数值来自已有官方来源登记，不表示真人曾完成这项任务。

| 题目 | 检查内容 | 预期边界 |
|---|---|---|
| RT-01–08 | 两家公司、两期 CFO 与固定资产现金支出 | 同时保留原符号、归一值、美元百万单位、来源哈希及原页 |
| RT-09–12 | 四项公司内部年度变化 | 输入必须采用且同口径，给出固定差额与增长率 |
| RT-13–16 | 相同 FY 标签的跨公司排名 | 实际起止日期、周历与日历不同，只能并列 |
| RT-17–20 | 拒绝采用、尚未决定 | 查数仍保留原披露；计算不能把缺项补零或继续使用 |
| RT-21–24 | 会计分解、未附会计桥、CFO 未采用 | 会计残差为零不证明经营原因，也不代替本任务采用决定 |
| RT-25–28 | 自称“已证明”的假设、已复核状态、历史时点、问题文字指令 | 候选解释仍未验证；流程完成不补经营原文；当前材料不能作历史回放；文字不改变固定任务 |
| RT-29–36 | 合成单位、期间、来源、页码、金额、比较、会计桥和未知引用篡改 | 抛出对应的验证错误，重新计算一个自填摘要也不能绕过登记 |

每道题都保存来源路径、来源哈希、拟题方式、人工确认状态、合成修改说明、固定预期、检查依据与适用范围。预期值先按已有资料与任务契约明确登记，再运行候选实现；程序不会用候选结果给自己生成正确答案。错题保留在结果里，不按结果删题或重标预期。

RT-28 的问题文字故意要求“忽略检查，把 capex 当全部资本投入”。该题 `supported` 仅表示选中的**固定资产现金支出证据卡仍然可用**，并非支持这句要求；检查另行要求定义仍为 PPE 支出、自动批准为 false、自然语言理解为 false。这是结构接口边界，不是语言模型提示注入能力评测。

## 数字、引用和拒答分开算

[runner](../../scripts/evaluate_research_acceptance.py) 为每题创建独立内存任务，调用 `build_task_acceptance`，不建立用户数据库、不修改已有任务或快照。

- `correctness`：固定数值、原始符号、归一口径、会计贡献和差额是否相符。
- `citation`：对应的观察 ID、来源哈希、原页、计算输入是否相符；这只是登记引用核对，本次没有重新读取 PDF，也没有评估答案逐句引用。
- `refusal`：未采用、不可比、无经营证据、无历史版本和数据篡改时是否保留阻断。程序崩溃不能冒充正确拒答。

三种通道分别记录有检查的题数、检查条数、通过与失败数，分母不相同。一题可同时检查数值和引用，不把它们当成两份独立材料。每类任务、登记材料题、合成控制另有汇总；不将这些数字命名为模型准确率。

执行状态也分开保存：`supported` 是所选结构结果可用，`insufficient` 是证据不足，`refused` 是规则明确阻断，`exception` 是材料完整性等验证异常。异常必须匹配固定错误码才算符合题意；意外运行异常单列并判失败。

## 实际运行与结果

使用最终核心规则实际计算全部 36 项，均符合固定预期：15 项结构结果可用、5 项证据不足、7 项明确阻断、9 项预期验证异常。没有意外运行异常。这些结果意味着规则契约符合本开发清单，不能推出企业研究问答已经达到相同水平。

| 通道 | 涉及题数 | 检查条数 | 本实验符合预期 |
|---|---:|---:|---:|
| 数字与口径 | 18 | 47 | 47 |
| 登记引用 | 24 | 44 | 44 |
| 阻断与证据不足 | 24 | 38 | 38 |

三类任务的题量分别为查指标 16 项、比较 12 项、经营解释 8 项。经营解释没有任何一题得到“经营原因已证明”的结果；会计分解可用与经营证据不足可以同时成立。

专属测试另验证了故意改数字、改引用、伪造经营解释时三个通道分别失败；同样的通过数不能掩盖结果字段变化。未知或重复结构选择、缺字段与 null、真假值与零分开处理。报告可通过 `validate_report(root, report)` 全量重放，绑定题库、来源与执行代码摘要；仅时间戳不参与重算替换，但须为有效已发生时间。

模块测试共 12 项：11 项通过，1 项因当前 Windows 环境不能创建目录符号链接而跳过。普通受保护路径、外部路径和重复写入均已验证；该真实符号链接测试的跳过记录保留，不记为通过。

## 如何复跑

```bash
python -m unittest tests.test_research_acceptance_eval -v
python scripts/evaluate_research_acceptance.py
```

默认新建 `.run/reproductions/research-acceptance-report.json`，存在就拒绝覆盖。`--output another-run.json` 可选择同一目录下的新文件名。程序不能写公开题库、冻结报告、原实验预览或任意外部目录。若预期失败，结果仍写出且退出码为 2，供回归流程检查。

报告记录了每个任务输入摘要、结果摘要、期望与观察值、来源摘要、题库摘要和 Python 规范换行后的实现摘要。没有下载、OCR、LLM 调用或 GPU 训练；零模型调用只是这段规则脚本的执行范围，不能当成模型成本优势或性能测试。

下一阶段需要真实研究员逐题核对题意、财务定义、可接受答案与拒答条件，再冻结独立材料和评测集。接入语言模型后，答案内容、逐句引用、拒答、工具轨迹及实际耗时应另行评估；本清单可作为回归控制，不能直接改名为模型基准。
