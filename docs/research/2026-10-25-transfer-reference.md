# 先固定 NVIDIA 参考，再看模型能否迁移

日期：2026-10-25。本轮交付官方财报的 16 项参考与重建脚本，没有运行 OCR，也没有根据识别结果修改参考框。模型推理须等主分支核查参考、冻结算法和配置后单独进行。

## 为什么换一家企业

已有微软、苹果案例能说明流程可运行，但不能证明换一家公司仍能处理正确。企业真正关心的是：新报告的日期表头、数字列和跨行标签变了，系统会不会把看不清的数字当作已确认事实。我们先增加 NVIDIA 两页材料，让既有行级和字词级规则面对新的表格，再保留所有不足与冲突。

岗位和业务依据沿用 2026-10-25 的[项目与岗位研究](../01-product-and-career.md)及[文档 AI 方案](../08-document-ai-and-governance.md)。本轮没有新客户访谈、竞品性能排名或市场统计。它补的是金融文档模型评测的数据与证据基础，不把增加一家公司包装成通用多模态能力。

这仍是**新发行人的已知位置开发检查**。参考页和字段已经选定，框来自文本层及原页检查；不是随机盲测、双人人工标注或通用表格抽取基准。

现金流开支行的标签跨两行，包含无形资产。参考框覆盖完整标签，不把它改写成“仅固定资产购建”，也不将这批参考接入已有简化自由现金流计算。`capex` 仅是现有事实字段的兼容名称，中文标签和原文位置保留完整范围。

`short_investments` 同样沿用已有字段名称，依据是这项有价证券列在流动资产分区；本轮没有据此判断每项证券的剩余到期期限。

短期债务行暂不评分：FY2025 单元格是横线，现有 `Fact` 数值合同不能无条件把横线解释成零。本轮两个年度都不纳入该行；这是运行前的明确范围限制，未尝试 OCR 后再筛选。不把缺失值补成零，也不据此计算总债务。

Note 1 的会计期间说明位于 PDF 物理 149 页、10-K 印刷 57 页：采用 52/53 周会计年，FY2025、FY2024、FY2023 均为 52 周。现金流 FY2025 的区间为 2024-01-29 至 2025-01-26，FY2024 为 2023-01-30 至 2024-01-28，首尾包含共 364 天。资产负债表只登记期末，不附加虚构期间起点。

## 参考是怎样建立的

**后续更正：** 本节记录的是 v1 构建过程。首次 OCR 后发现这里的字符坐标未扣除可见页面原点，参考框整体错位，因此 v1 已标记为无效参考，原文件和哈希仍保留。通用坐标修复及裁切字符拒绝已另行实现；[v2 参考](../../data/examples/nvda-fy2025-transfer-v2.json) 保留同一组财务值，只修正坐标与解析版本。原生 PDFium 坐标核验见[几何记录](../../artifacts/document-geometry-verification.json)，失效及诊断范围见[第 14 轮](../iterations/2026-10-25-14.md)。下方原先的重建相同结论只说明可重复，不能证明坐标正确；查看原页数值没有替代坐标叠加验收。

[构建脚本](../../scripts/build_nvda_reference.py) 用 PDFium 读取数字 PDF 的文字与字符位置，按预先写定的表名、单位、日期列和行标签定位。金额不是定位参数。两行开支标签按原文相邻行合并成参考区域；没有 OCR、语言模型补数字或按识别分数移动框。

原页以 scale 2 无标记渲染。本轮已逐页查看原图，并核对所有 16 个数值、符号、年份、分区和跨行标签。主代理另行查看原图并核对数字清单；独立研究顾问核查来源、日期、周历和许可。以上属于一个参考建立流程加 AI 代理复核，**不是两个独立人工标注者**。本轮没有声称参考是无误的金标准。

[参考文件](../../data/examples/nvda-fy2025-transfer.json) 为 UTF-8、LF 格式，原始文件 SHA-256 为 `5911a70e85b7855172abafa8fdd7324baa3653dd8e615ade3fd268af0be5ed59`；规范化 JSON 摘要为 `e6ade79add20c322074bb5e1c3f4883084c09dc1665984fabeced73469894339`。两者口径不同，冻结清单中的 `pack_sha256` 使用原始文件字节。

使用已准备的 PDF 依赖可以重建本地候选：

```powershell
python scripts/build_nvda_reference.py --download
```

默认将完整 PDF 留在 `data/raw/`，参考候选与原页放在 `.run/nvda-reference/`，不自动覆盖公开参考。脚本逐项验证 `Fact` 数值与期间约束，拒绝不明确的单元格或移动后的标题／列位置。本轮已实际重建，并将结果与主代理独立列出的 16 个值及两组 52 周期间核对；使用 pypdfium2 5.14.0 与 PDFium 156.0.8076.0，版本记录在本地 `reference-pack.provenance.json`。第二次重建的参考字节和两张原图摘要均相同。独立 `TransferPack` 合同验证通过，旧 `CasePack` 正确拒绝这个非时点参考包，Markdown 文件链接检查通过。

缺少 PDF 时，下载只允许新建注册的 `data/raw/nvda-fy2025-annual.pdf` 缓存；指向其他位置的目录别名或已有下载元数据会被拒绝。已存在且哈希匹配的 PDF 可以从其他位置只读使用。输出继承统一路径保护，并排除新旧已发布页面预览目录，不能通过命令行选项覆盖它们。

主分支将在参考与运行器复核后冻结清单，绑定两个模型配置、金额解析与视觉规则、推理适配器及本参考文件。Python 文件按 UTF-8、LF 规范化后计算摘要；JSON 与 PDF、图片按原始字节计算。**本报告提交时还没有新发行人的推理结果，不能写成识别成功或泛化提升。** 冻结后无论结果一致、冲突还是不足，都要保留，不通过删题或按输出改框提高分数。
