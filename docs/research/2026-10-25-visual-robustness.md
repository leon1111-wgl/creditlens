# 页面稍微变糊，财务数字还会被正确关联吗？

日期：2026-10-25。分支：`feature/visual-robustness`；开发起点：`e164d39`。本轮已运行本地 CPU OCR，没有训练、付费 API 或 GPU 支出。所有变体和失败结果均保留；这是一项小型开发实验。

## 为什么做

分析员收到的财报可能经过压缩或图像处理。同一个数字仍然看得清，OCR 却可能把它和旁边的符号、年份列合在一起。如果系统只检查“页面里出现了这个数”，就可能把不可靠的结果交给后续因子计算。我们需要看到图像变化影响了哪些字段，并把无法确认的结果留给人复核。

本轮沿用 2026-10-25 的[岗位与业务调研](../01-product-and-career.md)、[文档智能方案](../08-document-ai-and-governance.md)和[独立实验建议](2026-10-25-advisory-02.md)。对应的工程能力是金融文档处理、真实模型推理、异常定位和评测治理。本轮没有新增客户访谈、招聘市场统计或竞品排名。RapidOCR、PaddleOCR 已提供识别组件；CreditLens 增加的是结果如何接受财务口径检查、如何保留失败证据的流程。企业减少多少返工，仍需业务任务测试。

## 运行前固定了什么

从既有官方披露开发案例中固定两页：微软 PDF 第 53 页现金流量表，6 项事实；苹果 PDF 第 34 页资产负债表，14 项事实。选择它们是因为已有负数、合并文字框、分段表头和报表分区问题，便于解释失效机制。这两页不是随机抽样，也不是独立盲测集。

[配置文件](../../configs/visual-robustness.json)在首次推理前写定。脚本还在本地保存配置快照，再开始识别；这不是第三方预注册。每页固定运行以下四档，没有根据结果调整参数，也没有只报告最好的档位。

| 条件 | 固定处理 | 尺寸与坐标 |
|---|---|---|
| 原图 `clean` | 使用原 PNG 字节，重新执行 OCR | 完全保留 |
| 轻度模糊 `blur_0_7` | GaussianBlur，radius = 0.7 像素 | 保留 |
| 降低对比度 `contrast_0_65` | Contrast，factor = 0.65 | 保留 |
| 压缩 `jpeg_60` | JPEG quality = 60、subsampling = 0，再解码为 PNG | 保留 |

JPEG 的 PNG 容器保留了压缩后的像素变化。没有旋转、缩放、裁切、局部遮盖或参考答案修补。图像操作依据 [Pillow ImageFilter](https://pillow.readthedocs.io/en/stable/reference/ImageFilter.html)、[ImageEnhance](https://pillow.readthedocs.io/en/stable/reference/ImageEnhance.html) 和 [JPEG 参数文档](https://pillow.readthedocs.io/en/stable/handbook/image-file-formats.html#jpeg)，它们是标准处理方法，不是本项目提出的新算法。

模型只收到完整页图路径，不接收参考金额、行标签或参考框。完整识别结果先写入本地文件，再用既有 `visual-evidence-1` 行级规则检查金额、年份、期间、单位、行标签及适用的报表分区。坐标根据实际图像宽高映射回 PDF point；原图和三个变体使用同一组规则。

## 实际结果

每档都核对同样的 20 项事实，共 8 次整页 OCR、80 项“条件 × 事实”结果。这里的“一致”表示与既有参考事实一致；它不是通用抽取准确率，也不是财报真实性判断。

| 条件 | 一致 | 冲突 | 证据不足 | 相比本轮原图的变化 |
|---|---:|---:|---:|---|
| 原图 | 17 | 0 | 3 | 对照 |
| 轻度模糊 | 18 | 0 | 2 | 1 项由证据不足变为一致 |
| 降低对比度 | 18 | 0 | 2 | 同一项由证据不足变为一致 |
| JPEG 压缩 | 17 | 0 | 3 | 状态未变化 |

微软每档都是 4 项一致、2 项证据不足；苹果原图及 JPEG 为 13 项一致、1 项证据不足，另两档为 14 项一致。原图本轮重跑的状态与已保存的基线一致。三个退化条件中均未出现“一致转为冲突或证据不足”，但样本与强度太有限，不能据此宣称模型已具备生产鲁棒性。

**有意思的变化来自苹果 2025 年现金及现金等价物。** 原图与 JPEG 的 OCR 把 `35,934` 和下一列的 `$` 合成一个框。数字虽然能读到，框跨出了金额区域，既有规则返回 `merged_or_misaligned_region`，保留为证据不足。模糊和降低对比度后，OCR 分别检测出金额与美元符号，金额框可以单独关联，状态才变成一致。已查看本地完整页图并核对相应 OCR 框，输入没有参考框叠加。

这说明轻微图像变化会改变检测分组。它不证明模糊会提高整体准确率，也不足以支持把模糊设为生产默认处理。四档结果都保留，不将每个字段最有利的一档拼成总成绩。微软剩下的两个不足结果也没有用参考答案补回。

八次 OCR 调用计时合计 16.7087 秒，不包含模型初始化、图像处理及文件读写；同机还有并行工作，不作为吞吐量或生产延迟基准。

## 怎样追查和复现

机器可读结果见 [visual-robustness-report.json](../../artifacts/visual-robustness-report.json)。其中记录两家发行人的原始披露链接、披露日期、PDF 哈希、事实包哈希、原图与变体图像哈希、OCR 结果哈希、完整状态转移及每项检查的状态。失败项另保留必要的观察文字和坐标；完整页图与完整 OCR 文本只保存在本地 `.run/visual-robustness/`，不进入公开仓库。

本次环境是 Python 3.12.14、RapidOCR 3.10.0、ONNX Runtime 1.31.0、NumPy 2.5.4、Pillow 13.0.0。检测与识别均实测为 `CPUExecutionProvider`，推理配置为 4 个 intra-op 线程、1 个 inter-op 线程。沿用基线固定的 PP-OCRv6 small 检测及识别权重，分别校验完整 SHA-256；缺少或哈希不同的权重会终止，不回退到云服务或自动换模型。许可与初次准备过程见[文档 AI 实验说明](../13-document-ai-experiment.md)。

在已按基线说明准备依赖与模型的仓库里，可先生成本地原始页图，再运行实验：

```powershell
python scripts/evaluate_document_ai.py --download --output .run/regenerated-document-ai-report.json
python scripts/evaluate_visual_robustness.py
python -m unittest tests.test_visual_robustness -v
```

第一条命令刻意把重跑基线报告写到 `.run/`，以保留已冻结的公开基线报告；该报告含时间与耗时字段，覆盖它会改变摘要，鲁棒性脚本会拒绝继续。渲染器版本变化也可能改变 PNG 哈希，应核验原因并另建实验版本，不能无提示地替换冻结输入。Windows 本轮复用主工作区的已准备页图，实际命令为：

```powershell
D:/acl-xwf/creditlens/.venv/Scripts/python.exe scripts/evaluate_visual_robustness.py --source-dir D:/acl-xwf/creditlens/.run/document-ai
```

结果文件的 `config_sha256` 是经过校验和默认值规范化后的配置对象摘要，不是配置文件的原始字节哈希。`source_report_sha256`、事实包与 OCR 摘要同样使用项目的规范化 JSON 摘要；图像、PDF 和权重使用文件字节 SHA-256。

新增 10 项测试已通过，覆盖配置与线程约束、禁止几何变换、原图哈希和尺寸检查、变换可重复性、OCR 输出长度不一致时停止、事实遗漏或重复时停止、状态迁移计数和公开报告完整性。分支全套 144 项测试通过，Markdown 文件链接检查通过。其中 2 项图像测试需要 Pillow；最小依赖 CI 如未安装 Pillow 会明确跳过，不计为已验证图像处理。

## 当前边界与下一步

当前已实现：固定配置的完整页图退化、真实 CPU OCR、逐字段核对、全部条件结果与失败记录。没有在本分支实现网页比较界面、通用表格抽取、扫描件识别系统或模型训练。

当前尚未验证：真实扫描噪声、拍摄透视、旋转、复杂图表、新发行人和未见版式。既有参考事实经过开发适配，没有双人独立标注；共用表头的字段也不构成独立样本。本轮不能估计漏错率、误放行率、模型校准或真实业务节省时间。

下一轮应先准备未用于调规则的新文档与人工标注，固定更广的退化矩阵，并检查错误参考是否会被错误放行；真实扫描件要另列来源与许可。细粒度字词框可作为另一条受控对照，但不能混入本次行级规则的结果。当前实验用现成 CPU 预训练模型即可完成，仍不需要租 A100。
