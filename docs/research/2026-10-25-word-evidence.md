# 把金额和旁边列的符号分开，同时保留拒绝的理由

日期：2026-10-25。分支：`feature/document-ai-words`。这是一次已在本机 CPU 上运行的字词坐标对照实验，旧的整行实验保持不变。数据仍是微软与苹果两份官方数字 PDF 的六页、42 项已知位置开发事实。

## 为什么做

金融研究员需要把披露中的数字放进季度分析、因子和风险研究。读取时把相邻年份串在一起，后续计算即使公式正确，结果也会失真。上一轮有三项金额连同旁边列的美元符号被读成一行，程序无法证明金额属于目标列，因此保留“证据不足”。本轮试验原生字词坐标能否解释这三项问题，同时保留负号、期间和单位检查。

业务与岗位依据沿用 2026-10-25 的 [岗位与产品调研](../01-product-requirements.md)、[平台方案](../11-financial-research-platform.md) 和 [独立研究建议](2026-10-25-advisory-02.md)。这项工作展示模型接入、错误分析、财务口径约束和可复现实验能力。没有新增招聘市场统计、客户访谈、节省工时或竞品优劣结论。RapidOCR、PaddleOCR 已提供文字识别，本项目新增的是金融证据怎样接受检查、怎样说明失败；不把调用开源模型描述成自研 OCR 算法。

## 官方说明与实际输出

[RapidOCR 官方使用说明](https://rapidai.github.io/RapidOCRDocs/main/install_usage/rapidocr/usage/) 提供 `return_word_box=True`。本机 RapidOCR 3.10.0 的实际结构是：每条检测行对应一组 `(文字, 原生分数, 四点框)`，不是一份没有父行关系的平铺列表。适配器核对行数、元组结构和坐标，保留父行，不能在升级包后默默套用旧结构。

依据 [v3.10.0 字词坐标代码](https://github.com/RapidAI/RapidOCR/blob/v3.10.0/python/rapidocr/cal_rec_boxes/main.py)，字词框由识别位置和裁剪变换推导，属于近似坐标，不是独立标注的真实字符边界。实际输出中 `101,832 $` 分为金额和美元符号两个有坐标的 token，`(64,551)` 则保留为完整 token。

该版本的识别解码保存字符分数，字词输出组装时把分数列表与分组内容配对；这不足以把每个原生字词分数当成完整词的校准置信度。本轮保留原生分数到本地原始结果，判定统一沿用父行分数，不借高分字符放行整词。依据是锁定版本的 [解码代码](https://github.com/RapidAI/RapidOCR/blob/v3.10.0/python/rapidocr/ch_ppocr_rec/utils.py) 和上述字词坐标代码；运行记录另存实际安装文件的 SHA-256。0.90 门槛仍只是工程拒绝规则。

这些资料于 2026-10-25 核验。既有 [文档实验说明](../13-document-ai-experiment.md) 中 PaddleOCR 3.0 技术报告仅提供识别、结构解析和信息抽取的组件区分；本轮没有新增论文方法复现，也没有将论文成绩归给项目。

## 实验如何保持可比

1. 输入是原实验保存的无标记完整页图。逐页核对图像 SHA-256 与尺寸，不接受裁过的目标金额图或画过答案框的预览图。
2. 模型只接收整页图像路径。金额、标签、年份、定位框和 PDF 文本均不传给模型；原生输出适配器也没有参考答案参数。
3. 原检测／识别权重、CPU 引擎、阈值、渲染尺度和线程设置保持一致。配置若改变任何原基线设置，脚本停止，不将不同配置包装成只改坐标粒度的对照。
4. 同一次 OCR 输出分别保留原父行和原生字词；前者用旧检查器再算一次，后者用新检查器。六页父行输出的 SHA-256 均与原基线完全相同，排除了本轮文字识别碰巧改变的情况。
5. 全部 42 项事实都进入报告，保存每项旧状态、同轮行级状态、字词状态及原因。`artifacts/document-ai-report.json`、原配置和旧 `visual.py` 没有覆盖或修改。

候选选择仍只看空间：交集占目标框至少 0.35，或候选中心位于目标框。数字候选必须唯一，不能按期望金额选子串、删字符、修正字母或拼接多个碎片。金额、年份、期间、单位文字、行标签以及适用的分区边界都要满足要求。

新增保护规则包括：

- **字符不能消失。** 除空白外，父行文本必须与全部子 token 的文本连接一致，括号、负号和小数点都不能丢失。
- **相关父行不能消失。** 父行命中目标区域但没有命中的字词时，标记不足。独立顾问发现一条正常数字行与一条缺词坐标的重叠负数行可能被错误简化，现已修复并添加回归。
- **框外的数字碎片不能静默忽略。** 与金额／年份框垂直重合至少一半、横向间隔不超过 8 point 的未选数字、括号、正负号、小数或百分号，保留其原文和坐标并拒绝判一致。远处另一列的金额不会因此被当作当前金额。美元符号不改变正负号，仍依靠字段和单位检查，不能据此宣称识别了完整币种语义。
- **状态不自动变审批。** 一致仅表示两条读取路径与登记参考一致，`automatic_approval` 始终为 `false`。

环境为 Windows、Python 3.12.14、RapidOCR 3.10.0、ONNX Runtime 1.31.0、NumPy 2.5.4、Pillow 13.0.0。两项实际 provider 都是 `CPUExecutionProvider`，模型仍为固定哈希的 PP-OCRv6 small 检测／识别制品。配置见 [document-ai-words.json](../../configs/document-ai-words.json)，许可边界沿用 [第三方说明](../../THIRD_PARTY_NOTICES.md) 与原基线。本轮没有训练、租卡或付费 API。

## 验证和复现

新增 17 项程序回归，覆盖负号／括号、小数碎片、错误年份／期间／单位／标签／分区、错误列、多个金额候选、缺失字词、重叠父行、父行低分、坐标边界、原生结构适配、保留全量事实及来源指纹。全部 151 项 unittest 在本分支通过；已有 Starlette 的 httpx 弃用提示仍存在。这些合成规则样例不计入上面的真实 OCR 结果。

复现需要原基线生成的干净页图。从仓库根目录运行：

```bash
python -m pip install -r requirements-ocr.lock
# 没有本地页图时才运行；另存重跑结果，保留公开冻结基线。
python scripts/evaluate_document_ai.py --download
python scripts/evaluate_word_evidence.py
python -m unittest tests.test_word_evidence -v
```

也可用 `--image-root` 指向已有原实验的 `.run/document-ai` 目录；脚本会核对原图哈希。本轮在隔离工作树运行，读取主库已有页图，未重建或改写主库基线。完整字词结果保存到本工作树 `.run/document-ai-words/`；只有最少必要的财务证据片段和运行清单进入公开报告。原始 PDF、完整页图及完整 OCR 不提交。

报告同时登记源披露／事实包指纹、基线文件哈希、配置指纹、推理实现指纹、关键 RapidOCR 源文件哈希、模型文件哈希、每页原图和两种 OCR 输出哈希。它们支持变更核查，不声称能抵御有权限者同时改写全部数据和指纹。
