# 第23轮独立审查：公司解释的采用与交接

2026-10-25。研究分支已同步主线 `e221dd5`，开始时工作区干净。本轮只增加独立解释补充底稿，不改父研究任务、旧v1/v2快照或既有23项、36项开发报告。

## 为什么值得做

上一轮已经能在研究任务旁查看微软的官方解释、金额换算和未核实范围，但分析员还不能把采用理由交给复核员确认。补充材料若只挂在旧的已批准任务旁，容易让后来阅读的人误以为它也经过同一轮复核。

本轮应让分析员明确选择“作为公司陈述采用”“不采用”或“仍缺证据”，填写理由和范围，再提交独立的补充底稿。它引用父底稿的固定版本，拥有自己的提交、复核和退回记录。企业价值判断沿用2026-10-25的[实际项目研究](2026-10-25-hku-industry-projects.md)和[研究任务设计](2026-10-25-enterprise-research-design.md)，不新增客户访谈、业务收益或部署结论。该改进属于证据交接和模型治理基础，不是新的多模态模型能力或训练成绩。

## 设计阶段的必要控制

| 风险 | 必须实现的边界 |
|---|---|
| 新解释借用父稿批准 | 仅允许已复核父任务建立补充；子稿初始状态始终为draft，有自己的独立批准 |
| 父任务和导出来自不同读取版本 | 对齐父task ID、revision、snapshot SHA及approve记录；冻结完整父export并计算摘要，不只保存一个可变链接 |
| 客户端自报来源或结论 | 输入仅允许服务器选择父稿、处理决定、理由和覆盖范围；证据、支持范围、因果标志、贡献者由服务端生成 |
| 同人换角色复核 | 按用户主体ID合并父创建／编辑／提交者和子稿贡献者，禁止其审核子稿；角色名称变化不能绕过 |
| 目录更新使旧稿失效 | 新创建／提交校验当前登记；旧get、snapshot与export只使用冻结内容，不因当前目录删除而丢失可读性 |
| 重试产生新记录或错误失败 | 幂等键按租户、发起主体及请求内容绑定；重复相同请求返回原记录，不能因后来目录改变破坏重放 |
| 退回后混入新草稿 | 每次提交生成独立子快照；指定旧snapshot的导出仅带该版内容及对应复核，不带后来编辑 |
| 复核完成被误读为原因证实 | 固定support_scope为公司陈述，独立因果验证始终false；rejected／needs_evidence经复核后仍保持拒绝／缺证据 |

父任务的复核员若未参与父稿或子稿制作，不因以前复核过父稿而自动成为禁止人；禁止名单依据实际制作贡献。批准的是所列材料、采用决定与限制，不是对经济原因作独立因果证明。哈希检测内容不一致，不是签名，也不抵御能够同时重写数据库内容和摘要的管理员。

## 四句话验收

1. **输入：** 一个已复核的父研究版本、服务器登记的公司说明，以及分析员填写的决定、理由和范围。
2. **正确：** 子稿冻结父导出与解释证据；采用只针对公司陈述，金额前提和采用条件成立；独立主体审核同一个提交摘要。
3. **失败：** 越租户、过期revision、自审、客户端替换证据或新提交时登记漂移均拒绝；旧批准不覆盖新稿，缺证据不因approve自动消失。
4. **发现与恢复：** 明确返回失败原因，刷新或退回修改后重新提交；相同请求安全重放，历史子快照与父稿原导出持续可查。

## 独立实现检查

已只读检查 `explanation_evidence.py`、`explanation_review_store.py`、离线导出检查器、新API与页面。父记录和完整export在同一个SQLite事务中读取；服务端冻结两者的关联和摘要，再生成解释证据。客户端模型拒绝额外证据字段。创建幂等检查先于当前来源加载，提交时重新核对来源；历史读取只验证内嵌内容及对应版本的固定规则。

独立跨实现分支动态加载代码，在临时SQLite运行真实材料驱动的合成流程，没有改主数据库、登记事实或旧报告。实测结果：

- 已批准父稿建立的新子稿为draft，没有继承reviewed；客户端附加evidence得到422，跨租户父创建、子读取和导出得到404。
- 父作者、子稿作者、子稿编辑者分别切换为reviewer，均得到403。同一子稿revision的两个并发保存，一项成功、另一项409。
- 目录模拟缺失后，已存子稿get、旧快照export和相同创建请求的幂等重放仍成功；新建和新提交得到409。
- 完成needs_evidence提交、退回、改稿、重提、独立确认后，最终状态为reviewed，但决定仍为needs_evidence，独立因果标志仍为false。父稿原export及第一次退回子快照export的规范JSON字节始终不变。
- 重写支持范围、因果标志、来源摘要、抵消项、租户或审核主体，并重新计算外层内容摘要，仍被相应契约拒绝。它检查的是已登记版本与内嵌关系；不能据此声称真实身份认证或抗管理员伪造。
- 禁止当前来源加载器运行时，离线导出文件仍可通过验证。重复JSON键、NaN和溢出数值被明确拒绝，没有把格式失败当作有效结论。

以上身份及协作意见均是合成测试，公开财务材料保持来源登记；不是金融机构真实用户验收。不同代理复核也不等于已取得外部独立人工金标准。

## 发现的问题与修复复核

| 严重性 | 实际问题 | 修复及独立复核 |
|---|---|---|
| P2 | 内嵌金额重算使用全局Decimal上下文。将精度设为3时，合法证据抛出InvalidOperation | 改为局部40位精度；独立在全局精度2下验证完整导出成功 |
| P2 | 初版Action理由允许1字，导出契约要求10字；短审核意见先过输入再报409 | 请求、契约与页面统一至少10字；新进程独立检查submit、approve、return的短理由均被前置验证拒绝 |
| P2 | 新页面详情标题提到期间，却未显示实际起止与365／366天；采用前提失败时仍可选择adopt | 已显示实际日期、天数和关联前提，不满足条件时禁用adopt并保留不采用、待补证据；已静态读回 |

短理由导致的早期失败在事务中回滚，随后同一版本仍可正常提交长理由，没有误留下审批记录。

页面在身份切换时清空父稿、子稿及隐藏证据，异步响应检查身份epoch；操作中禁用切换，草稿修改后阻止提交和导出。下载保留服务端原始响应文本，防止浏览器重序列化改变浮点字面与摘要。API沿用服务器Actor和租户读取约束，原文链接来自已锁定的来源登记。实际浏览器操作、下载文件比对和全套回归由主开发记录，本报告不以静态审查替代它们。

## 采纳与暂缓

已采用独立子稿的版本、权限、并发、幂等、历史导出及有限支持范围；三个P2问题均已修复并按相称方式复核，当前没有未解决的核心阻塞。父任务及既有23项、36项验收不因新子稿而被重新解释。

将子解释直接合入父研究内容、开放任意新来源、自动抽取经营解释、独立因果核实、真人金标准、通用VLM与训练继续留作后续任务。当前证据版本使用固定材料指纹；扩充来源应新增版本及兼容分派，不能覆盖常量让旧导出改用新材料。下一步可增加一条不同公司或不同支持程度的解释，检验“来源已登记”“作为公司说法采用”“证据仍不足”三种含义能否持续清楚；仍不预告新模型成绩。
