# 第26轮独立审查：登记页面成组交接与失败重试

2026-10-26。研究工作树`a36d9d5`已合并主线`ed20b4c`，起始状态干净。新增本报告及主开发追加授权的`check_preparation_write_intent.js`回归脚本；其他工作树只读，不下载原始PDF／页图、不运行模型、不改旧冻结结果或个人材料。

## 为什么做这一组工作

分析员交接一份材料时，一页结构正常不能掩盖另一页漏交、重复或坐标损坏。更正后也需要留下此前失败的依据，方便下一位处理者理解已经修复什么、还有什么未完成。企业任务依据复用2026-10-25的[实际项目研究](2026-10-25-hku-industry-projects.md)、[研究任务设计](2026-10-25-enterprise-research-design.md)及[输入预检审查](advisory-16.md)，没有新增访谈、生产部署或效率收益结论。

本轮“齐全”只指同一版本材料的登记页集合。它不证明整份PDF完整，不理解跨页表格，也不是OCR准确率。持久化记录用于查看失败和显式重试，不等于后台任务自动恢复或批量知识库入库。

## 提前提出的必要边界

| 环节 | 必须保持的约定 |
|---|---|
| 页集与版本 | 服务端登记决定预期页集；同一任务固定文档／来源／版本，不接受客户端重新定义完整性 |
| 缺页和重复 | 分别记录提交页数、唯一预期页和可交接页；重复不能靠最后一次覆盖，缺／重／额外页或任何错误整组阻断 |
| 空识别结果 | 结构允许空输出不代表原图没有文字；登记必需事实仍无内容时，应明确空页状态和交接限制 |
| 内容最小化 | 仅存白名单摘要、受控错误代码／路径和输入哈希；原始OCR及规范化正文均不进入数据库或公开报告 |
| 幂等与并发 | 键绑定租户、主体、任务与请求摘要；已完成请求先安全回放，同键不同内容拒绝，CAS保证同版本并发最多一次新尝试 |
| 历史与漂移 | 新尝试检查当前登记，旧记录读取不依赖后来目录仍然存在；漂移不能改写旧尝试或使旧幂等回放失效 |
| 权限与交接 | 服务端身份决定租户和操作权限，客户端不能声明他人身份；通过预检不自动进入检索、批准事实或继承旧批准 |

四句话验收：输入是固定登记文档的成组页和明确来源声明；正确是每个登记页都有唯一、可解释的准备状态；错误要留下缺页／重复／逐页失败及版本，不能以部分成功遮蔽；修复后使用新的尝试并保留旧摘要，重启后能够读取历史及主动重试。

## 实现与独立验证

核心将结构检查与交接状态分开：合法空OCR或空字词组可以通过结构检查，但本任务仍阻断交接，保留`empty_recognition`或`missing_word_evidence`。登记摘要在开始、逐页和结束时核对；版本变化不允许用一部分旧材料和一部分新材料拼出通过结果。输出只含受控摘要、页码、哈希及错误，不返回原始或规范化OCR正文。

独立执行9个核心场景：完整输入、漏页、坏坐标、重复项中一页损坏、额外页、空OCR、空字词、跨文档页及正文测试标记。只有完整非空输入和仅修改正文内容的结构合法输入准备通过；其他场景整组阻断。重复项全部保留，不挑选其中“较好”的一页。正文测试标记未出现在任何返回摘要中；这也说明结构通过并不等于已识别正确的财务内容。

在临时SQLite与复制的登记依赖上，独立串联漏页→坏坐标→修正成功，状态为blocked／blocked／prepared_not_indexed，版本1／2／3。实际检查：

- 重建store后可读取历史；旧create和retry幂等请求返回原响应，不混入后来版本。
- 指定旧attempt的导出摘要保持不变；跨租户404，只读角色写入403，同键换主体／内容409，旧revision和已完成任务重试409。
- 删除临时登记清单后，旧历史和旧幂等回放仍可读，新重试409；这类前置拒绝不冒充已保存的逐页失败尝试。
- 两个不同幂等键并发重试同一revision，只有一个成功，另一个409，版本只增加一次。
- 仅在OCR正文里加入唯一测试标记，数据库文本转储、数据库文件和历史／导出均未出现该标记。

外层明确`attempt_metadata_persisted=true`、`raw_ocr_persisted=false`，与纯预检函数的`database_written=false`区分。持久化的是诊断尝试，不是金融事实或检索索引。对提交前被中断的请求没有后台恢复承诺，重启后读取已提交历史与显式重试是本轮范围。

已发现并确认修复两项集成问题：初稿完整样例的word_results嵌套层级错误，修正后三个样例分别得到漏页阻断、坏坐标阻断、完整准备通过；固定错误路径`document_id/ocr_input`里的斜杠最初不被存储白名单允许，主开发补充后，独立执行新增回归，None／数组／布尔／字符串四种错误对象均能留下blocked摘要，修正后通过，且不回显原文。

本次独立探针读取数据库后的临时连接清理有遗漏，功能结果输出完成后临时目录清理失败；后续清理被自动审批策略拒绝，目录保留，不另换工具绕过。该问题属于顾问测试脚本的收尾，不是应用store连接或功能失败；机器临时绝对路径不进入公开报告。

独立HTTP集成验证完成：API-key模式创建失败记录返回201，修正返回200；指定旧attempt下载前后逐字节相同。未授权401、越租户404、只读角色伪造演示角色写入403、重复JSON键422、旧revision409，响应为no-store。HTTP正文测试标记也未进入响应、导出或数据库文件。此项测试临时连接正常关闭。

界面五项建议已体现在源码：历史列表与当前样例登记分开加载，登记暂不可用不阻止打开历史；身份变化清空隐藏详情；切任务／尝试先清旧详情；独立刷新序号防止队列乱序回填；幂等写请求返回后另取当前任务，区分当前版本标题与请求对应的历史尝试。后续导出读取失败原先会被吞掉并过早清除重试键，现已返回明确失败状态，保留键且不再覆盖错误提示。

继续审查发现并确认修复P2：重试写入成功后，当前任务revision已更新；若导出读取失败，再点重试会把新revision加入请求，导致原signature变化并生成新幂等键。用当时HTML的save函数在Node内存环境替换request／loadAttempt进行独立控制，两次失败读回后捕获的请求revision为1／2、幂等键不同，证明保留变量本身不足以保证重放。主开发修正为按路径与原始编辑文本识别同一意图，同时保留第一次请求体；后续读回失败再试时，原body与key不变，明确编辑后才创建新的意图。

新增[独立回归脚本](../../scripts/check_preparation_write_intent.js)直接加载页面实际save及编辑处理函数，通过6个控制：创建／重试分别在读取当前任务或导出时失败、成功读回后清除意图、编辑后新建意图。修正版本6项通过；仅在内存里恢复旧signature方式时，脚本在请求体与幂等键一致断言处失败，证明该控制能够抓住本次回归。仓库合并后运行`node scripts/check_preparation_write_intent.js`；也可传入待审HTML路径。此控制没有实际网络请求或浏览器故障注入，不替代主开发报告的三次浏览器提交及实际下载验收。未发现剩余阻塞项。

## 下一项跨页任务的最小材料

先选一个原表页与一个单位／期间或附注页的官方版本，冻结PDF摘要、物理页、关系类型和应引用的两个位置；明确这是登记的两页任务，不是整本报告完整性。人工确认尚未完成时保持开发参考标签。

验收至少包含正确关联、缺一页、重复页、错修订版、同名不同期间和冲突单位。输入预检通过之后，证据关联仍需独立判断，不能用“页齐全”代替“这些数字可以比较”。未来图表任务另登记轴类型、误差范围与估读状态，本轮不新增其成绩。
