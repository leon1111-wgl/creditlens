# 第31轮独立审查：先分别记录原文，再冻结参考候选

2026-10-26。研究工作树从与主线`226bc13`内容相同的`5c90232`开始，起始状态干净。本轮仅新增本报告和获授权的页面状态控制脚本；主工作区与两条实现分支只读。没有下载原始材料、调用识别模型或付费服务，也没有新增真人标注。

## 为什么先做参考核对流程

上一轮的细词方法没有增加真实开发材料的匹配数，反而使四项原匹配记录转为不足。下一步既需要解释规则行为，也需要可靠的参考，不能继续把工具整理的旧答案当作独立人工标准。本轮将任务、来源和观察过程保存下来，使另一位核对者能够追查“谁在什么材料上看到了什么”，并保留分歧与修正历史。

企业需求沿用2026-10-25的[项目调研](2026-10-25-hku-industry-projects.md)、[研究交接设计](2026-10-25-enterprise-research-design.md)和[岗位需求](../01-product-requirements.md)。与投研、风险分析相关的实际价值是原文核对、复核分工和失败交接；本轮没有新增客户访谈、效率收益或商业竞品测试。它落实了[上一轮参考协议](advisory-21.md)的一部分执行机制，尚未完成该协议要求的真人独立标注。

## 本轮验收的四句话

| 项目 | 约定 |
|---|---|
| 输入 | 固定官方材料版本、物理页、行名和年份；两个应用身份分别填写完整金额、符号、单位原文、分区及本人定位，或记录歧义／不足。 |
| 正确 | 首份封存后其他身份不能读到内容；两份齐全才比较；没有参与填写的第三复核身份只能把一致记录冻结为候选，不能授予人工金标准身份。 |
| 失败 | 同人换角色填写第二份、自审、来源漂移、并发版本冲突、两份分歧、网络中断或误把旧操作响应当当前版本。 |
| 恢复 | 原请求按原幂等键回放，重新读取当前状态；第三身份关闭旧轮后另开空白新轮，旧冻结导出保持原样。来源不可用时仍能读取历史与关闭旧轮。 |

目录保留40种唯一查询，与旧42项登记记录分开。服务端内部保留对应关系，对表单仅发送白名单任务：不发送旧参考金额、参考框、模型候选或含分区答案的fact ID。任务ID由来源、页和查询身份生成，金额不参与生成。每份观察单次提交后封存，没有可覆盖旧值的草稿更新接口。

一致性检查同时比较完整金额字面、解析值、定位、单位、币种与分区字段。负号、括号及负零不能被忽略；两人填出相同数值但使用不同字面或范围仍可产生分歧。自由观察说明保留，但不决定内容一致；说明不同通过`notes_differ`单列。两人均记录“不足”也不是成功取到数值，比较结果保留`answer_status`。

金额框采用严格坐标一致，不自动以容差合并。独立手画的两框很容易不同，这是当前流程限制，不能称为成熟的标注一致性算法。应用在保存时以冻结任务重新检查真实页面边界；裸比较函数只核规范内容，不能单独证明来源、坐标真实性或答案正确。

## 盲填与人工参考的边界

本项目旧参考及模型输出已公开，服务无法保证参与者未在别处看过。当前实现只保证新工作流在第二份提交前不展示对方内容、不预填旧答案。首份观察的摘要、长度和正文也不能通过列表、事件或错误响应送给其他身份，避免低熵金额被猜出。

两个API身份不等于两位真实人员，第三复核账号也不能证明实际独立性。`human_gold=false`、`independence_not_verified=true`始终保留。后续轮次虽然从空白开始，参与者可能已看过上一轮答案，因此不应称为新盲测。对于`Term debt`这类原查询存在多处分区的情况，仍需真实人员判断应记录歧义，不能因两份恰好选择同一金额就把原问题升级为唯一答案。

本轮保存的是原文观察候选，不自动验证完整财务期间、会计口径或来源真实性。它不替换旧42项参考，不重算旧实验成绩，也没有增加独立保留集或新模型质量分数。

## 独立验证与已采纳修正

使用真实40项目录和独立临时SQLite，实际运行了六组联调控制：

1. 首份观察的金额、单位、说明canary及观察摘要，不出现在另一分析员、复核员、只读身份的详情与列表中；未冻结导出拒绝。
2. 同一`user_id`切换为复核角色仍不能填写第二份；跨租户读取返回拒绝；填写者不能复核自己的观察。
3. 第二份提交后可以看到两份内容；第一位填写者重试原键，仍得到原先只有一份的响应，不补入后来产生的对方内容。
4. 第三未参与身份能够冻结一致候选，导出仍明确不属于人工金标准。
5. 当前目录不可用时，旧冻结导出与已成功请求的原响应仍可读取；新的观察提交被阻止。
6. 当前目录不可用时，第三身份可以关闭未完成旧轮，且看不到被隐藏的首份内容；新轮不复制观察，旧冻结导出保持相同。

所有临时数据库连接通过上下文正常关闭。首次独立探针的动态模块加载缺少注册步骤，导致Pydantic无法解析类型；修正探针初始化后重新运行上述控制，未修改产品代码，也不将这次探针初始化错误计为产品缺陷。

随后独立执行[隔离复演](../../scripts/replay_reference_review.py)的`build_replay`，与[公开结果](../../artifacts/reference-review-replay.json)逐字段相同：18项控制通过、3个模拟轮次、4份虚构观察、1份冻结候选、人工金标准0份。虚构金额和框没有冒充官方页原文；该报告验证的是流程，而非真实标注正确率。

| 问题与级别 | 处理与独立复核 |
|---|---|
| P2：身份切换后隐藏DOM仍保留旧轮次、来源链接和自由说明 | 主开发补齐清理；实际页面脚本控制检查可见与隐藏节点、表单值均清空。 |
| P2：POST已保存但返回500或无效JSON时，页面丢弃原幂等键 | 不确定结果保留原键和原payload；即使编辑本地表单或版本变化，重试不替换原请求。只有确定拒绝才释放该意图。 |
| P2：幂等回放返回旧版本，详情可能落后于当前记录 | 写入确认后单独读取当前记录与列表。独立控制中操作响应为版本2、当前读取为版本3，最终展示版本3。读回失败明确显示操作返回版本，并阻止新写入直至重新读取。 |
| P2：注册不可用时连关闭旧轮也被阻断，无法开始恢复 | 主开发发现并由存储分支修复：关闭仅封存旧历史，不依赖当前目录；提交与冻结仍检查当前登记。独立联调确认首份隐藏与旧导出不受影响。 |

## 页面、接口与后续执行

[页面控制脚本](../../scripts/check_reference_review_state.js)直接执行当前HTML中的JavaScript，共24项通过。覆盖身份／记录切换后的迟到响应，首份隐藏视图、自审按钮、原页错误、手动两角坐标换算、没有参考框预填、原响应字节导出、创建与提交的不确定重试、非幂等动作失败后的状态确认，以及保存成功但后续读取失败。只在内存中把500重新当作确定拒绝，重试控制会准确失败；没有修改主页面来制造结果。

运行`node scripts/check_reference_review_state.js`；跨工作树检查时可追加HTML路径。控制使用合成响应与可控Promise，不是实际浏览器渲染、真实网络故障注入或真人填写验收。脚本设有未完成超时，避免漏回应请求时进程无声退出。HTTP与真实浏览器验收由主开发另行记录。

接口只读审查确认：先取得服务端身份与租户，再读写记录；新建与观察提交使用严格JSON和幂等键；客户端不能上报作者身份或人工金标准标记。原页通过已登记文档页读取，返回字节须与保存任务的图片摘要相同，不允许任意文件路径；页面仅叠加填写者自行选择的框。摘要用于内部一致性检查，不是签名，不能抵抗本地管理员连同记录和摘要一起重写。

当前没有剩余阻塞项。下一步应安排真实人员先阅读协议，再固定未用于规则调整的来源与题目，在查看方法输出前独立填录、处理分歧并冻结可使用的参考版本；正式执行前仍需确认许可和评测分组。当前40种已观察查询仅用于流程开发，不能用这次模拟操作宣布已建成独立人工测试集。
