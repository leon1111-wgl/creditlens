# 第36轮独立审查：重新打开原行选择导出

审查日期：2026-10-26。业务依据复用2026-10-25的[产品需求](../01-product-requirements.md)与[企业研究任务设计](2026-10-25-enterprise-research-design.md)，不新增招聘、客户访谈或节省工时主张。上一轮已能选择同名原行并导出；本轮检查收到的文件是否与可信冻结结果逐字段相同，补齐文件交接后的复查入口。

## 价值和边界

研究员转交JSON后，接收者不能仅凭文件中的金额或自报摘要确认内容未变。本轮应由服务器或本地可信仓库重建预期导出，核对完整查询、来源、候选全集、显式选择、取数依据和权限范围字段。通过只表示与这份冻结结果一致，不证明财报真实、金额业务含义正确、提交人身份真实或完成了人工参考标注。

若文件版本与当前登记报告不同，应说明无法在当前版本核对，不能仅凭不相同就断言人为篡改。可信报告缺失或校验失败属于核验环境不可用，也不应把已有历史导出直接判坏。现有业务底稿、审批和旧API不因本次检查而改变。

## 必须检查的入口条件

- API先验证访问身份，再受限读取原始请求；不能仅相信客户端的Content-Length。
- UTF-8、重复键、非有限数、溢出数、类型、深度和体积均在比较前检查。浏览器不要先解析再重新序列化，避免把重复键或浮点字面变化隐藏掉。
- 上传的摘要、来源URL和路径都是待验证数据，不用于下载资料或指定可信文件。
- 错误只返回受控原因与位置，不回显上传字段、原文、文件内容或私有路径；不持久化上传数据。
- 文件读取和API响应都须隔离迟到结果。换身份、文件、当前查询或新选择后，旧检查结果与导出不能重新出现。

四句话验收：输入是上轮原样导出及可信冻结报告；正确标准是完整结构和类型逐字段相同；无效输入、不同版本和可信参考不可用分别说明；恢复来源或换回原始文件后重新检查，不修改原有底稿。

## 实际审查记录

顾问按第35轮GET接口的完整结构，独立构造并检查八条登记路径的原样封套，全部返回`matched`，原始字节摘要相符。六类修改——布尔值替代版本整数、浮点行索引、未知字段、改来源URL、改金额、自行重算上传报告摘要——均返回不匹配，且响应不包含输入中的测试私有字符串。没有只检查金额或相信上传的自报摘要。

另独立运行11类解析器反例：转义后重复键、NaN、数值溢出、下溢、浮点字面坍缩、非法UTF-8、孤立代理码点、过深结构、过多节点、超大输入、过长整数。全部在读取可信报告前拒绝。纯对象接口允许合法共享子容器，仍拒绝祖先循环；不会把循环对象交给递归摘要函数。

模拟可信来源载入失败时，接口核心只给固定来源错误，不回显内部异常中的测试字符串；恢复后同一原件仍能通过。完整替换为另一条真实已登记路径也会通过，这是预期边界：系统没有预先可信的收件摘要或签名，不能证明该文件在此前从未被替换。

### 固定实验与保存检查

正式报告为84,892字节，SHA-256为`643bfa2a0f2f7d0d636faae296ef9aba4a3cf9d2c62dc95b9233e45bba48269a`。顾问独立复放8条登记封套与34项合成控制，结果逐字段一致。把控制中的不匹配改成成功、把来源真实性标志改为真、删除问题列表，保存报告检查均以`report_mismatch`拒绝。

这些数量是文件格式、内容比较和失败处理的控制，不是新OCR结果或财务正确率。报告不保存上传正文；CLI的错误输出也不包含文件内容或未知字段名。CLI依赖安装仓库的可信登记，不能称为无参考的离线验真。

### 页面与访问入口

新增[页面状态控制脚本](../../scripts/check_row_selection_verification_ui.js)，执行实际HTML中的函数，30项受控检查通过，正式八条核验响应都用于渲染和原响应导出。文件通过`arrayBuffer`保留原始字节，粘贴内容直接编码；没有在发送前解析再重写JSON。重复键、浮点字面与非法UTF-8字节都能原样送达检查入口。

顾问在测试准备中发现，JavaScript重建测试导出会把`792.0`变为`792`，不能拿这种输入配对正式成功响应。已改用标准库Python保留数字类型重建测试文本，并逐条核对正式实验中的输入字节数及SHA-256，确认八份输入完全相同后才进行页面测试。该修正只涉及测试夹具，产品页面本来就发送原始字节。脚本使用资料目录的`.venv`或系统Python，也可通过`CREDITLENS_TEST_PYTHON`指定解释器。

检查分别延迟文件读取、POST响应和响应正文，再切换身份、文件、文字、查询、新选择或候选重载，确认旧结果不能回填。文件读取失败、401、409、500、无效JSON和不支持的响应结构会清掉旧检查及导出，保留输入供重试。文件元数据、实际字节及多字节粘贴文本超过128 KiB时，都在POST前停止。原文和差异内容通过`textContent`呈现，身份切换清除文件、文字及核验结果。此前26、21、19项页面控制也通过。

```powershell
node scripts/check_row_selection_verification_ui.js ../creditlens/creditlens/table-lookup.html ../creditlens ../creditlens-robustness/artifacts/row-selection-verification-report.json
```

只读代码审查确认新POST先鉴权，逐块读取并限制128 KiB，原有Origin检查保留；上传来源URL不会被访问，核验过程不写业务数据库。浏览器展示明确文件将发给当前工作台服务，并提供本地命令替代入口。Node VM检查不等于真实浏览器或网络故障注入；真实HTTP、下载和最终兼容验收由主开发另行记录。

## 采纳与保留边界

已采纳完整封套比较、原始字节传输、受限解析、错误脱敏、来源失败与内容不匹配分开，以及合法整包替换仍能匹配的说明。本轮独立探针没有发现尚未修复的阻塞问题，不为凑缺陷新增问题。

后续若要证明某个收件文件没有被替换，需要另行确定可信收件摘要、签名或受控交接记录；不能通过继续增加本轮字段比较次数获得这种保证。当前依然不证明财报真实、使用者选择了正确会计范围、独立人工核查或业务审批。本轮没有下载原始文档、运行OCR或付费模型，独立人工金标准仍为0。
