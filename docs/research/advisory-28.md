# 第37轮独立审查：写入完成后丢失响应的恢复

审查日期：2026-10-26。需求依据沿用2026-10-25的[产品需求](../01-product-requirements.md)、[企业研究任务设计](2026-10-25-enterprise-research-design.md)和[三类任务约定](../24-research-task-acceptance.md)。没有新增客户访谈、节省工时或模型表现结论。

## 本轮优先问题

研究员保存采用决定、交出底稿，或复核员确认后，网络响应可能丢失。数据库已经保存的操作与页面仍显示的旧版本由此分离。现有版本锁能够阻止重复写入，却不能告诉使用者刚才是否成功；研究与解释补充两个页面还会因未保存标记阻止刷新。这个缺口影响已有任务的完成与交接，优先于继续增加一个只读一致性检查模块。

顾问用真实登记材料和隔离SQLite逐一执行两套任务的保存、提交、确认、退回，再丢弃首次返回并重复完全相同的请求。八条路径第一次都只增加一个版本和一条事件，相同请求重试全部返回409。显式GET能取得成功后的版本；解释补充操作不改变父研究导出。这里模拟的是响应未交给调用者，没有声称实际制造了网络断连。

代码位置明确：原`tasks.html`和`explanation-reviews.html`保存及操作函数没有写入幂等键，两个Store先检查旧revision。保存响应丢失后本地dirty仍为真，重新保存遇409，刷新或切任务又被脏稿保护阻止。原测试已有并发版本竞争、创建幂等和历史导出稳定性，缺少事务已完成但响应未到达后的操作回执与页面恢复检查。

## 建议的最小改进组

输入是当前身份、目标底稿、原版本、操作内容和可选幂等键；正确标准是同一意图只产生一次业务修改，并可重新读取其回执及当前版本；错误包括请求未发送、事务已提交但响应丢失、读回失败和另一人产生新版本；恢复时重试原请求和原键，再单独读取当前状态，不用旧回执覆盖新版本。

- 回执与事件、快照和任务变更处于同一SQLite事务；回执写失败必须使业务修改一起回滚。
- 重放前仍检查当前身份、角色、租户和资源权限。指纹绑定主体、资源、操作和原请求，包含revision及快照摘要；不能通过复用键取得另一人的响应。
- 成功回执固定为当时响应。源登记后来不可用时，可在授权范围内取回旧回执；不能因此重新执行已经成功的提交，也不能取消新操作的来源校验。
- 未带键的既有接口保持原版本冲突语义，旧快照、事件和导出格式保持不变。
- 页面保存原请求正文与键。断网、5xx、坏JSON、响应正文读取失败或当前版本读回失败时保留意图，提供明确重试入口；未确认期间不继续编辑或发起另一笔操作。
- 当前版本应来自另一次GET。服务端回放旧成功响应后，即使其他人已推进版本，也不把旧回执装成页面最新状态。
- 无未确认写入时，允许使用者明确放弃本页未保存内容并刷新。身份变化清理意图与旧数据；内存意图不宣称能跨刷新、重启或设备恢复。

本轮不改变任何财务计算或审批意义。恢复“确认底稿”的回执，只证明系统记录的操作已完成，不能把公司说明升级为独立核实的经营原因。

## 独立实现检查

新回执实现已用隔离SQLite独立检查。研究与解释补充的八类写操作在同键重试时返回首次完整响应，不再增加版本或事件。任务已经推进到版本4后，原保存仍回放版本2，GET继续返回版本4；模拟当前材料加载不可用时，旧保存回执仍可读取。角色降为只读、跨租户和同租户更换主体分别被403、404和409拒绝。

顾问通过SQLite的INSERT触发器使回执保存失败：普通保存的任务与事件整体回滚；提交复核还包括新快照一起回滚，均返回503。解释补充操作前后的父研究导出保持相同。这些检查在临时数据库进行，连接正常关闭，没有改主应用数据。

当前回执通过内容摘要和仍保留的事件前缀发现存储不一致；它不是签名，不能抵抗同时改写业务记录、回执及所有摘要的本地管理员。历史响应可读也不免除新提交的材料登记校验。

## 页面故障与恢复

[状态控制脚本](../../scripts/check_research_write_retry_ui.js)执行两个实际HTML脚本及共享写入控制器，使用既有导出的材料内容作渲染夹具。62项受控检查通过，角色、HTTP响应和故障均为模拟，未将代理操作视为真人验证。

- 首次fetch失败、响应正文读取失败、JSON损坏和500会保留原正文与键。重试返回旧回执，再读取较新版本；页面只装载GET结果。
- 当前版本GET失败、正文失败、403或返回落后版本时，已经获得回执的意图仍可重试。保存、提交、确认和退回都保留原版本、说明及快照绑定。
- 明确4xx拒绝释放本次意图并保留草稿。若此前曾有不确定的请求，当前重试被拒绝不能证明此前没有完成，应重新查看服务端记录。
- 不确定期间禁止编辑和另一笔写入，成功恢复后重新启用字段。主开发已修正初版一次性禁用过多元素的问题，避免成功后创建问句仍不能编辑。
- 切换身份后，迟到的写入结果、响应正文及当前版本响应都不能恢复旧内容；旧请求成功或失败也不干扰新身份正在进行的写入。
- 明确放弃未保存改动只执行GET；GET失败仍保留草稿。当前版本已读回、仅列表刷新失败时，不再保留重复写入意图。

```powershell
node scripts/check_research_write_retry_ui.js ../creditlens
```

参数是待验收仓库根目录，脚本直接读取其中的两个HTML、共享控制器和已有导出夹具；没有复制或改写主分支页面。未传参数时使用脚本所属仓库。Node VM不替代真实浏览器、实际网络断连或HTTP接口验收，最终兼容检查由主开发另行记录。

## 采纳与局限

本轮已采纳事务内回执、权限先于回放、原请求同键重试、回执与当前版本分开、显式放弃草稿及身份变化清理。独立探针未发现尚未修复的阻塞问题。没有扩展为后台队列恢复，也没有把数据库回执称为签名或来源真实性证明。

页面的未确认请求仍只保存在内存，刷新或关闭后不会自动恢复原键；用户需要重新读取服务端记录再决定下一步。当前材料变更后的新任务接续、通用上传和资料修订传播仍是其他任务，不由本轮写入恢复自动完成。本轮没有下载原始文档、运行OCR、调用模型或新增人工金标准。
