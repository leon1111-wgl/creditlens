# 第38轮独立审查：把材料检查落实到一项明确查询

审查日期：2026-10-26。依据沿用2026-10-25的[产品需求](../01-product-requirements.md)、[企业研究任务设计](2026-10-25-enterprise-research-design.md)及[三类任务约定](../24-research-task-acceptance.md)，没有新增招聘、客户访谈或业务收益结论。

## 旧行为与本轮价值

顾问使用已有正式研究导出的材料与采用决定，分别把问题改为微软当期经营现金流、未登记公司的收入、苹果全部资本投入、下一年毛利率预测。四次检查的任务结果逐字段相同：八项材料可定位、四组年度变化可计算、经营原因依据不足。

这个行为符合旧接口的固定模板设计。旧代码保留`natural_language_question_understood=false`，页面也明确不理解自由问题，因此不能把上述复现描述为旧模型错误理解了问题。实际缺口是操作粒度：使用者仍要自己从全量结果里挑出所需公司、指标和期间，缺少一项明确查询的独立输入、结果和交接记录。

本轮应让使用者显式选择任务类型及观察条件，只返回这一选择的证据、计算与缺口。原研究问题仍是背景文字；新查询不能反过来证明那段自由问题已被理解或完整回答。研究底稿及旧审批也不因只读查询而改变。

## 必须保留的边界

1. 查询条件来自显式选择，服务端严格验证任务类型、公司、指标、年度和数量，不接收客户端金额、引用对象、公式或来源摘要作为事实。多余字段、布尔值冒充年份、重复条件和错版本不能被静默修正。
2. 查指标可以展示未采用的原披露，同时标记不能用于计算。比较要求同公司、同指标、连续且方向正确的两期都已采用；不能把跨公司、缺项或倒序变成另一个默认问题。
3. 固定资产现金支出保持PPE现金支出的范围，不升级为全部资本投入。实际财年起止、长度、单位、符号转换和来源版本随所选结果保留。
4. 经营变化的会计分解、公司明示陈述、分析员假设和独立核实分别展示。数值相符、公司陈述已收录、假设文字或旧底稿批准都不能让因果验证变成真。
5. 未在登记材料中找到，只说明当前工作台缺少相应材料。它不等于企业没有披露、数值为零或应当忽略该期间。
6. 响应绑定当前任务、版本、材料摘要、完整查询条件和规则版本。用户改选、编辑草稿、切任务或切身份时立即清结果与导出；迟到的响应及正文不能恢复旧内容。

四句话验收：输入是一份已保存研究和用户显选的查询；正确标准是只使用匹配条件的登记证据，按适用口径给出原值、公式或明确缺口；错误包括选错公司或期间、未采用、来源失效以及把公司说明当作独立原因；修正选择或材料后保存并重新查询，旧导出保持原样。

## 人工参考尚缺时仍值得准备什么

已有[参考核对流程](../34-reference-review.md)能够隔离两份提交、展示分歧并冻结候选。本轮没有必要再增加模拟账号来制造“独立标注”数量；账号不同不能证明不同真人参与，现有开发资料也不能重新称为未见测试集。

下一步可先冻结未参与本项目规则调整的公司／报告范围、问题清单、许可与来源版本，再给实际标注者明确说明：完整金额字面、单位、实际期间、分区、缺失类型和定位怎样记录，何时必须保留歧义。参考在模型结果揭示前完成，记录真实参与者与仲裁；这些条件未完成前，软件控制和代理交叉复核继续保持独立人工金标准为零。

## 独立实现检查

顾问用现有登记材料独立执行12种范围组合：正常查数、未知公司、全部资本投入、未登记年度、同公司比较、逆序、重复、跨公司、跨指标、两家公司经营证据和不支持的PPE经营解释。结果按预期分别可定位、可计算、未登记、阻断、不足或不支持，没有自动换成另一组数字。

另外四类输入——布尔版本、布尔年份、历史日期字段和客户端金额——在计算前拒绝。三个未采用分支保持区别：查指标仍能看原披露；比较的差额为空；经营会计分解的计算内容为空。修改原研究标题不改变显式查询结果，已批准状态也不让独立核实或因果标志变为真。

测试首次从旧冻结导出重建当前任务时漏掉了创建选项，被材料校验正确拒绝。补全当前任务字段后完成上述检查；没有为测试放宽产品校验，也没有把导出内容当作可直接提交的新任务。

### 固定开发报告

正式报告为719,116字节，SHA-256为`056acf1c230df6cef87bf3b644a69acdd5ba800e8d167d255a48b48c94d79373`。顾问独立完整复放32项控制，10项登记材料投影和22项合成控制均符合固定预期；三个不变性检查保留原标题独立性、旧导出和任务版本／事件／快照。

保持用例总数与通过计数但修改所选金额、把模型准确性评测标志改为真、改动不变性结果摘要，报告复验都拒绝。以上是固定选择器及软件行为验证，不是自然语言问答正确率，也不是新增人工参考。

### 页面与接口

初版页面只比对任务、版本和查询条件。顾问提出补齐材料摘要、输入绑定和所选卡身份检查，主开发已采纳；同任务同版本但错材料的响应也会拒绝。公司说明的数字核对按实际字段区分“本期经营现金流”和“年度增量”，显示表内值、披露值及各自单位，不再显示两个含义不明的相同状态标签。

[页面控制脚本](../../scripts/check_research_query_ui.js)读取实际HTML和共享写入控制器，并要求正式报告中的五组响应作为夹具。51项检查通过，包括：

- 三类任务及未登记期间的实际结构能够显示；本期金额与增量保持可读区别，未登记不写成未披露。
- 改公司、指标、年度、任务类型、草稿、保存版本、底稿或身份后，迟到响应及响应正文都不会恢复旧结果。
- 401、409、500、网络或正文失败、无效JSON会清掉原结果并允许重新查询；旧查询失败不覆盖新查询成功。
- 任务、版本、查询、材料摘要、证据卡、输入绑定不对应时拒绝；写入开始会使尚未完成的查询失效。
- 未保存草稿不能查询或下载旧结果；下载再次检查实际选择值，且保存服务端响应原文，不重新序列化数值。
- 自由说明通过文本节点显示，不执行其中的HTML。

```powershell
node scripts/check_research_query_ui.js ../creditlens ../creditlens-robustness/artifacts/research-query-report.json
```

未传参数时读取脚本所属仓库及其正式报告；缺少正式夹具会失败，不静默跳过。上述控制使用模拟响应时序，不替代真实浏览器、HTTP及页面渲染验收，主开发另行记录。

## 结论与保留事项

这轮把“材料整体有哪些能力”推进为“本次明确选择能获得什么”。独立检查未发现剩余阻塞问题。旧底稿、旧固定任务验收和审批不改写；新查询结果是当前版本的只读记录，不自动加入冻结底稿。

尚未实现自然语言意图理解、独立因果核实或真实人工评测。后续可以在明确查询契约和真实人员参考具备后评价模型是否正确选择证据；不能把本轮控制数量或已有参考候选数量代替这一步。
