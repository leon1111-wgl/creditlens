# 第39轮独立审查：刷新后接续待确认的研究写入

审查日期：2026-10-26。需求依据沿用2026-10-25的[产品需求](../01-product-requirements.md)、[企业研究任务设计](2026-10-25-enterprise-research-design.md)及[三类任务约定](../24-research-task-acceptance.md)。没有新增客户访谈、效率收益或模型表现结论。

## 问题与范围

第37轮已解决同一页面内“服务端完成写入，但页面没有收到响应”的重试。原请求和幂等键只在内存中，刷新会丢失；研究员或复核员重新进入页面时，仍需判断刚才的保存、提交或复核是否完成。接续这一条未确认操作，比另建一套检查模块更直接地支持已有研究交接。

本轮保存的是已经准备发送的一条写入意图，包含目标、原版本、原正文和原幂等键。它不是自动保存全部草稿，不代表操作已成功，也不自动重试或批准。恢复范围是同一标签页的刷新；关闭标签页、浏览器或设备后的恢复不在承诺范围内。

`sessionStorage` 不应保存 API key 或其他登录凭据，但原请求仍包含采用理由、备注等业务内容。它不是加密保险箱，不能抵抗同源脚本或本机访问者；公开测试只能使用合成内容和可公开材料。

## 验收边界

1. 写入前保存原意图，并读回确认。权限、配额或静默写失败不能被当作“已可跨刷新恢复”；未可靠保存时不得发送该笔新写入。
2. 恢复前重新取得服务端会话，按租户、用户和角色三项绑定。存储中的身份不是授权依据；身份不匹配或记录损坏时，不显示正文、不自动删除，也不自动发送请求。
3. 记录只接受两类底稿的精确路由、允许的方法和正文结构。拒绝外部 URL、额外请求头、注入字段、错误类型和超限内容。客户端记录可被篡改，服务端仍必须执行权限、版本、来源及幂等校验。
4. 恢复后先读取绑定底稿的当前版本。旧原文只留作同键重试，不能装成当前已保存内容；GET 得到新版本也不能改写原请求的版本、正文或键。
5. 用户显式点击才重试。读回失败时保留待确认记录，但先重新读取目标；身份变化或迟到响应不能重新展示旧身份内容。
6. 成功或明确拒绝后，清理也要读回确认。清理失败必须明确提示并继续阻断新写入，不能留下会在下次刷新复活的记录。清除本地记录不撤销服务端操作，也不证明此前操作没有完成。

四句话验收：输入是刷新前保留的单条写请求和重新认证的身份；正确标准是读取同一底稿后，由用户重试原正文和原键，并显示服务端当前版本；错误包括存储不可用、损坏、跨身份、读回失败或清理失败；恢复时保留可解释状态，通过明确重读、重试或清除接续，不产生第二笔意图。

## 验证记录

### 页面与本地记录

[刷新恢复控制](../../scripts/check_research_reload_ui.js)执行两个实际HTML、共享日志模块及写入控制器。它创建全新的Node VM，并只让前后两次页面共享同一份合成会话存储；没有把上一页的内存意图偷偷带入新页面。60项控制通过：

- 保存、提交、确认及退回都在发送前留下原请求；刷新后只读取会话和目标，没有自动POST。用户点击重试后，方法、路径、正文、原版本、快照绑定和幂等键均与首次相同。
- 当前服务端版本单独读取。原备注不会填入当前已保存表单；较新的GET结果不会改写待重试的旧正文。
- 存储拒绝读取、拒绝写入或静默不写时，不发出新业务请求。成功后拒绝删除或静默不删除时，仍保留阻断与原意图，恢复存储后可再确认并清理。
- 用户、租户或角色不匹配时，只有固定提示，没有原备注或操作身份详情。损坏记录不自动清除，必须由用户明确确认；清理失败保持原记录和阻断状态。
- 外部路径、不同读取目标、多余正文凭据字段、版本不一致、页面类型错误、重复键、非有限数、过深嵌套及超限记录均被拒绝恢复，不发送其中的目标，也不回显测试中的私有标记。
- 目标GET的403、500、正文读取失败、坏JSON和错任务ID均保留待确认状态，并禁止直接重试写入。明确重新读取成功后才开放重试。
- 身份变化后，迟到的响应和正文不会恢复旧任务、版本、元信息或旧身份提示。

旧[写入重试控制](../../scripts/check_research_write_retry_ui.js)的62项断言和[显式查询控制](../../scripts/check_research_query_ui.js)的51项断言也通过。适配只补新日志模块、合成会话存储和完整租户身份，没有减少原断言。首次回归中，一处旧夹具遗漏租户字段而被新校验拒绝；补全合成身份后通过，产品规则没有为夹具放宽。

```powershell
node scripts/check_research_reload_ui.js ../creditlens
node scripts/check_research_write_retry_ui.js ../creditlens

```

新脚本可在目标仓库参数后再指定共享日志与控制器所在仓库，供合并前只读检查不同工作树；未指定时全部读取目标仓库。测试使用可公开底稿作渲染夹具，存储、角色、响应时序和故障均为合成。Node VM不能替代真实浏览器的会话存储、页面刷新和视觉验收，主开发另行记录。

## 采纳与保留事项

已采纳写前可靠保存、服务端身份匹配、固定请求白名单、显式重试、当前版本重读、清理失败阻断及不保存登录凭据。整合中明确了损坏／异身份日志也会阻断写入，重新核对需再次读取日志；成功写入后的清理异常也有单独提示，不再使用“仍未确认”掩盖已读回的服务端结果。
