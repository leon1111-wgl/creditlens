# 公司说明：数字相符之后，还要检查什么

2026-10-25。本实验给已登记的微软经营现金流说明增加一组独立开发控制。研究员看到公司说“现金流增加”，需要同时知道数值是否对得上、哪些因素是公司自己的解释、哪些限定不能丢，以及这份新资料有没有进入已批准的底稿。

来源和核心实现见[公司说明登记](company-attribution-core.md)。该模块不重新抓网页、不运行 OCR 或语言模型，只读取小型登记目录与既有财务材料。开发控制由 AI 辅助拟定，独立人工确认全部为 `pending`；这里的“独立”指控制与核心规则分别实现，不能写成独立人工标注、保留集或模型准确率。

## 先把两种数值说清楚

PDF 中的 FY2025 经营现金流是 136,162 百万美元，上期是 118,548 百万美元，差额为 17,614 百万美元。网页文字使用十亿美元，分别写成 136.2 和增加 17.6。

本工具先从精确报表值计算，再按 0.1 十亿美元精度核对：

| 对象 | 从精确值转换 | 网页摘要 | 能得出的结论 |
|---|---:|---:|---|
| 当期经营现金流 | 136.162 | 136.2 | 舍入兼容，不能叫精确相等 |
| 年度增加额 | 17.614 | 17.6 | 舍入兼容，不能叫精确相等 |

两个摘要数分别舍入。用 `136.2 − 17.6 = 118.6` 反推上期，再与 118.548 比较，会引入不必要的误判。工具使用 `ROUND_HALF_UP` 是明确登记的核对策略，不代表公司原文宣称使用了同一算法。

公司称主要原因是客户收款增加，同时说明供应商和雇员付款增加、所得税支付增加抵消了部分增量。控制要求这些限定同时保留。数值相符与限定完整，仍不能证明公司解释已经得到独立验证；同份年度报告的 HTML 和 PDF 也不是两个独立证据源。

## 23 项固定控制

[控制清单](../../data/evaluation/company-attribution-cases.json) 保存固定预期、来源绑定、修改说明和人工确认状态。它包含 5 项登记材料题、18 项合成控制；采用决定、任务问题及复核状态均由脚本设定，不冒充真实团队操作。

| 编号 | 检查内容 |
|---|---|
| CA-01–03 | 当期值与变化额分别换算、舍入；保留精确输入，不从摘要反推 |
| CA-04–05 | 保留主要原因与两个抵消项；苹果未登记不等于未披露；当前 HTML 首次公开日未知 |
| CA-06–07 | CFO 尚未采用或明确拒绝时，数值仍可核对，任务关联不能显示已支持 |
| CA-08–09 | 假设文字自称“已证实”或任务状态为 reviewed，都不能升级说明的证据等级 |
| CA-10–11 | 新补充绑定当前 revision，不改合成旧快照；自由文字不改变固定任务规则 |
| CA-12–16 | 合成任务错币种、错期间、错公司、错来源或请求历史时点时拒绝 |
| CA-17–22 | 合成目录改精度、摘要数、币种、公司、期间或删除税款抵消项时拒绝 |
| CA-23 | 目录缺失时停止新补充，不从问题或假设生成替代原因 |

目录篡改题在 `.run/reproductions` 下建立临时小副本，通过真实登记加载器检查，再清理临时目录；官方目录没有修改或删除。这些题验证的是冻结登记的完整性，不能据此声称系统能够理解任意新披露的币种和财务语义。

CA-10 只验证纯函数输入及合成快照没有被改写，该测试不覆盖真实数据库的历史导出。CA-11 的租户名只是文字标签；纯模块没有身份鉴权职责，报告明确写入 `tenant_authorization_evaluated=false`，不能把它列为跨租户安全成绩。

## 实际结果与复算方式

[执行脚本](../../scripts/evaluate_company_attribution.py) 已实际运行全部 23 项，均符合固定预期；其中 12 项得到预期验证异常，没有意外运行异常。四个通道独立保留分母：

| 通道 | 涉及题数 | 检查条数 | 符合预期 |
|---|---:|---:|---:|
| 数字换算与舍入 | 5 | 18 | 18 |
| 公司陈述及限定范围 | 4 | 9 | 9 |
| 阻断与拒绝升级 | 19 | 28 | 28 |
| 当前版本与来源绑定 | 4 | 9 | 9 |

这些是开发控制结果，不是 23 个独立企业样本或 64 个独立模型问题。同一登记说明被多种条件反复检查。即使控制全部符合预期，经营原因仍未独立证实。

报告保留每题的固定预期、观察结果、错误码、输入与结果摘要，以及代码、题库、材料和来源目录摘要。校验时逐字段重算，保持通过数却修改观察值、人工确认状态或来源哈希，同样会被拒绝。原始目录字节与加载器验证对象还要内容一致，不能给一个版本的结果挂上另一个版本的原始哈希。

专属软件测试共 12 项，全部通过。另行故意删除抵消项、把舍入结果标成精确相等、伪造独立因果或修改调用输入时，检查都能发现差异；异常崩溃不会被算作正确拒绝。

```bash
python -m unittest tests.test_company_attribution_evaluation -v
python scripts/evaluate_company_attribution.py
```

脚本默认新建 `.run/reproductions/company-attribution-controls-report.json`；可用 `--output another-run.json` 指定同一目录下的新文件。文件已存在就拒绝覆盖，不能写公开报告、事实包、实验预览或外部目录。失败项仍保存，预期不符时退出码为 2。

实际生成的开发报告为 33,392 字节，并通过 `validate_report(root, report)` 全字段复放及独立只读检查。旧材料和旧冻结报告保持不变。下一步应由真人独立核对说明及测试期望，再补充更多企业原文和可独立核实的经营证据；这组控制不替代该工作。
