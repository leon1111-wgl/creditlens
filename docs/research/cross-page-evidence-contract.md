# 三张卡片完成一次跨报表页比例计算

本模块只处理一个固定任务：**经营现金流净额占营业收入比例**。分析员须选择经营现金流金额、营业收入金额、合并范围说明三张登记卡片。两张金额卡位于不同报表页；合并范围卡用来说明这些报表的编制基础。这是跨报表页关联，不是跨页续表恢复，也不理解任意自然语言问题。

接口为 `evaluate_evidence_selection(task, cards, selected_ids)`。该纯函数不读文件、不执行文档文字、不请求网络、不接触数据库，也不改传入对象。服务端必须先选取可信的冻结任务与卡片目录，客户端不能用自己编的金额替换它们。函数只能核对传入内容的结构和关系，不能独立证明目录或来源真实。

## 输入和正确条件

任务固定主体、报告摘要、财年、实际期间起止、`USD_million`、合并口径，以及三个角色各自允许使用的卡片 ID。卡片保留来源链接、报告摘要、原始金额及有符号十进制值、值状态、原页和金额／年度／单位框。范围卡只有已登记页码和文字定位，三个金额类框为空；不为没有重新定位的附注补造坐标。

三个角色须恰好各一，且选择的 ID 与任务登记一致。主体、报告版本、实际期间、单位、合并范围须一致。合并口径只表示报表所列总额，持续及终止经营分解仍是未知。范围附注的期间字段是该任务的适用上下文，不表示短定位锚逐字披露了两个财年的日期。不同年度共享的附注锚不能算成独立证据样本。

当前材料模式核对登记日及已知披露日是否晚于任务截止日；已知披露日也不能早于覆盖期末。首次发布日期未知时保持空值和 `unknown`。登记日不是原始公告时间。`historical_as_of` 无论日期能否对上都拒绝，不能把当前快照冒充历史可得材料。

## 数字和拒绝状态

原始金额采用完整、有限的语法：无币种前缀、`$` 前缀或 `USD ` 前缀，配合法千分位和最多六位小数；负数可用完整负号或括号。不会删除任意币种标记、百分号或多余数字。归一值必须是十进制字符串，并与原值数值及符号一致，包含负零的符号。其他有效财务写法可能在这一窄契约下被拒绝，不能自动猜测修补。

`disclosed`、`not_disclosed`、`not_applicable`、`unreadable` 和数值零不同。范围文字卡使用 `text_evidence`；金额只有明确披露值可参与计算。缺失值不转零，经营现金流可为负或零，营业收入必须为正。少卡、错卡、重复卡、同页伪装跨页、未来材料等返回 `refused`、逐项检查和原因，计算结果为空。损坏的契约形状、类型、坐标或重复目录 ID 抛出带固定代码和路径的 `CrossPageEvidenceError`，不把原文放入错误。

全部检查通过才用 `Decimal` 的局部精度 40 执行 `cfo / revenue * 100`。结果按 `ROUND_HALF_UP` 保留六位小数，输出原始输入、归一值、公式、精度和舍入规则。原始未量化百分比是精度 40 下的运算结果，不宣称无限精确。仅该观察比例可计算；不能据此叫回款率、收现率、利润率，也不能推出盈利质量、经营原因或预测。

## 结果和验证范围

结果包含任务、目录和选择的规范 JSON 摘要，三角色要求、缺失角色、逐项 `passed/code/message`、错误和所选卡片的完整引用白名单。不会展开全部候选目录。`automatic_approval`、`independently_verified`、`model_quality_verified` 始终为假。来源登记不等于模型识别质量，计算通过也不自动采用或批准事实。

本模块测试使用明确的合成卡片，覆盖正确比例、负经营现金流、零分母、状态缺失、错期间／币种／范围、重复与错误选择、符号不完整、未来材料、注入式文字和 Decimal 上下文。真实资料的登记、四个固定任务及开发控制由材料与实验模块提供，不能把这些软件测试称为新模型、通用跨页理解或独立人工评测成绩。
