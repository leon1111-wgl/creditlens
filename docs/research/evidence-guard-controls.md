# 金额依据的强制检查与开发控制

日期：2026-10-25。使用者任务是确认某个报表金额的文字、符号和位置能否作为同一份证据采用。旧规则与公开结果保留，本轮增加单独诊断，不改写旧结论。

独立审查找到三类旧规则可能放行的输入：金额词还在原位但父行框已经移走；金额前带有与 USD 不相容的 `¥`；金额旁出现没有词框的独立负号。数值相同不能消除这些问题。因此新检查对每个金额执行，不只处理旧规则已经判为不足的金额。

## 两组分母分开

1. **已观察材料**：复用 AMD 已发布的两页、14 项参考与必要完整父行，逐项重算旧 currency 与新 guarded 结果。不运行 OCR，不重新下载原文，不把这次规则修改称为新发行人盲测。
2. **合成开发控制**：38 项固定输入，8 项合法正例、30 项应阻断输入。参考与 OCR 都是手工构造的小型控制，预期由工具辅助事先拟定，独立人工确认仍为 pending，人工金标准数量为 0。所有失败都保留，不能删除难题改善统计。

控制覆盖完整金额、负号、负值括号、零值、远处无关文字，父词几何错位、错误币种、近邻无词框符号、低父行分数、重复候选、缺词、父词文字不守恒，以及单位或年份本来就不一致的情况。后一组确保新金额守卫不会顺手把其他字段的失败升级为通过。

另有同父行 `$` 与金额分成两词的正负控制：合法关联、合法负值、错误币种、逆序位置、第三词、过远间距和父框错位。首版开发试算曾把 AMD 两项净利润的同父行拆分美元符号判为不足，其余 12 项一致；随后加入明确的两词归属检查。这个开发过程说明过度拒绝也需要调查，不代表模型重新识别或新增验证样本。最终登记结果以主分支实际生成的报告为准。

## 报告如何防止只改数字

`creditlens/evidence_guard_diagnostic.py` 先校验旧 issuer 与 currency 发布登记，再核对参考包、原 PDF 摘要、页面及事实全集。同一 PDF 不能换个文档 ID 重复计数，同一个事实不能在多页重复。每个新结果保留完整旧结果；非金额字段和旧日期、货币关联信息必须不变，新层只能保持或降低状态。

报告同时绑定规则实现、运行脚本、参考版本和控制目录的摘要。读取报告时重新执行全部已观察事实及全部控制，比较字段与规范 JSON 摘要；同样的总数不能掩盖观察文字、位置、理由或预期被改动。新报告不会改变旧发布文件。

`summary.old_false_agreements` 在已观察材料里仅表示“旧规则一致、新守卫阻断”，不能解释为独立人员已经证明财务数值错误；控制组同名字段才对应预先声明应拒绝的合成输入。报告中的通过数是开发要求检查数，既不是 OCR 准确率，也不是大模型问答成绩。

## 复跑与限制

在项目根目录运行：

```powershell
python scripts/evaluate_evidence_guard.py --output evidence-guard-report.json
python -m unittest tests.test_evidence_guard_diagnostic -v
```

输出只能新建在 `.run/reproductions/` 下，已有文件、公开发布目录、原实验目录、目录别名以及嵌套输出被拒绝。CLI 不联网、不加载识别模型、不发 API 请求。

本分支已实际执行 CLI：14 项已观察材料在旧、新规则下均为一致，非金额字段保持原样；38 项控制符合固定预期，其中旧规则曾对 12 项应拒绝的控制显示一致。新增 12 项测试通过，覆盖相同计数下篡改字段、缺失和重复事实、来源与规则漂移、非法目录以及拒绝覆盖。独立复核另将理由、父框、范围声明、预期和事实身份分别修改，均被整份报告重放拒绝。这里的开发控制结果不能代替新材料或独立人工评测。

当前公开复算只检查已经保留的必要父行与词，不保证新守卫需要的所有邻域都已包含，更不证明文档真实或模型实际执行。主开发如使用本地保留的完整 OCR 做额外全页对照，应单独记录范围与结果，不能把这里的 `full_ocr_verified=false` 改成 true。后续需要新材料、独立人工确认和按发行人隔离的评测，才能讨论迁移效果。
