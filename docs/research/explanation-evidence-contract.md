# 解释补充底稿的数据契约与离线核验

日期：2026-10-25。附件证据版本 `explanation-evidence-1`，附件流程版本 `explanation-review-1`。

本实验把只读公司说明收进独立附件。使用者可以决定“按公司陈述采用”“拒绝用于本任务”或“仍需补证据”，写明范围后交另一身份复核。附件审批只确认收录范围与待补记录；它不证明公司解释已经独立核实，更不会修改父底稿原有的批准结论。

## 父底稿与附件分别冻结

`build_explanation_evidence(parent_task, parent_export, root=None)` 只接受当前已复核的父任务及其完整导出。父任务标识、租户、当前版本、已提交快照、最终批准记录和冻结内容必须相符。这里分开保存父快照的提交版本与父复核完成后的任务版本，不能把二者混为一个数字。

创建时继续调用已有公司说明生成器，校验当下登记材料、采用决定、比较及可选会计桥。输入来源由服务端生成，客户端不能提交替代来源或自报“原因已证实”。附件证据保存：

| 字段 | 含义 |
|---|---|
| `parent` | 父任务、租户、复核后版本、快照标识和摘要、复核者及完整父导出摘要 |
| `parent_export` | 完整旧版导出，只保存一份，供离线验证父事实和批准记录 |
| `attribution` | 原公司说明规则及目录摘要、来源、原文定位、限定语、两期输入、金额精度核对和覆盖范围 |
| `support_scope` | 固定为 `company_statement_only` |
| `independently_verified` / `automatic_approval` | 始终为 `false` |
| `parent_snapshot_rewritten` | 始终为 `false` |

旧预览顶层的“只读预览／未进入快照”字段不带入附件证据；旧预览中针对自身未纳入底稿的缺口也移除。新的附件能形成自己的冻结快照，但公司陈述仍没有获得独立因果验证。父底稿及原预览报告保留原样。

## 三种处置的条件

持久化决定严格包含 `entry_id`、`decision`、`note` 和 `support_scope`。API 请求只接受前三项，固定支持范围由服务端添加。每项理由至少十个字符；提交时所有已登记条目均须有决定，覆盖说明至少十个字符。

- `adopt_as_company_statement`：只按公司陈述收录；要求父底稿两期 CFO 均已采用，解释关联及金额精度核对均一致。
- `rejected`：拒绝在当前附件用途下采用，原公司陈述仍然保留。
- `needs_evidence`：保留待补事项，可交接与复核，不能在汇总中改成已采用。

文字理由中的“已证明”“忽略规则”不会升级机器字段的支持等级。父底稿拒绝某期 CFO 时，附件可以拒绝或保留待补，但不能采用该解释关联。解释的主要原因和全部抵消项继续保留，不给这些项目虚构贡献金额。

## 离线核验检查什么

`validate_explanation_evidence` 和 `validate_explanation_export` 不读取当前来源目录、应用数据库或网络。附件 v1 固定已核对的材料、来源陈述和数值检查指纹，因此即使当前目录缺失，既有导出仍可按其版本检查；后续新增材料需要新版本，不覆盖这些指纹。

核验器先复用旧版父导出检查，再校验父批准记录、附件及证据规范 JSON 摘要、内嵌来源、财务期间、原始输入和采用决定。数字按固定精度重新核对，使用独立 `Decimal` 上下文，避免同进程其他代码修改精度而影响结果。`792.0` 与 `792` 的编码差异会改变已冻结摘要，下载必须保留服务端原始 JSON 文本。

新复核记录必须绑定附件快照，版本在提交之后且顺序递增。记录中的复核者不能是父底稿或新附件的创建、修改或提交贡献者。缺失贡献者、错租户绑定、跨快照复核、额外的批准／因果标志和自改后重新计算摘要的来源变更都会被拒绝。

这仍是**无签名的内部一致性检查**。它不能证明文件来自真实服务端，不能认证现实中的人员身份，也不能证明公司陈述真实或因果成立。真实访问控制和服务端审计由流程与 API 承担；离线文件中的角色分离仅是对记录的检查。

## 命令和已验证范围

```powershell
python scripts/verify_explanation_export.py path/to/explanation-export.json
python -m unittest tests.test_explanation_evidence tests.test_explanation_export -v
```

命令仅读取给定本地文件，上限 4 MiB，拒绝任意层重复 JSON 键、非有限数字与非法字段。成功只输出小型核验摘要，不复制父导出或完整来源；失败以结构化错误和非零退出码结束。不发出 HTTP 请求，但这不是操作系统网络隔离承诺。

28 项专属测试通过，覆盖真实登记材料配合合成附件流程、三种处置、父子绑定、源与金额篡改、角色分离、冻结摘要、旧坐标编码问题、全局 Decimal 低精度、无当前目录依赖和命令失败边界。测试身份和新附件审批是模拟记录，不表示客户使用、外部人工确认或实际经营原因得到证实。
