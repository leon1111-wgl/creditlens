# 把公司解释与毛利数字放在一起核对

本实验服务研究员整理经营变化的任务。毛利分解已算出产品、服务收入构成与分类自身毛利率对总毛利率变化的会计贡献。公司说明模块把公司公开说明放到旁边，让研究员看清：公司谈的是金额还是比率、覆盖哪一部分业务、数字保留了几位，以及原文是否包含“主要因素”“部分抵消”等限定。公司自己的说明仍需与其他材料交叉核实，不会因为数字吻合就变成已经证明的原因。

企业任务依据沿用已记录的需求调研与三类研究任务验收，未新增客户访谈或效率提升结论。公司说明模块提供的是有固定来源的结构化核对，不是任意文本理解。

## 登记材料与结果

范围固定为微软、苹果 FY2025 相对 FY2024 的八条陈述，来自[官方说明登记](../../data/sources/margin-company-claims.json)。它们绑定同一份[毛利会计分解报告](../../artifacts/margin-bridge-report.json)，不替换原报告及其来源。

| 公司与陈述 | 核对结果 | 使用时应知道的边界 |
| --- | --- | --- |
| 微软总毛利金额增加 229 亿美元、增长 13% | 数值相容 | 精确金额差是 228.85 亿美元；金额和增长率分别按披露精度核对 |
| 微软总毛利率下降 | 方向相容 | 不能将金额增长直接当作毛利率增长 |
| Microsoft Cloud 毛利率 69% | 范围不足 | 现有分类没有 Cloud；全公司约 69% 不能代替 Cloud |
| 苹果产品毛利金额增加 | 方向相容 | 产品毛利金额增加 32.54 亿美元，毛利率仍可下降 |
| 苹果产品毛利率 37.2% → 36.8% | 数值相容 | 分别核对两期，精确变化约 −0.409967 个百分点 |
| 苹果服务毛利金额增加 | 方向相容 | 金额变化与比率变化分别登记 |
| 苹果服务毛利率 73.9% → 75.4% | 数值相容 | 精确变化约 +1.527768 个百分点 |
| 苹果总毛利率 46.2% → 46.9% | 数值相容 | 此条仅登记表格数字，没有为公司补写总变化原因 |

八条结果为四条数值相容、三条方向相容、一条范围不足。它们来自两家公司已观察材料，独立人工金标准为零，不是八道独立模型测试题。十九项合成控制另列，不与真实材料混算。

## 怎样核对

来源适配器先固定新目录的 UTF-8 LF 字节摘要、规范 JSON 摘要和旧毛利报告摘要，再逐条核对发行人、两期起止、报告版本、说明来源和段落捕获摘要。产品与服务比率的叙述段落和表格数字分别定位；报告保留 `source_record`，能看见这层区别。

纯规则检查区分毛利金额、增长百分比、毛利率和百分点。数字按登记的零位或一位小数使用 HALF_UP 核对；这是工具的比较策略，不宣称公司说明过自己的舍入算法。独立 `Fraction` 计算从已登记收入和成本重算金额、比率与变化，没有读取候选结果来生成预期。两期披露比率分别四舍五入后的差单独记录，不能冒充未舍入的精确差。

公司解释、驱动因素及限定词原样进入结构化输出。登记目录中的文字、限定词或捕获摘要被改动时，保存报告验证会拒绝。对于合法结构但文字夸大的合成输入，纯算术仍可能相容；报告明确保留 `natural_language_understood=false`、`causal_explanation=false` 与 `independently_verified=false`，不把没有执行的语义或因果检查伪装成通过。

## 来源与验证范围

- 微软来源登记包含当次成功抓取 HTML 的响应摘要及指定段落摘要。本次实验只读取这些已登记的小型证据，不访问网页。
- 苹果直接 HTTP 抓取返回 403；来源使用官方 SEC 页面经网页工具返回的段落或表格文字计算规范摘要。原始响应摘要为空，原始 HTML 字节未核验，不将文本摘要写成整页真实性证明。
- Filing date 是备案事件日期，不是当前 HTML 字节的首次公开时间。本实验不具备历史时点回放资格。
- 资料为工具辅助整理，独立人工确认仍为 pending。没有新下载、OCR、模型调用或付费调用，没有新增数据库记录。

## 开发控制与复现

十九项预先固定控制涵盖正常舍入、Cloud 与总公司范围混用、公司／年份／期间／报告错配、错误方向、百分比与百分点混用、合法半舍入边界、略低于边界、零基期增长，以及自由文字不能升级因果结论。全部保留在报告分母中，实际十九项符合预期、零项失败。二十一项专属工程测试还检查保存报告同计数篡改、来源改版、目录双读变化、严格 JSON、实现摘要、调用方 Decimal 环境污染和输出路径保护。

独立核验也检查必要结果是否存在：可计算的登记陈述若缺金额、方向或两期披露差，不能靠空比较得到通过。合成错公司、错期间等结构拒绝单独标为没有执行算术比较。报告即使能逐字段重现，只要必需核验或固定控制有失败，也不会被加载入口标为验证通过。

```powershell
python scripts/run_margin_claims.py --verify-saved
python scripts/run_margin_claims.py --output margin-claims-replay.json
python -m unittest tests.test_margin_claim_experiment
```

新结果只允许独占创建在 `.run/reproductions` 直属 JSON 文件，已有文件和公开来源不能被覆盖。`--verify-saved` 重新计算所有登记与合成结果、来源绑定和实现摘要，并逐字段比较[保存报告](../../artifacts/margin-claims-report.json)。这证明当前代码能够重现这份有限结果；它不重新取得网页，也不检验完整 OCR 或模型质量。

后续可以扩充有明确类别与期间的公司说明、交给独立身份复核转述与限定词，再设计真正未参与开发的语义验证任务。本实验不把公司的解释自动分配给毛利会计桥中的每一项贡献。
