# 应用重建后的研究写入恢复

日期：2026-10-26，第39轮。脚本：`scripts/replay_research_restart.py`；结果：`artifacts/research-restart-report.json`。

研究员点保存或提交后，即使没有收到返回，也需要分清两件事：服务端是否已经保存，以及随后是否又有人推进了版本。本轮检查服务对象被关闭、重新创建之后，原请求还能否找回自己的回执，并通过新的 GET 读取当前状态。

## 本轮实际做了什么

脚本使用隔离临时 SQLite、模拟 API-key 身份和既有小型登记材料，实际退出 TestClient 的应用生命周期并关闭客户端，重新调用 `create_app`。每次都产生新的 FastAPI、ResearchTaskStore 和 ExplanationReviewStore 实例，重新打开同一个临时数据库。对旧 Store 的连接还做了退出上下文后不能继续执行SQL的检查。

全程在同一 Python 进程内，创建13个应用实例、完成12次重建。没有终止进程、关闭机器、制造真实网络中断、恢复备份或测试后台队列。框架保留首次响应字节用于对照；这不是外部网络丢包实验。浏览器刷新恢复由主分支单独验收，本脚本不把服务端检查当作浏览器结果。

|场景|参数与检查|实际结果|
|---|---|---|
|研究底稿 PATCH 保存|保存成功后重建应用，原身份、键和请求体重放|HTTP响应字节相同，事件和数据库内容不重复|
|研究底稿 actions 提交|提交成功后重建，沿用相同版本、键和请求体|原快照回执可读，只生成一次提交快照|
|解释补充稿 PATCH 保存|独立编辑身份保存后重建再发原请求|响应与原件相同，解释底稿不多一次修改|
|解释补充稿 actions 提交|提交后关闭应用并重建|同一回执恢复，父底稿未被改写|
|他人随后确认|第三身份把两个底稿推进至版本4，再重建并重放四个旧请求|旧回执仍分别是版本2/3；新 GET 保持版本4，未回退|
|研究材料登记漂移|只改临时复制的财务JSON，再重建|已成功的回执仍可读；新的提交在会计桥来源核验处返回409；恢复登记后同一待提交请求成功|
|公司说明登记漂移|只改临时复制的公司说明，再重建|旧回执仍可读；新说明冻结返回409；恢复登记后可以完成|
|未提交SQL连接关闭|实际 BEGIN 后暂写一个版本及回执行，不执行 commit，关闭连接后重建|两项临时写入都回滚；原键没有被占用，合法请求可正常完成|
|回执写入失败后重建|临时 SQLite trigger 让实际HTTP提交的回执插入失败|返回503，业务和回执在同一事务回滚；重建、移除故障后原键可提交，下一次重建仍能重放|

四个主要路径覆盖保存和提交两类动作。批准/退回等动作的完整幂等边界沿用第37轮测试，本轮没有将其56项控制重复计成新场景。

## 结果与计数

本轮61项程序断言全部通过，13项专属测试通过。61是针对这些路径的检查数量，不是61个用户任务，也不是金融问答准确率。

完成的8个带键写入意图对应8条回执。最后的研究快照为3份、解释补充快照为2份，其中包括故障恢复用的独立模拟底稿。最初两份已确认底稿的导出摘要在全部重建、来源故障和回滚检查之后保持不变。

报告逐项保存请求参数或其摘要、预期和实际状态、首响/重放响应摘要、重建前后状态和表内容摘要。数据库摘要来自实际查询业务表与回执表的内容，不使用容易随页布局变化的SQLite文件字节摘要。报告不包含完整底稿、原PDF、页图、OCR、API凭据或本机临时路径。

注册事实只用于构造可信的小型流程夹具。身份、故障和数据库均为模拟，人类金标准为零；批准解释补充稿仍不证明公司陈述中的原因成立。

## 复演与限制

```powershell
python scripts/replay_research_restart.py --verify-saved
python scripts/replay_research_restart.py --output restart-local.json
python -m unittest tests.test_research_restart -v
```

`--verify-saved` 重建整个隔离流程，逐字段比较结果。只改响应摘要、把故障状态改为成功、把应用重建标记改成数字或声称操作系统崩溃测试，即使总计数不变也会失败。测试还模拟把重建动作替换成空操作，报告构建必须拒绝把它计为已重建。

输出只允许在 `.run/reproductions` 直属目录独占新建JSON，拒绝覆盖已有文件或发布产物。保存报告按1MB限额读取，拒绝重复JSON键、非有限数值和错误UTF-8。实现和小型JSON来源都绑定UTF-8、LF规范化摘要，输入在运行前后再比对；仅换行差异可复验，来源内容变化仍须处理。

临时材料从仓库小文件复制，不从网络下载。临时目录在结束后清理，不操作主数据库。结果只证明当前SQLite和应用流程在明确关闭、事务回滚和对象重建下的行为，不承诺电源故障持久性、跨机器恢复、真实网络可靠性或用户效率提升。
