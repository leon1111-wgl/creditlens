# 同一页 OCR：文字顺序与表格行列定位对照

研究员查财报时，不仅要找到一个看似正确的数字，还要知道它来自哪一行、哪一年的列。本实验从之前保存的整页 OCR 出发，比较两个不用大模型的方法：一个按文字序列及年份顺序选金额，一个按行名位置与年份列边界选金额。两者使用完全相同的行级 OCR、金额语法、识别分数门槛和单位说明规则。

## 输入和评分分开

固定输入为微软 FY2025 年报的物理第 50、52、53 页，以及苹果 FY2025 年报的第 32、34、36 页。微软二十项、苹果二十二项，共四十二项旧开发事实全部保留；收入和经营现金流八项只是界面入口，不缩小整体分母。

每项查询只给行名和年份。整页 OCR 已经包含文字、置信分数及页面坐标；提取接口没有参考金额、参考框、分区、财务单位或 `Fact` 参数。页码是已登记的题目上下文，因此这仍是给定页、给定行名查表，不是从任意问题检索整份年报。

先完成四十二项提取并固定输出，再读取原始有符号金额与参考框评分。资本开支原文的括号负数按负数比较，不与业务层转成正数的现金流出绝对额混用。测试中修改参考金额和框不会改变提取结果，只会改变后续评分。

评分分别保存：

- 是否选出候选，以及无法选择的原因。
- 候选金额是否与参考有符号金额相同。
- 候选是否位于参考单元格：参考区域覆盖率至少 0.5，且候选中心在参考框外扩 8 PDF 点以内。这一评分条件在运行前登记，不用于选择候选。
- `matched` 要求金额与位置同时匹配；金额偶合但位置不同计为 `wrong`；没有唯一候选计为 `insufficient`。

单位文字及 `except` 限定原样保留，但 `millions` 不能证明币种为美元。金额匹配也不证明整个财务期间已确认。因此结果中的 `unit_proven` 和 `complete_period_proven` 均为 false，不把数值对照升级为已核准财务事实。

## 不为消除失败增加答案信息

苹果报表内 `Marketable securities`、`Term debt` 等标签可能出现在不同分区。查询只有行名与年份时，重名属于真实歧义，本实验不会悄悄把参考分区或框交给某一种方法。无法完整解析的金额、低分、缺列、跨列符号和表头不足都保留，不通过裁剪正确子串追分。

六项合成控制单独登记：正常两列、仅交换金额的 OCR 顺序但保留坐标、缺金额、重复行名、合并金额和低分。在序列交换控制中，文字基线应暴露串列，版面方法仍可依据坐标选择；这是人为构造的规则对照，不能作为真实金融文档上的提升。其他控制用于检查失败是否解释清楚。合成数据不加入四十二项真实参考的分母。

## 本次实际结果

2026-10-26 在固定核心提交后读取六份原 OCR，完整运行四十二项，结果如下。没有新 OCR、模型调用或下载。

| 方法 | 全部查询 | 金额和位置匹配 | 错取 | 不足 |
|---|---:|---:|---:|---:|
| 文字序列 | 42 | 26 | 0 | 16 |
| 表格行列位置 | 42 | 26 | 0 | 16 |

两种方法在微软二十项中各匹配十八项、苹果二十二项中各匹配八项。本批数据没有显示版面方法的真实增益，不能用合成的顺序交换结果替代这个结论。匹配项的金额和参考位置均一致；另外十六项全部保留在[正式报告](../../artifacts/table-lookup-report.json)，包括微软净利润行的符号/金额内容问题、苹果的重名行、必需证据低分及跨列边界。不同方法的具体拒绝原因可分别查看。

六项合成控制均符合预先固定的预期，其中交换文字顺序的控制暴露了基线串列。十八项实验测试通过，另完成一次显式完整 OCR 重放，逐项输出与正式报告一致。公开报告约 584 KiB，只含必要候选和定位；[发布登记](../../configs/table-lookup-artifact.json)固定其字节摘要。四十二项参考及合成控制均未经独立人工标注，这些数字是固定开发查询的结果，不称模型准确率。

## 如何复演

`configs/table-lookup.json` 固定了两份事实包的规范摘要、旧公开 OCR 报告摘要、六份本地 OCR 的原始及规范摘要、完整事实清单和评分条件。脚本不会下载 PDF、图片或数据，也不调用 OCR、语言模型或付费 API。

本地保留六份原 OCR 时：

```powershell
python scripts/evaluate_table_lookup.py --ocr-root .run/document-ai --output table-lookup-rerun.json
```

未指定 `--ocr-root` 时只读本仓库的 `.run/document-ai`。缺文件或哈希不同则失败，不自行恢复或生成。输出只允许在 `.run/reproductions` 直接新建 JSON；不能覆盖已有文件、公开报告或原始实验。

只有公开仓库的小报告时：

```powershell
python scripts/evaluate_table_lookup.py --verify-saved
python -m unittest tests.test_table_lookup_experiment
```

`--verify-saved` 核对发布登记的报告字节摘要、实现和配置摘要、来源事实、完整案例集合、候选结构及每项评分，不读取完整 OCR，也不重新执行提取。`load_table_lookup_snapshot` 提供相同的只读边界供界面使用。只有显式调用 `validate_table_lookup_report(..., ocr_root=...)` 才用完整保留 OCR 重放并逐项比较整个报告；不能把离线检查与完整复放混为一谈。

## 局限

这些都是已观察过的开发页面，查询标签也取自已登记参考；独立人工金标准仍为 0，新 OCR 调用为 0。本实验衡量固定查询上的规则输出，未测开放式问答、通用表格理解、其他公司的泛化或真人任务效率。文字顺序和版面方法可能在当前样本上同分；报告保留实际结果，不要求版面方法必须领先。原始 PDF、页图和完整 OCR 不放入公开报告，必要候选的位置与来源摘要可以查看，但不构成真实性鉴定。
