# 单位适用性检查契约

`unit-applicability-1` 解决一个具体问题：取数器找到了数字，但表头的量级说明可能带有例外。比如“以百万计，收入除外、收入以十亿计”，不能只读前面的“百万”就换算收入。这个检查层保留旧取数结果，另外判断当前候选能否使用完整单位行中的基础量级。

它是对已保存证据片段的纯函数检查，不读取文件、网络或数据库，不重新运行 OCR，也不重新选择金额。旧提取器、规则版本和冻结报告均不修改。通过本层不表示已经核实币种、期间、报表范围、来源真实性或 OCR 正确性。

## 输入与输出

```python
inspect_unit_applicability(*, row_label: str, extraction: dict) -> dict
```

`row_label` 是用户查询的行名，`extraction` 是原方法的完整结果，支持 `text_sequence`、`layout_column`、`word_layout`、`role_layout` 和 `explicit_row_layout`。不接收参考金额、参考框、企业标识、标准答案或 `Fact.metric`。金额仍来自原方法已经选中的证据索引。

输出的 `original_candidate` 原样保留旧方法、状态、原因、原始值、归一值、索引和单位声明；`evidence` 保留相关行名、单位与被选金额的原始片段。`input_sha256` 是 `row_label` 与完整输入结果的规范 JSON 摘要：键排序、UTF-8、不转义中文、紧凑分隔符、不允许非有限数。它绑定本次输入，不是签名或真实性证明。

| 状态 | 含义 | 新换算值 |
| --- | --- | --- |
| `unit_ready` | 已选金额的完整单位行在支持语法内，声明、引用和行类别检查通过 | 提供 `scale`、`scale_factor`、`scaled_value` |
| `blocked` | 原来选中了候选，但单位或证据仍有问题 | 三项均为 `null` |
| `not_selected` | 原方法没有选中候选 | 三项均为 `null`，本层不解除旧拒绝 |

所有输出的 `automatic_approval` 固定为 `false`，`scope.currency`、`scope.financial_period` 和 `scope.financial_scope` 固定为 `unknown`。`unit_ready` 只表示有条件的量级换算可用，不能直接进入研究底稿的采用或批准流程。

## 完整单位语法

只进行 NFKC、大小写与连续空白规范化，允许完整且成对的最外层括号。规范化后必须完整匹配以下语法，不能截取前缀：

1. `In millions / thousands / billions`。
2. `In SCALE, except per-share amounts`，其中 `per share` 也可使用空格。
3. `In SCALE, except number of shares, which are reflected in SCALE, and per-share amounts`。
4. 上一条最后的 `per-share amounts` 替换为 `par value`。

第二个量级仅登记为股数例外，不能用于普通金额；每股金额和面值也只登记为例外，不在本层做转换。已保存的六页开发材料实际包含四种完整原文：普通百万、每股例外，以及苹果股数以千计并带每股或面值例外的两种说明。支持这些原文不等于支持任意财报表头。

按行、按年度改变量级，`unless otherwise stated`、未知尾缀、不完整括号和未解析的多重量级全部阻断。例外不能因为旧结果的 `scale` 已经写了 `million` 而被忽略。

## 行类别与证据要求

`Basic`、`Diluted`、`EPS`、显式每股、股数、面值、加权平均股数、百分比、比率和毛利率等行名不能直接使用普通金额量级。其中 `Basic` 或 `Diluted` 单独出现时，无法判断是每股金额还是股数，采用保守拒绝。

单位包含已支持例外时，只有代码内公开的有限金额行类别可以使用基础量级，例如收入、净利润、经营现金流、现金及现金等价物、资产负债、借款和固定资产现金支出。类别按完整规范化行名判断，不根据公司、案例、参考金额或参考框放行。未知行名返回 `unknown_exception_row_category`。词典不能代表通用财务语义分类；股权激励费用这类含 `share` 但属于金额的明确行名单独登记，不由一个宽泛的 `share` 子串判断。

普通无例外单位行对未命中上述非金额/歧义模式的行名保留其明确基础量级；这也不是证明该行的经济含义。新增复杂行类别应有独立控制，不能通过修改旧参考数据来放行。

进一步要求：

- 单位行唯一，完整文本与旧单位声明完全一致；量级和例外标志与新完整解析一致。旧结果如果擅自填入币种，也不通过本契约。
- 行名证据唯一，与查询的规范化行名一致。
- 被选金额索引唯一，原始完整金额文本与该证据一致；复用严格金额语法解析，归一字符串必须相同。括号、负号及负零保留，不把不同符号表示当成同一个原文。
- 行名、单位、被选金额使用不同证据索引，且各自识别分数至少为 `0.90`。这些分数不是校准概率。
- 旧词级结果若仍带 `guard_issues`，本层不会给出换算值。其他旧取数保护并不在本层重跑，发布实验仍需依赖已校验的旧报告来源。

换算使用隔离的 `Decimal Context(prec=128)`，因子分别为 `1000`、`1000000`、`1000000000`，不受调用者改变全局精度、舍入方式或陷阱的影响。输出数值为十进制字符串；缺失不填零，零和负零保留。

## 输入损坏与验证范围

结构错误抛出 `UnitApplicabilityError(code, path)`，当前固定 code 为 `invalid_extraction`。错误路径由契约字段组成，不回显任意上传键或正文。拒绝布尔数值、非有限数、错误方法类型、额外标准答案字段、非法几何和无法编码的 Unicode 等。输入深度最多 24、节点最多 20,000、规范 JSON 最多 256 KiB；每组证据最多 2,000 项，坐标绝对值最多 `1e9`。这些是接口边界，不是对真实页面尺寸的证明。

专属测试覆盖五条旧取数路径上危险前缀仍能选中、而新层阻断的情况，以及四种完整表头、三种量级、未知行、隐含每股行、证据错绑、低分、符号与负零、数值上下文、无副作用和非法输入。它们是开发者编写的合成控制，不是独立人工金标准。对旧公开候选的应用与统计由单独实验记录；本契约本身不宣布问答准确率或通用单位识别效果。
