# 单位适用性：旧候选兼容核查与合成风险控制

本轮服务查指标的人：取到 `100` 和看到 `In millions`，还不能忽略同一句中的行、年份或每股例外，直接把它当一亿。新增只读检查先保留旧候选，再判断完整单位说明是否适用于该行；不满足时不输出量级因子或放大后的金额。旧取数结果、参考评分和发布报告均保留。

## 输入与可用范围

核查复用已发布的小型证据，不读取完整 OCR、原 PDF，也不调用模型或网络：

- 第29轮文本方法的42条登记结果；
- 第34轮同一批42条登记结果中的整行、词级和按角色方法；
- 第35轮4组同名行查询的8条显式选择路径。

42条登记记录只有40组唯一查询。四种自动方法重复检查这些记录，共168次，再加8条显式路径，共176次单位检查；这些数量不是独立样本数，也不是新增人工标注或模型准确率。参考仍为工具辅助整理，独立人工金标准为0。

规则支持四类完整单位说明：基本量级、每股例外、股数另用量级及每股例外、股数另用量级及面值例外。基本单位说明不要求所有行都出现在有限词典中；有例外时，必须属于明确支持的金额行类别。`Basic`、`Diluted` 等不能据此猜成总金额。未知尾部、按行或按年份改变量级、`unless otherwise` 等均保守阻断。这是有限规则，不是任意自然语言理解。

`unit_ready` 仅表示保存候选与保留单位说明可以按本规则解释量级。币种、财务期间、合并范围仍为 unknown；不因百万量级推断 USD，不自动采用或批准。原方法未选中时返回 `not_selected`，不借单位证据补出金额。

合计112次可解释量级、64次保留原不足，本批旧材料没有新增 blocked。单位风险没有伪装成微软或苹果真实页面中的错误。该复算仅覆盖保存的必要证据，没有重扫完整页寻找未保留的单位语句。

另固定20个合成场景，每个分别经过文本、整行、词级、按角色、显式选行五条旧路径，再进入新单位检查。预期在执行前固定，20场景／100次方法检查均符合预期。其中50次原方法已选中的候选被新层阻断，属于开发风险控制，不是实际公司材料错误率。

控制覆盖：合法百万／千／十亿量级、负值和零值、完整已知例外；按行／按年混合量级、未解析条件、双量级和未知尾部；`Basic`／`Diluted`／例外下未知行类别；低分单位；候选单位声明与原行不符、缺失单位原行。低分和明确每股行仍保留旧方法的不足状态。

## 保存核验与使用

新报告绑定三个旧报告的实际字节 SHA、旧快照已验证的来源与页图登记、新核心及实际依赖源码 SHA。Python 文件使用 UTF-8／LF 摘要；不绑定无关 API 或页面文件。读取时先验收旧报告，再逐字段重算新176次检查与100次合成检查，不能靠汇总数相同通过。末次摘要比对拒绝读取期间的来源或实现漂移。

`UnitApplicabilityStore(root)` 仅提供 `snapshot()`、`case(case_id, method)`、`selection(query_id, row_index)`。单项导出含新报告和三个旧报告摘要、明确目标、旧提取摘要和单位检查；没有写数据库的方法。显式选行不提供默认行号，bool／float行号拒绝。

```powershell
python scripts/evaluate_unit_applicability.py --verify-saved
python scripts/evaluate_unit_applicability.py --output unit-applicability-local.json
python -m unittest tests.test_unit_applicability_experiment -v
```

默认生成到 `.run/reproductions/unit-applicability-report.json`；自定义输出也只能是该目录下新建 JSON，已存在文件拒绝覆盖。`--verify-saved` 验证仓库的新保存报告，不重跑 OCR、不联网。公开报告约537 KiB，小于2 MB读取上限。

16项专属测试覆盖完整分母与旧候选不变、五路风险及合法符号、same-count内容篡改、bool／float选择、重复 JSON key／非有限数／错误编码／大小上限、源码或来源摘要漂移、真实报告加载与单项导出、只读 CLI 和拒绝覆盖。完整页遗漏、任意财务行分类、来源真实性和独立人工复核不在本轮验证范围。
